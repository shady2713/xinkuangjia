# 部署与运维说明

## 1. 运行依赖与环境变量

Profile selection: when `SPRING_PROFILES_ACTIVE` is unset the application starts with the `prod` profile, and the generic env example selects `prod` deliberately. The `prod` profile enforces MySQL TLS with `sslMode=VERIFY_IDENTITY` and `allowPublicKeyRetrieval=false`: the database server certificate must be trusted by the JVM and its identity must match `DB_HOST`.

Local development must select `local` explicitly. `init_local_dev.py` writes `SPRING_PROFILES_ACTIVE=local` into newly generated env files; an older backend `.env` without that key needs the line `SPRING_PROFILES_ACTIVE=local` added (all other values stay unchanged), or the process environment override `SPRING_PROFILES_ACTIVE=local`, which takes precedence over `.env`. `scripts/runtime/start_java.ps1` only reads these settings, never rewrites `.env`, and refuses to start unless they select `local`.

生产环境仅依赖 **MySQL 8.0+** 与 **Redis 7.x**，所有密钥均通过外部环境变量注入（严禁写入镜像或代码库）。

| 变量 | 说明 | 默认/示例 |
| --- | --- | --- |
| `SPRING_PROFILES_ACTIVE` | 运行环境（生产用 `prod`，强制开启 MySQL TLS `VERIFY_IDENTITY`） | `prod` |
| `DB_HOST` / `DB_PORT` / `DB_NAME` / `DB_USERNAME` / `DB_PASSWORD` | MySQL 连接信息。生产连接必须使用 `VERIFY_IDENTITY`，且公钥获取必须关闭 | 必填 |
| `REDIS_HOST` / `REDIS_PORT` / `REDIS_PASSWORD` | Redis 连接信息 | 必填 |
| `SM2_PRIVATE_KEY` | 64 位小写十六进制 SM2 私钥（不可留空） | 必填 |
| `USER_INIT_PASSWORD` | 仅作用于批量导入用户的初始口令；不用于种子管理员 | 可选 |
| `FILE_STORAGE_PROVIDER` | 文件存储后端：`local`（本地磁盘）或 `aliyun-oss`（阿里云 OSS） | `local` |
| `FILE_LOCAL_BASE_PATH` / `FILE_LOCAL_DOMAIN` | `local` 模式下的持久化目录与访问基址（默认值为相对路径，生产须显式设为挂载点，见 2.1） | `./.local-storage` |
| `ALIYUN_OSS_ENDPOINT` / `ALIYUN_OSS_BUCKET` / `ALIYUN_OSS_PUBLIC_URL` / `ALIYUN_OSS_ACCESS_KEY` / `ALIYUN_OSS_SECRET_KEY` | `aliyun-oss` 模式必填配置 | 按需 |
| `ALIYUN_SMS_ENABLED` / `ALIYUN_SMS_ACCESS_KEY_ID` / `ALIYUN_SMS_ACCESS_KEY_SECRET` / `ALIYUN_SMS_SIGN_NAME` / `ALIYUN_SMS_LOGIN_TEMPLATE_CODE` / `ALIYUN_SMS_RESET_PASSWORD_TEMPLATE_CODE` | 阿里云短信验证码配置（未启用时自动降级脱敏日志） | `false` |
| `SPRING_DATA_REDIS_DATABASE` / `CAPTCHA_ENABLE` / `SPRING_JACKSON_TIME_ZONE` / `LOGGING_FILE_NAME` | 可选运行时微调（Redis 库号、滑块验证码开关、时区、日志路径） | `0` / `true` / `Asia/Shanghai` |

Private file access boundary:
- `local`: `/infra/file/private/presigned-get-url` returns business error `FILE_PRIVATE_SIGNING_UNSUPPORTED` (1_001_003_010); read private files through the authorized `/infra/file/private/content` route (supported by both providers).
- `aliyun-oss`: one signed GET per file record (owner or file-query permission), only for that record's object key; `expirationSeconds` min 60, default 900, max 3600 (`X-Amz-Expires`).

## 2. 构建生产产物与容器镜像

### 2.1 后端（3 模块聚合 JAR）
```bash
cd 后端代码/basic-framework-boot
mvn -B -ntp clean package -DskipTests
docker build -t basic-framework-backend:v2.0 ./basic-framework-server
```
- 镜像基于非 root `eclipse-temurin:17-jre-alpine`，监听 `48080`。
- 本地附件需要持久卷，容器内路径须与 `FILE_LOCAL_BASE_PATH` 一致。宿主目录须提前授予后端镜像内 `appuser` 读写权限。见 [启动示例](#container-startup)。

### 2.2 前端（单包 Nginx 静态镜像）
```bash
cd 前端代码/basic-framework-admin
pnpm install --frozen-lockfile
pnpm run build
docker build -t basic-framework-admin:v2.0 .
```
- 镜像基于非 root `nginxinc/nginx-unprivileged:1.27-alpine`，监听 `8080`，已内置安全响应头（CSP / `X-Frame-Options` / `X-Content-Type-Options`）与 `/admin-api/`、`/system/oauth2/` 反向代理。
- 运行时公开配置位于 `/usr/share/nginx/html/_app.config.js`（已配置 `Cache-Control: no-store`），默认值来自前端的 [`public/_app.config.js`](../前端代码/basic-framework-admin/public/_app.config.js)。挂载同名文件后可调整标题和 API 地址。`VITE_APP_CAPTCHA_ENABLE` 控制浏览器展示，配置须与后端 `basic-framework.captcha.enable` 一致，发布默认两端启用。

### 2.3 启动前后端容器

提前按 [后端配置模板](../后端代码/basic-framework-boot/.env.example) 准备受保护的 `/srv/basic-framework/backend.env`，包含第 1 节运行变量。MySQL 和 Redis 地址须从后端容器可达，生产 MySQL 地址须匹配 TLS 证书身份。先完成空库初始化和超管口令交接，再依次启动后端和前端。

```bash
docker network create basic-framework-net
docker run -d --name basic-framework-server --network basic-framework-net \
  --network-alias basic-framework-backend \
  --env-file /srv/basic-framework/backend.env \
  -e FILE_STORAGE_PROVIDER=local -e FILE_LOCAL_BASE_PATH=/data/files \
  -v /srv/basic-framework/files:/data/files \
  basic-framework-backend:v2.0
docker run -d --name basic-framework-web --network basic-framework-net \
  -p 127.0.0.1:8080:8080 \
  basic-framework-admin:v2.0
```

Nginx 通过同一网络上的 `basic-framework-backend:48080` 代理请求。样例从宿主机的 `http://127.0.0.1:8080` 访问前端。

## 3. 离线内网交付

> **Empty-schema bootstrap (new installs only).** Initialize the database with
> `scripts/runtime/bootstrap-empty-schema.sh <database>`, not by piping the raw SQL
> into `mysql`: the raw SQL drops existing baseline tables (`DROP TABLE IF EXISTS`).
> The script refuses, before importing anything, unless the schema exists and holds
> no tables, views, routines or events (missing schema, SQL errors or a nonzero
> count all fail). It then imports the baseline with exactly its 14 `DROP TABLE`
> lines removed and stops at the first SQL error, so a concurrent writer causes a
> `CREATE TABLE` failure rather than data loss.
>
> - Purpose: one-time initialization of a dedicated, freshly provisioned schema.
>   The script must be the sole initializer and sole writer during bootstrap;
>   provisioning must fail closed if it fails (drop and re-provision, never retry
>   into a partial schema).
> - The MySQL account needs schema-wide privileges/visibility on the target schema;
>   objects it cannot see would make the emptiness check unreliable.
> - Connection: `MYSQL_HOST` + optional `MYSQL_TCP_PORT`, or `MYSQL_UNIX_PORT`,
>   plus `MYSQL_USER`. Option files and login paths are ignored (`--no-defaults`
>   `--no-login-paths`; requires MySQL 8.4 or an Oracle MySQL client supporting
>   `--no-login-paths`) and no extra `mysql` flags are accepted. Provide the password only through the inherited
>   `MYSQL_PWD` environment of a protected process, never in arguments or the repository.
> - TCP provisioning uses `VERIFY_IDENTITY`. Set `MYSQL_SSL_CA` to the trusted CA file.
> - Keep the guarded script and `数据库文件/basic_framework.sql` in their repository-relative paths.
> - Existing installs: deployment state is unknown and no migrations are provided.
>   Do not run this script or the raw SQL against them. Stop the application,
>   inventory the schema, rehearse backup and restore, and apply only reviewed,
>   ordered migrations after verification.

1. 在可联网构建机打包后端 JAR、前端 `dist/` 与基础镜像，并执行 `docker save` 导出镜像 tar 包。
2. 将 `数据库文件/basic_framework.sql`（14 张干净基线表）、初始化脚本、镜像 tar 包与脱敏后的 `.env.example` 拷贝至内网目标机。
3. 内网目标机导入镜像（`docker load`），启动 MySQL 与 Redis，在预先创建的空 schema 上执行 `bootstrap-empty-schema.sh`，安装 14 张基线表。
4. 启动后端前，由运维在受控环境生成符合应用复杂度要求的一次性初始口令及 BCrypt 哈希。仅更新 `system_users` 中种子超管（`id=1`、`username=admin`、`user_type=super_admin`）的 `password`，保持 `password_change_required` 为 1。核对更新恰好一条，通过受保护渠道交接初始口令。第 5 步完成后从超管入口首登并完成强制改密。
5. 配置 `FILE_STORAGE_PROVIDER=local` 与显式 `FILE_LOCAL_BASE_PATH`，将附件卷挂载到同一路径（`appuser` 可写），按 [启动示例](#container-startup) 启动后端与前端容器。
6. 按运维周期轮换 `SM2_PRIVATE_KEY`（轮换后重启服务并刷新浏览器缓存即可生效）。
