# 纠错即门禁

## 摘要

代码审查中纠正过一次的问题，默认在同一次变更里补一条会失败的检查：测试、lint 或类型检查。只改代码、只写审查评论或在 `AGENTS.md` 增加提醒，都不算完成。检查接入现有入口后，后续改坏会直接变红，而不是依赖下一位审查者记得同一条规则。

<a id="约定"></a>

## 约定

纠正发生时按以下顺序落地：

1. 先写检查，在未修复的代码上运行并确认失败，保留失败命令和关键输出。
2. 再改代码、配置或文档，让同一检查通过。
3. 检查接入已有入口，不新增只能手工执行、没有调用方的脚本。
4. 无法写成确定性检查时，在 PR 正文说明原因、替代核查方式和覆盖缺口，不把提醒文字当作门禁。

反向证明（故意改坏后检查变红）不提交，也不能为了通过而放宽规则、增加忽略或删除检查。

<a id="已有门禁"></a>

## 已有门禁

| 门禁 | 入口 | 覆盖范围 | 反向证明 |
| --- | --- | --- | --- |
| TS4058 声明发布 | 管理前端根 `pnpm check:type`（turbo `typecheck`） | `tabs-ui` 等 `packages/@core` 包执行 `vue-tsc` 声明输出，且全工作区含源码包均纳入 `typecheck` | 在导出函数返回类型中引用未导出的 `Props` 或移除包的 `scripts.typecheck` 时检查变红 |
| e2e 明文凭据 | 仓库根 `python -B -X utf8 -m pytest scripts/tests/test_e2e_scan_safe.py` | `apps/web-ele/e2e` 下的规格、README 和夹具文本；拒绝真实形态的口令、HMAC 等字面量 | 在规格中恢复字面量口令时测试变红 |
| 前端坏味道门禁 | 管理前端根 `CI=true pnpm lint` 与 [`footguns.node.mjs`](../../前端代码/basic-framework-admin/internal/lint-configs/eslint-config/tests/footguns.node.mjs) | 禁止空 `catch`、`.vue` 裸 `@ts-ignore`/`@ts-expect-error`、未闭合 `eslint-disable`、`it.skip` 及被注释掉的测试用例 | 在源码或测试中引入空 `catch {}`、裸 `@ts-ignore` 或 `it.skip` 时检查变红 |
| 后端分层与接口边界 | Java 工程 `mvn -B -ntp -Pquality-gate verify`（[`FootgunArchitectureTest.java`](../../后端代码/basic-framework-boot/basic-framework-server/src/test/java/com/basicframework/server/archunit/FootgunArchitectureTest.java)） | 禁止 `core` 依赖 `module`/`server`、Controller 暴露 `*DO`、业务模块抛裸异常及混用旧日志 API | 在 `FootgunArchitectureFailureTest` 构造违规样本类时规则准确命中 |
| 后端环境模板双射 | Java 工程 `mvn test`（[`LocalEnvironmentConfigurationTest.java`](../../后端代码/basic-framework-boot/basic-framework-server/src/test/java/com/basicframework/server/LocalEnvironmentConfigurationTest.java)） | 校验 `.env.example` 与 `application*.yaml` 占位符双向绑定，杜绝悬空环境变量 | 在 `.env.example` 写入未被 YAML 引用的键时测试失败 |
| Markdown 空链接与空锚点 | 仓库根 `python -B -X utf8 scripts/docs/verify_md_links.py`（[`test_documents.py`](../../scripts/tests/test_documents.py)） | 拒绝 `[文案]()`、`![图片]()` 与 `[文案](#)` 等空目标占位符 | 在文档中写入空括号链接或裸 `#` 锚点时检查返回非零退出码 |
| CI 与文档索引漂移 | 仓库根 `python -B -X utf8 -m pytest scripts/tests/test_init_local_dev.py` | 校验 `.github/workflows/ci.yml` 实际必过步骤与 `脚本使用索引.md`、`README.md` 描述一致 | 在文档中将必过门禁误写为暂不阻断时测试变红 |

e2e 检查只读取文本文件，不把 `fixtures/` 下的 xlsx、png 当作文本密码库。`CHANGE_ME_*` 等占位符、环境变量读取和隔离测试库的 BCrypt 摘要不属于明文凭据；边界以测试源码为准。

<a id="新增门禁"></a>

## 新增门禁

新增检查沿用现有边界：

- 放在已有测试或检查目录，使用所在语言的既有框架；命令写入本页或[脚本使用索引](脚本使用索引.md)。
- 只读被检查内容，不回显命中的敏感值，不因缺少依赖或空范围而静默通过。
- 同时提供合法样本通过和目标反例失败的测试，反例覆盖规则本身，而不只覆盖入口是否存在。
