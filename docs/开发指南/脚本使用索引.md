## 按任务选择

先确定修改的是运行行为、交付入口还是检查规则，再选择对应消费者的验证。完整覆盖口径见[测试策略](../测试与可靠性/测试策略.md)，质量入口和失败码见[质量检查脚本](质量检查脚本.md)。

| 当前任务 | 选择入口 |
| --- | --- |
| Markdown、README、Skill | 文档链接、路径、结构、策略、README 和技能检查；含 Mermaid 时补解析检查 |
| Java 业务、SQL 或配置 | 所属 Maven 模块及受影响消费方测试、Java 增量注释；SQL 与权限补真实隔离联调；改动 Controller/VO 时补 `--group boundaries` |
| Vue、TypeScript 页面或组件 | 定向 Vitest、类型和注释；交付或路由变化补生产构建与浏览器验证 |
| 登录、菜单权限或核心 CRUD 的浏览器行为 | 仓库根[浏览器业务端到端](#浏览器业务端到端)；缺少隔离环境时如实失败 |
| 前端清单、导入层级、端点读取 | `pnpm quality:workspace` 与 `pnpm quality:layers`（真实语法树审计）；仓库根的 `--group boundaries` 追加包级循环与声明核对 |
| 检查器、规则、调度或解析桥接 | 工具测试加实际 CLI；合法场景通过、目标反例失败 |
| 准备静态交付包 | 构建记录、打包、核验和静态冒烟；另外验证浏览器、登录和后端接口 |
| 需要提交前检查 | 读取实际暂存范围并运行暂存检查；结果只证明索引中的版本。安装入口见"提交钩子安装与核对" |
| 性能基线、预算或性能回归判定 | [性能基线与预算](#perf-checks)；需要真实隔离环境，缺失时明确失败 |
| 交付物第三方许可盘点或分发义务核对 | [性能基线与预算](#perf-checks) 的 `license_inventory.py`；只登记事实与缺口，结论由有权者给出 |

## 启动与构建

开发启动命令从仓库根运行；环境与配置分别查 [Java README](../../后端代码/basic-framework-boot/README.md)和[前端 README](../../前端代码/basic-framework-admin/README.md)。目标环境交付查[部署说明](../部署/部署说明.md)，数据库、Redis 和对象存储由使用项目按自身环境提供。示例命令不构成导入数据库或覆盖配置的授权。

| 工作目录 | 命令 | 结果与边界 |
| --- | --- | --- |
| 仓库根 | `pwsh -File scripts/runtime/start_java.ps1 -Build` | 打包并运行 Java；启动脚本的跳过测试参数不构成测试证据 |
| 仓库根 | `pwsh -File scripts/runtime/start_frontend.ps1` | 运行管理前端开发服务 |
| 仓库根 | `bash scripts/runtime/start_java.sh -b` | 无 PowerShell 时启动 Java 的等价入口：先打包再运行，`.env` 与 JAR 路径的先决条件和 `start_java.ps1` 一致 |
| 仓库根 | `bash scripts/runtime/start_frontend.sh` | 无 PowerShell 时启动管理前端的等价入口：与 `start_frontend.ps1` 同样执行 `pnpm dev:ele` |
| 仓库根 | `mvn -B -ntp -f scripts/database/pom.xml flyway:info` | 读取显式指定的数据库版本；必须同时注入 `FLYWAY_URL`、`FLYWAY_USER`、`FLYWAY_PASSWORD`，且 `FLYWAY_URL` 必须带库名（例如 `jdbc:mysql://127.0.0.1:3306/basic_framework?...`），缺凭据或 URL 不含库名时会报 `Unable to determine schema for the schema history table` 并退出 1；安装、升级与备份按[数据库流程](../部署/数据库初始化与迁移.md)，不自动操作数据库 |
| 仓库根或交付目录 | [独立管理员初始化命令](../部署/数据库初始化与迁移.md#创建首个管理员) | 使用实际应用 JAR、目标库确认与受控口令输入，只在空身份库创建账号及角色关联 |
| [Java 工程](../../后端代码/basic-framework-boot/) | `mvn test` | 聚合单元测试；核对 Surefire 实际测试数量 |
| Java 工程 | 文件专项命令见[文件上传验证](../部署/文件上传协议.md#隔离验证) | 真实 MySQL/MinIO 事务、签名与补偿；显式环境缺失时失败 |
| Java 工程 | 容量统计定向命令见[并发契约](../性能优化/性能调查与证据.md#对象容量统计的并发契约) | 实际模块 API 的并发快照与采集边界；不代表浏览器延迟 |
| Java 工程 | `mvn -Pquality-audit verify` | 测试、JaCoCo 和 PMD；PMD 只执行 maven-pmd-plugin 默认规则集（实测 45 条，覆盖 bestpractices、codestyle、design、errorprone、multithreading、performance），不含命名、魔法值、资源关闭、事务边界、幂等与注释规则，不能据此认为已完整执行某套更大的 Java 规范；明确报告覆盖缺口，不能作为最终交付通过 |
| Java 工程 | `mvn -Pquality-gate verify` | 测试、PMD 和逐文件 LINE/METHOD 全覆盖；范围为实际 Maven reactor |
| [管理前端](../../前端代码/basic-framework-admin/) | `pnpm install --frozen-lockfile` | 安装已锁定版本并执行工具 stub；不升级依赖 |
| 管理前端 | `pnpm -r --if-present run stub` | 安装忽略脚本或复制缓存后，重建当前目录的工具入口 |
| 管理前端 | `pnpm check:type` | `turbo run typecheck`：应用、`packages/**` 与 `internal/**` 各包按自身 tsconfig 做 TypeScript/Vue 类型检查；任一包报错即失败 |
| 管理前端 | `pnpm build:ele` | 输出 `apps/web-ele/dist`；不执行业务测试 |
| 管理前端 | `pnpm build:docker` | 先生产构建，再制作 `basic-framework-admin:local` 静态前端镜像；不自动停止/删除容器或部署服务 |

## 根目录质量检查

下列命令从仓库根执行，Python 环境准备见[准备环境](质量检查脚本.md#准备环境)。`--list` 只列入口，`--checks` 自动补齐前置检查；调度器默认并发 3 项，单项超时 180 秒，可分别用 `--jobs`、`--timeout` 指定正整数。

```powershell
python -B -X utf8 scripts/workflow/run_checks.py --list
python -B -X utf8 scripts/workflow/run_checks.py --group docs
python -B -X utf8 scripts/workflow/run_checks.py --group comments
python -B -X utf8 scripts/workflow/run_checks.py --group boundaries
python -B -X utf8 scripts/workflow/run_checks.py --checks md-links skills --json
python -B -X utf8 scripts/workflow/change_scope.py --base HEAD
python -B -X utf8 scripts/workflow/run_checks.py --group docs --json --report "$env:TEMP/quality-report.json"
python -B -X utf8 scripts/workflow/verify_report.py "$env:TEMP/quality-report.json" --json
```

| --- | --- | --- |
| Markdown 链接 | [verify_md_links.py](../../scripts/docs/verify_md_links.py) | 相对链接、图片与锚点；不联网检查 URL |
| 文档与源码路径 | [verify_doc_refs.py](../../scripts/docs/verify_doc_refs.py) | 文档行内代码路径和源码文档引用 |
| 页面结构、策略、README | [verify_doc_structure.py](../../scripts/docs/verify_doc_structure.py)、[verify_doc_policy.py](../../scripts/docs/verify_doc_policy.py)、[verify_package_readmes.py](../../scripts/docs/verify_package_readmes.py) | 折叠、当前规则中的禁用引用、包类别结构 |
| 技能元数据 | [verify_skill_metadata.py](../../scripts/skills/verify_skill_metadata.py) | 技能目录、name、description 及调用策略 |
| Mermaid | [verify_mermaid.py](../../scripts/docs/verify_mermaid.py) | 真实围栏语法；使用管理前端依赖 |
| Java、Python 工具注释 | [check_worktree_comments.py](../../scripts/code/check_worktree_comments.py) | 使用临时索引检查当前改动，不覆盖 Web |
| Java 全量注释 | [check_full_java_comments.py](../../scripts/code/java/check_full_java_comments.py) | 全部纳管 Java 文件（当前 904 个）的每个声明，规则与暂存检查器相同；检查对象数固定等于文件数，干净工作区也不会退化成零对象，已作为 `java-comments-full` 随 `--group comments` 阻断 |
| Web 注释 | [check_worktree_web_comments.py](../../scripts/code/web/check_worktree_web_comments.py) | 工作区增量；`--all` 检查全部声明，`--staged` 读取索引。`--all` 当前仍有未清零的历史问题，尚未接入阻断门禁，现状与命令见[前端 README](../../前端代码/basic-framework-admin/README.md) |
| 后端模块边界 | [verify_backend_boundaries.py](../../scripts/code/java/verify_backend_boundaries.py) | 17 个 Maven 模块的内部依赖边、单体依赖方向、跨业务模块实现引用与登记扩展点的真实消费方 |
| 后端接口契约 | [verify_api_contracts.py](../../scripts/code/java/verify_api_contracts.py) | 145 个端点的模型边界、统一响应协议、逐端点授权登记与响应模型敏感字段输出范围 |
| 出口型方法可观测性 | [scan_exit_type_methods.py](../../scripts/code/java/scan_exit_type_methods.py) | 读 `target/classes` 字节码列出"方法体无分支、唯一出口是方法末尾 `xreturn`"的方法，输出文件、方法、行范围与判定依据；只做可观测性，不改阈值、不改退出码、不自动豁免文件 |
| 前端工作区分层 | [verify_workspace_layering.py](../../scripts/code/web/verify_workspace_layering.py) | workspace 包真实引用图、分层方向、未声明依赖、别名越界与包级循环 |
| D16 逐条复核材料 | [build_d16_review_package.py](../../scripts/tools/build_d16_review_package.py) | 为严格比较成立的候选生成逐条复核材料（对象标识、代码流读数、逐行差异归因、注释逐字原文与指纹、作者与来源事实、契约影响标记、复现命令与未解决问题），并生成 D16 §84 通配符导入扩展材料；`--verify-item`／`--verify-wildcard` 复算并与材料比对，任一读数不符即非零退出。只准备材料、不判定：判定列一律留空，工具不进入任何门禁组 |
| 证据复核 | [verify_report.py](../../scripts/workflow/verify_report.py) | 核对报告输入、规则与工具指纹；内容变化、零对象假通过或运行中变动不能作为有效证据 |
| 暂存版本 | [check_staged_quality.py](../../scripts/workflow/check_staged_quality.py) | 按暂存范围路由，包含密钥扫描和受删除影响的引用方 |
| 提交钩子安装与核对 | [install_git_hooks.py](../../scripts/workflow/install_git_hooks.py) | 把 `core.hooksPath` 指向受版本控制的 `.githooks`，核验钩子文件可执行位与索引模式；`.git/hooks` 下已有其他管理器写入的钩子时以退出码 2 明确拒绝，避免被静默忽略；`--check` 只核对不改动 |
| 密钥扫描 | [scan_staged_secrets.py](../../scripts/security/scan_staged_secrets.py) | 独立暂存扫描；不包含在 run_checks 中 |
| 业务项目决策记录 | [verify_agent_note_classification.py](../../scripts/docs/verify_agent_note_classification.py)、[verify_agent_note_format.py](../../scripts/docs/verify_agent_note_format.py) | 仅检查当前项目自行建立的活动记录；框架不携带维护历史 |

报告保存到仓库及工具目录之外。报告区分实际通过、失败、不适用、环境错误、超时和未运行；全部没有实际检查对象不能通过。保存的指纹用于内容一致性复核，不是防伪签名，不能代替真实验证。

单项文档脚本可传仓库相对文件或目录，例如 `python -B -X utf8 scripts/docs/verify_md_links.py docs/开发指南`。工作区与暂存版本不能混用，零对象和跳过不能证明该范围已验证。

<a id="perf-checks"></a>

## 性能基线与预算

入口在 [scripts/perf](../../scripts/perf) 下，从仓库根执行。测量只使用真实 HTTP 入口与真实中间件，不复制产品算法、不注入替身；判定只消费实测报告与受版本控制的预算文件，不发请求、不读环境变量。预算数值与适用范围见[性能预算与基线](../性能优化/性能预算与基线.md#decisions)，当前状态为待有权者确认。**发布门禁接入**：`perf_budget.py` 未登记进 `run_checks.py` 任一分组，但已进入 `ci_gate.RELEASE_CHECKS` 的 `backend-performance-budget`，发布阶段真实测量、缺项即拒绝发布证据；预算未获有权者批准时 release 一律红，接法见[发布门禁接入](../性能优化/性能预算与基线.md#release-gate)。

| 入口 | 用途与副作用 | 输出与退出码 |
| --- | --- | --- |
| [run_baseline.py](../../scripts/perf/run_baseline.py) | 写：自建隔离环境（随机单库、结构导入、一次性管理员、合成数据集、独占 Redis 逻辑库）并按两轮重启后端后测量；退出时按所有权回收本次取得的全部资源 | 0 未超预算；1 超预算或证据不足；2 环境失败或回收不完整 |
| [seed_dataset.py](../../scripts/perf/seed_dataset.py) | 写：向显式确认的同名隔离库重建固定常量合成数据集；先删除本工具前缀的历史行 | 0 写入完成；2 目标未确认或凭据/客户端缺失 |
| [measure_endpoints.py](../../scripts/perf/measure_endpoints.py) | 只读被测系统；对目标发真实请求并写报告 | 0 报告已生成；2 缺少凭据、目标不可达或任一场景失败 |
| [merge_reports.py](../../scripts/perf/merge_reports.py) | 只读两份报告并写合并结果；条件不一致时拒绝合并 | 0 已写出；2 输入不可读或不可比 |
| [perf_budget.py](../../scripts/perf/perf_budget.py) | 只读核对预算 | 0 全部满足且构件绑定成立；1 超预算、证据不足或绑定不符；2 报告/预算不可用（含预算未声明可复现绑定）。退出码 2 在 `--json` 下同样写出结论文档（`status` 为 `unavailable`，附 `unavailable` 段写明类别、原因与处置），退出码本身不变 |
| [source_identity.py](../../scripts/perf/source_identity.py) | 只读：按工作区真实内容计算可复现源码身份（Git 修订 + 源码内容摘要），供性能预算绑定被测版本 | 0 身份已算出；2 Git 检出不可用或源码范围缺失 |
| [fault_proxy.py](../../scripts/perf/fault_proxy.py) | 仅在环回地址插入固定延迟，**只用于负对照** | 常驻监听；2 参数不可用 |

<a id="资源所有权与回收"></a>

### 资源所有权与回收

规则是"先证明独占、再使用、按证明回收"，预置的外部数据与并发运行的数据都不在清理范围内：

- **取得**：端口预检通过后才连接 Redis，只读取目标库键数量并写入一个带 6 小时存活时间的标记键 `bf-business-e2e:owner`；非空库一律跳过（自动挑选）或明确失败（`--redis-database` 显式指定），不存在任何预清空动作。
- **回收**：只有标记值仍等于本次运行随机令牌时才执行 `FLUSHDB`，标记被替换即拒绝清理并报告；MySQL 随机库在 `CREATE DATABASE` 成功后才登记，端口预检或构建失败时不会尝试删除从未创建的库。
- **进程**：按精确 PID 回收，不使用按名匹配的清理。POSIX 上仅在自己创建的独立进程组内整组回收，Windows 上先用 `taskkill /PID <pid> /T /F` 回收进程树、缺少该命令时回退到按 PID 结束；单项回收失败不中断其余资源回收，残留会在标准错误逐条报告并让退出码变为 2。
- **异常退出**：SIGTERM/SIGBREAK 被转换为可捕获中断，中断与运行期异常都在向外抛出前完成回收；`--keep` 则保留全部资源供人工诊断。进程被强杀（SIGKILL）时无法执行回收，残留标记会在存活期内阻止其他运行把该库当成空库复用。

运行期验证码开关在产物副本中关闭（后端同步 `BASIC_FRAMEWORK_CAPTCHA_ENABLE=false`），原始 `dist` 不被修改。CI 作业 `browser_e2e` 使用同一入口，缺少环境时红灯。

镜像来源都写在 [ci_services.py](../../scripts/workflow/ci_services.py) 的 `VERIFIED_IMAGES` 中，三者都拒绝只带标签的来源：`mysql` 与 `redis` 的 `sha256` 摘要已用 `docker manifest inspect` 核对过 linux/amd64 清单；`minio` 上游已不再提供匿名可拉取的官方镜像（Docker Hub `minio/minio` 与 quay.io 均拒绝匿名访问，`dl.min.io` 官方端点返回 410），因此默认值改用一个与官方镜像元数据一致的公开镜像，并已在本机真实 Docker 上按 `server /data` 启动、校验 `/minio/health/ready` 返回 200。`BF_CI_IMAGE_MINIO`、`BF_CI_IMAGE_MYSQL`、`BF_CI_IMAGE_REDIS` 都可覆盖默认值，覆盖值同样必须按摘要固定；`ci_services.py images` 是启动前的统一预检。

文档检查（`md-links`、`doc-refs`、`doc-structure`、`doc-policy`、`mermaid`）需要 `markdown-it-py` 与 `mdurl`，`skills`、`package-readmes` 需要 `PyYAML`；三者都锁定在 `requirements-ci.txt`，`docs_tools` 作业必须自己安装，不能依赖其他作业的 pip 环境。

`cryptography`、`cffi`、`pycparser` 是必需项而不是可选加固：PyMySQL 连接 MySQL 8.x 的 `caching_sha2_password` 时，服务端未缓存认证需要走 RSA 全量认证，缺少 `cryptography` 会直接抛 `RuntimeError`。
