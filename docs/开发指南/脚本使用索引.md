## 按任务选择

先确定修改的是运行行为、交付入口还是检查规则，再选择对应消费者的验证。完整覆盖口径见[测试策略](../测试与可靠性/测试策略.md)，质量入口和失败码见[质量检查脚本](质量检查脚本.md)。

| 当前任务 | 选择入口 |
| --- | --- |
| Markdown、README、Skill | 文档链接、路径、结构、策略、README 和技能检查；含 Mermaid 时补解析检查 |
| Java 业务、SQL 或配置 | 所属 Maven 模块及受影响消费方测试、Java 增量注释；SQL 与权限补真实隔离联调 |
| Vue、TypeScript 页面或组件 | 定向 Vitest、类型和注释；交付或路由变化补生产构建与浏览器验证 |
| 前端清单、导入层级、端点读取 | 工作区约束与相应源码审计；清单关系变化核对模块图 |
| 检查器、规则、调度或解析桥接 | 工具测试加实际 CLI；合法场景通过、目标反例失败 |
| 准备静态交付包 | 构建记录、打包、核验和静态冒烟；另外验证浏览器、登录和后端接口 |
| 需要提交前检查 | 读取实际暂存范围并运行暂存检查；结果只证明索引中的版本 |

## 启动与构建

开发启动命令从仓库根运行；环境与配置分别查 [Java README](../../后端代码/basic-framework-boot/README.md)和[前端 README](../../前端代码/basic-framework-admin/README.md)。目标环境交付查[部署说明](../部署/部署说明.md)，数据库、Redis 和对象存储由使用项目按自身环境提供。示例命令不构成导入数据库或覆盖配置的授权。

| 工作目录 | 命令 | 结果与边界 |
| --- | --- | --- |
| 仓库根 | `pwsh -File scripts/runtime/start_java.ps1 -Build` | 打包并运行 Java；启动脚本的跳过测试参数不构成测试证据 |
| 仓库根 | `pwsh -File scripts/runtime/start_frontend.ps1` | 运行管理前端开发服务 |
| 仓库根 | `mvn -B -ntp -f scripts/database/pom.xml flyway:info` | 读取显式指定的数据库版本；安装、升级与备份按[数据库流程](../部署/数据库初始化与迁移.md)，不自动操作数据库 |
| 仓库根或交付目录 | [独立管理员初始化命令](../部署/数据库初始化与迁移.md#创建首个管理员) | 使用实际应用 JAR、目标库确认与受控口令输入，只在空身份库创建账号及角色关联 |
| [Java 工程](../../后端代码/basic-framework-boot/) | `mvn test` | 聚合单元测试；核对 Surefire 实际测试数量 |
| Java 工程 | 文件专项命令见[文件上传验证](../部署/文件上传协议.md#隔离验证) | 真实 MySQL/MinIO 事务、签名与补偿；显式环境缺失时失败 |
| Java 工程 | 容量统计定向命令见[并发契约](../性能优化/性能调查与证据.md#对象容量统计的并发契约) | 实际模块 API 的并发快照与采集边界；不代表浏览器延迟 |
| Java 工程 | `mvn -Pquality-audit verify` | 测试、JaCoCo 和 PMD，明确报告覆盖缺口；不能作为最终交付通过 |
| Java 工程 | `mvn -Pquality-gate verify` | 测试、PMD 和逐文件 LINE/METHOD 全覆盖；范围为实际 Maven reactor |
| [管理前端](../../前端代码/basic-framework-admin/) | `pnpm install --frozen-lockfile` | 安装已锁定版本并执行工具 stub；不升级依赖 |
| 管理前端 | `pnpm -r --if-present run stub` | 安装忽略脚本或复制缓存后，重建当前目录的工具入口 |
| 管理前端 | `pnpm check:type` | 当前应用的 TypeScript/Vue 类型检查 |
| 管理前端 | `pnpm build:ele` | 输出 `apps/web-ele/dist`；不执行业务测试 |
| 管理前端 | `pnpm build:docker` | 先生产构建，再制作 `basic-framework-admin:local` 静态前端镜像；不自动停止/删除容器或部署服务 |

## 根目录质量检查

下列命令从仓库根执行，Python 环境准备见[准备环境](质量检查脚本.md#准备环境)。`--list` 只列入口，`--checks` 自动补齐前置检查；调度器默认并发 3 项，单项超时 180 秒，可分别用 `--jobs`、`--timeout` 指定正整数。

```powershell
python -B -X utf8 scripts/workflow/run_checks.py --list
python -B -X utf8 scripts/workflow/run_checks.py --group docs
python -B -X utf8 scripts/workflow/run_checks.py --group comments
python -B -X utf8 scripts/workflow/run_checks.py --checks md-links skills --json
python -B -X utf8 scripts/workflow/change_scope.py --base HEAD
python -B -X utf8 scripts/workflow/run_checks.py --group docs --json --report "$env:TEMP/quality-report.json"
python -B -X utf8 scripts/workflow/verify_report.py "$env:TEMP/quality-report.json" --json
```

| 检查 | 独立入口 | 检查范围 |
| --- | --- | --- |
| Markdown 链接 | [verify_md_links.py](../../scripts/docs/verify_md_links.py) | 相对链接、图片与锚点；不联网检查 URL |
| 文档与源码路径 | [verify_doc_refs.py](../../scripts/docs/verify_doc_refs.py) | 文档行内代码路径和源码文档引用 |
| 页面结构、策略、README | [verify_doc_structure.py](../../scripts/docs/verify_doc_structure.py)、[verify_doc_policy.py](../../scripts/docs/verify_doc_policy.py)、[verify_package_readmes.py](../../scripts/docs/verify_package_readmes.py) | 折叠、当前规则中的禁用引用、包类别结构 |
| 技能元数据 | [verify_skill_metadata.py](../../scripts/skills/verify_skill_metadata.py) | 技能目录、name、description 及调用策略 |
| Mermaid | [verify_mermaid.py](../../scripts/docs/verify_mermaid.py) | 真实围栏语法；使用管理前端依赖 |
| Java、Python 工具注释 | [check_worktree_comments.py](../../scripts/code/check_worktree_comments.py) | 使用临时索引检查当前改动，不覆盖 Web |
| Web 注释 | [check_worktree_web_comments.py](../../scripts/code/web/check_worktree_web_comments.py) | 工作区增量；`--all` 检查全部声明，`--staged` 读取索引 |
| 证据复核 | [verify_report.py](../../scripts/workflow/verify_report.py) | 核对报告输入、规则与工具指纹；内容变化、零对象假通过或运行中变动不能作为有效证据 |
| 暂存版本 | [check_staged_quality.py](../../scripts/workflow/check_staged_quality.py) | 按暂存范围路由，包含密钥扫描和受删除影响的引用方 |
| 密钥扫描 | [scan_staged_secrets.py](../../scripts/security/scan_staged_secrets.py) | 独立暂存扫描；不包含在 run_checks 中 |
| 业务项目决策记录 | [verify_agent_note_classification.py](../../scripts/docs/verify_agent_note_classification.py)、[verify_agent_note_format.py](../../scripts/docs/verify_agent_note_format.py) | 仅检查当前项目自行建立的活动记录；框架不携带维护历史 |

报告保存到仓库及工具目录之外。报告区分实际通过、失败、不适用、环境错误、超时和未运行；全部没有实际检查对象不能通过。保存的指纹用于内容一致性复核，不是防伪签名，不能代替真实验证。

单项文档脚本可传仓库相对文件或目录，例如 `python -B -X utf8 scripts/docs/verify_md_links.py docs/开发指南`。工作区与暂存版本不能混用，零对象和跳过不能证明该范围已验证。

## 前端命令

命令均在管理前端根运行；这套工具不汇总 Java 测试。新增工具中的写入和只读行为分列如下。

| 入口 | 用途与副作用 | 详细说明 |
| --- | --- | --- |
| `pnpm quality:workspace` | 检查 workspace 与 catalog 声明 | [工作区依赖](质量检查脚本.md#前端工作区依赖) |
| `pnpm quality:dependencies` / `quality:layers` / `quality:config` | 只读审计依赖、分层或端点；合并入口 `quality:development` | [源码审计](前端开发检查与构建工具.md#源码审计) |
| `python -B -X utf8 scripts/quality/check_crud.py <api-path> <views-path>` | 只读核对完整 CRUD 文件、真实导入边界、应用类型与模块 ESLint；缺少环境返回非零 | [Web 技能检查](../../.agents/skills/weetion-development-web-standards/README.md#检查与验收)；原 `check.sh` 转发到此入口 |
| `pnpm graph:modules:check` | 只读核对清单生成图；`graph:modules` 写图 | [模块依赖图](前端开发检查与构建工具.md#模块依赖图) |
| `pnpm clean:artifacts` | 默认预览；显式计划确认后才删除产物 | [清理产物](前端开发检查与构建工具.md#清理产物) |
| `pnpm build:recorded` / `build:record:verify` | 前者构建并写来源记录，后者只读核对 | [构建记录](前端开发检查与构建工具.md#构建记录) |
| `pnpm test:unit:isolated` / `test:e2e:isolated` | 在子进程隔离代理后运行真实测试 | [测试代理隔离](前端测试与交付工具.md#测试代理隔离) |
| `pnpm test:coverage` / `coverage:uncovered` | 前者跑测试生成覆盖率，后者只读已有报告 | [覆盖率](前端测试与交付工具.md#覆盖率与未覆盖位置) |
| `pnpm build:analyze` | 在独立缓存目录写体积报告与分析构建 | [构建体积分析](前端测试与交付工具.md#构建体积分析) |

## CI 门禁工具

下列工具服务于 [ci.yml](../../.github/workflows/ci.yml) 的编排，只在 GitHub Linux 临时 runner 内运行；本机不是该 runner 时会受控失败，不影响开发机。

| 入口 | 用途与边界 |
| --- | --- |
| `python -B -X utf8 scripts/workflow/ci_gate.py aggregate --stage <阶段>` | 从 `NEEDS_JSON` 核对固定三作业真实成功且有正整数用例；跳过、取消、零用例、空报告一律失败 |
| `python -B -X utf8 scripts/workflow/ci_gate.py reports --backend <后端目录>` | 消费 JUnit 报告并要求四个真实集成测试类实际执行（含 OAuth 机器主体专项）；声明计数与真实用例不符即失败 |
| `python -B -X utf8 scripts/workflow/ci_services.py start` / `stop` | 启动或回收本次运行自建的 MySQL、Redis、MinIO；凭据只存在于 runner 临时环境 |
| `bash scripts/workflow/install_ci_maven.sh` | 在 runner 临时目录安装固定 Maven，校验官方 SHA-512 后解包 |
| `python -m pip install --require-hashes -r scripts/workflow/requirements-ci.txt` | 安装固定摘要的 CI 工具依赖 |

镜像来源分两类，不要混用：`mysql` 与 `redis` 的 `sha256` 摘要已用 `docker manifest inspect` 核对过 linux/amd64 清单，写在 [ci_services.py](../../scripts/workflow/ci_services.py) 的 `VERIFIED_IMAGES` 中。`minio` 来源无法在本仓库开发环境证实——Docker Hub 匿名访问返回 401，`dl.min.io` 官方二进制端点返回 410——因此**没有**写死默认值，必须由 `BF_CI_IMAGE_MINIO` 显式提供已按摘要固定的引用；`BF_CI_IMAGE_MYSQL` 与 `BF_CI_IMAGE_REDIS` 可覆盖默认值。三者都拒绝只带标签的来源。

`cryptography`、`cffi`、`pycparser` 是必需项而不是可选加固：PyMySQL 连接 MySQL 8.x 的 `caching_sha2_password` 时，服务端未缓存认证需要走 RSA 全量认证，缺少 `cryptography` 会直接抛 `RuntimeError`。

当前状态：**该流水线从未在 GitHub Actions 云端运行过**，仓库内没有任何一次真实运行记录，配置层已验证不等于门禁通过。本机 Linux 引擎不可用，容器编排只验证到配置层。

## 脚本自身的测试

仓库工具使用 pytest。修改检查器或规则时选择相关测试文件，再执行实际消费方 CLI；解析桥接测试需要管理前端已安装依赖。

```powershell
# 仓库根
python -B -X utf8 -m pytest scripts/tests
```

修改暂存检查、密钥或 Java/Python 工作区快照时，定向入口为 `python -B -X utf8 -m pytest scripts/tests/test_java_scope_git.py scripts/tests/test_staged_checkers.py scripts/tests/test_staged_quality.py`。这些用例使用独立 Git 仓库核对真实路径、无 HEAD、部分暂存、重命名、字段映射及原索引/对象库不变；仍须运行对应实际 CLI。

数据库工具的独立集成入口为 `python -B -X utf8 -m pytest scripts/database/tests/test_mysql_migrations.py -q`。需要[专用 MySQL 与客户端](../部署/数据库初始化与迁移.md#隔离验证)，实际创建和删除自有随机库，验证版本迁移、校验和与备份恢复；未包含在普通 `scripts/tests` 入口中。

CI 门禁工具的定向入口为 `python -B -X utf8 -m pytest scripts/tests/test_ci_gate.py scripts/tests/test_ci_services.py`。这些用例覆盖必需作业真实成功、跳过与取消不算通过、非字典 `outputs` 的受控失败、报告零用例与关键类遗漏、镜像来源必须按摘要固定、健康检查成功与失败路径、所有权清理不误杀外部容器、客户端入口不含凭据，以及失败输出不泄漏密码；不启动真实容器，仍须核对[CI 门禁工具](#ci-门禁工具)中的未验证项。

| 目录 | 命令 | 覆盖职责 |
| --- | --- | --- |
| 管理前端 | `pnpm quality:workspace:test` | 包发现、依赖协议、catalog、无效配置和链接边界 |
| 管理前端 | `pnpm quality:development:test` | 真实 TS/Vue 解析、图生成、清理计划和构建记录失效 |
| 管理前端 | `python -B -X utf8 -m unittest discover -s scripts/quality/tests -p test_crud_check.py` | CRUD 模块内部相对导入、越界导入、缺失配置/依赖与真实失败退出码 |
| 管理前端 | `pnpm quality:delivery:test` | 代理、超时、覆盖率定位、ZIP 篡改与静态 HTTP |
| 管理前端 | `pnpm quality:analysis:test` | Rollup 分析插件的真实产物计量 |
| 管理前端 | `pnpm quality:test` | Web 注释和 Mermaid 规则的 Node 测试 |

这些是工具测试，不替代系统管理页面、权限或真实文件上传的业务验收。

## 维护要求

新增、移动或停用脚本时，同步本索引、对应专题与模块 README；公共解析或规则变化还要验证消费方。保留真实退出状态、输入上限、诊断脱敏与清理职责，不自动安装依赖或执行被检查源码，不硬编码开发者机器路径。
