## 按任务选择

先确定修改的是运行行为、交付入口还是检查规则，再选择对应消费者的验证。完整覆盖口径见[测试策略](../测试与可靠性/测试策略.md)，质量入口和失败码见[质量检查脚本](质量检查脚本.md)。

| 当前任务 | 选择入口 |
| --- | --- |
| Markdown、README、Skill | 文档链接、路径、结构、策略、README 和技能检查；含 Mermaid 时补解析检查 |
| Java 业务、SQL 或配置 | 所属 Maven 模块及受影响消费方测试、Java 增量注释；SQL 与权限补真实隔离联调 |
| Vue、TypeScript 页面或组件 | 定向 Vitest、类型和注释；交付或路由变化补生产构建与浏览器验证 |
| 登录、菜单权限或核心 CRUD 的浏览器行为 | 仓库根[浏览器业务端到端](#浏览器业务端到端)；缺少隔离环境时如实失败 |
| 前端清单、导入层级、端点读取 | 工作区约束与相应源码审计；清单关系变化核对模块图 |
| 检查器、规则、调度或解析桥接 | 工具测试加实际 CLI；合法场景通过、目标反例失败 |
| 准备静态交付包 | 构建记录、打包、核验和静态冒烟；另外验证浏览器、登录和后端接口 |
| 需要提交前检查 | 读取实际暂存范围并运行暂存检查；结果只证明索引中的版本 |

## 启动与构建

开发启动命令从仓库根运行；环境与配置分别查 [Java README](../../后端代码/basic-framework-boot/README.md)和[前端 README](../../前端代码/basic-framework-admin/README.md)。目标环境交付查[部署说明](../部署/部署说明.md)，数据库、Redis 和对象存储由使用项目按自身环境提供。示例命令不构成导入数据库或覆盖配置的授权。

| 仓库根或交付目录 | [独立管理员初始化命令](../部署/数据库初始化与迁移.md#创建首个管理员) | 使用实际应用 JAR、目标库确认与受控口令输入，只在空身份库创建账号及角色关联 |

## 根目录质量检查

下列命令从仓库根执行，Python 环境准备见[准备环境](质量检查脚本.md#准备环境)。`--list` 只列入口，`--checks` 自动补齐前置检查；调度器默认并发 3 项，单项超时 180 秒，可分别用 `--jobs`、`--timeout` 指定正整数。

```powershell
python -B -X utf8 scripts/workflow/run_checks.py --list
python -B -X utf8 scripts/workflow/run_checks.py --group docs
python -B -X utf8 scripts/workflow/run_checks.py --group comments
python -B -X utf8 scripts/workflow/run_checks.py --checks md-links skills --json
python -B -X utf8 scripts/workflow/change_scope.py --base HEAD
python -B -X utf8 scripts/workflow/run_checks.py --group docs --json --report "$env:TEMP/quality-report.json"
python -B -X utf8 scripts/workflow/verify_report.py "$env:TEMP/quality-report.json" --json
```

| 检查 | 独立入口 | 检查范围 |
| --- | --- | --- |
| Markdown 链接 | [verify_md_links.py](../../scripts/docs/verify_md_links.py) | 相对链接、图片与锚点；不联网检查 URL |
| 文档与源码路径 | [verify_doc_refs.py](../../scripts/docs/verify_doc_refs.py) | 文档行内代码路径和源码文档引用 |
| 页面结构、策略、README | [verify_doc_structure.py](../../scripts/docs/verify_doc_structure.py)、[verify_doc_policy.py](../../scripts/docs/verify_doc_policy.py)、[verify_package_readmes.py](../../scripts/docs/verify_package_readmes.py) | 折叠、当前规则中的禁用引用、包类别结构 |
| 技能元数据 | [verify_skill_metadata.py](../../scripts/skills/verify_skill_metadata.py) | 技能目录、name、description 及调用策略 |
| Mermaid | [verify_mermaid.py](../../scripts/docs/verify_mermaid.py) | 真实围栏语法；使用管理前端依赖 |
| Java、Python 工具注释 | [check_worktree_comments.py](../../scripts/code/check_worktree_comments.py) | 使用临时索引检查当前改动，不覆盖 Web |
| Web 注释 | [check_worktree_web_comments.py](../../scripts/code/web/check_worktree_web_comments.py) | 工作区增量；`--all` 检查全部声明，`--staged` 读取索引 |
| 证据复核 | [verify_report.py](../../scripts/workflow/verify_report.py) | 核对报告输入、规则与工具指纹；内容变化、零对象假通过或运行中变动不能作为有效证据 |
| 暂存版本 | [check_staged_quality.py](../../scripts/workflow/check_staged_quality.py) | 按暂存范围路由，包含密钥扫描和受删除影响的引用方 |
| 密钥扫描 | [scan_staged_secrets.py](../../scripts/security/scan_staged_secrets.py) | 独立暂存扫描；不包含在 run_checks 中 |
| 业务项目决策记录 | [verify_agent_note_classification.py](../../scripts/docs/verify_agent_note_classification.py)、[verify_agent_note_format.py](../../scripts/docs/verify_agent_note_format.py) | 仅检查当前项目自行建立的活动记录；框架不携带维护历史 |

报告保存到仓库及工具目录之外。报告区分实际通过、失败、不适用、环境错误、超时和未运行；全部没有实际检查对象不能通过。保存的指纹用于内容一致性复核，不是防伪签名，不能代替真实验证。

单项文档脚本可传仓库相对文件或目录，例如 `python -B -X utf8 scripts/docs/verify_md_links.py docs/开发指南`。工作区与暂存版本不能混用，零对象和跳过不能证明该范围已验证。

## 浏览器业务端到端

入口 [run_business_e2e.py](../../scripts/e2e/run_business_e2e.py) 从仓库根执行，用本次运行自建的随机库、取得独占所有权的 Redis 逻辑库与临时目录准备真实后端，再在构建产物上执行 Playwright 业务用例；退出时只回收本次运行确实取得的资源，缺少连接变量、后端、浏览器或构建产物时返回 2 并给出原因，不跳过用例。

```powershell
python -B -X utf8 scripts/e2e/run_business_e2e.py
python -B -X utf8 scripts/e2e/run_business_e2e.py --skip-backend-build --skip-frontend-build
python -B -X utf8 scripts/e2e/run_business_e2e.py --list
```

| 项 | 说明 |
| --- | --- |
| 连接变量 | `AUTH_TEST_MYSQL_URL`、`AUTH_TEST_MYSQL_USERNAME`、`AUTH_TEST_MYSQL_PASSWORD`、`BF_TEST_REDIS_PORT`、`BF_TEST_REDIS_PASSWORD`、`BF_TEST_S3_ENDPOINT`、`BF_TEST_S3_ACCESS_KEY`、`BF_TEST_S3_SECRET_KEY`；可选 `BF_TEST_MYSQL_CLIENT` 指定客户端入口 |
| 默认端口与库 | 后端 48099、预览 4173；Redis 逻辑库缺省在 1–15 中挑选第一个空库，`--redis-database` 显式指定时只使用该库；库名为随机 `bf_e2e_*`，拒绝使用 0 号 Redis 库与真实业务库 |
| 种子数据 | 结构快照 [basic_framework.sql](../../数据库文件/basic_framework.sql) 加官方一次性管理员入口；账号名默认 `e2eadmin`，口令每次随机生成并只注入子进程 |
| 用例范围 | [playwright.business.config.ts](../../前端代码/basic-framework-admin/apps/web-ele/playwright.business.config.ts) 收集 [e2e-business](../../前端代码/basic-framework-admin/apps/web-ele/e2e-business) 下的规格；当前为字典类型 CRUD 完整流程与重名拒绝失败路径 |
| 诊断 | `--keep` 保留库、Redis 独占逻辑库、临时目录与进程并打印精确 PID；`--summary <路径>` 写出真实用例计数 JSON；`--list` 只列用例不启动环境 |

<a id="资源所有权与回收"></a>

### 资源所有权与回收

规则是"先证明独占、再使用、按证明回收"，预置的外部数据与并发运行的数据都不在清理范围内：

- **取得**：端口预检通过后才连接 Redis，只读取目标库键数量并写入一个带 6 小时存活时间的标记键 `bf-business-e2e:owner`；非空库一律跳过（自动挑选）或明确失败（`--redis-database` 显式指定），不存在任何预清空动作。
- **回收**：只有标记值仍等于本次运行随机令牌时才执行 `FLUSHDB`，标记被替换即拒绝清理并报告；MySQL 随机库在 `CREATE DATABASE` 成功后才登记，端口预检或构建失败时不会尝试删除从未创建的库。
- **进程**：按精确 PID 回收，不使用按名匹配的清理。POSIX 上仅在自己创建的独立进程组内整组回收，Windows 上先用 `taskkill /PID <pid> /T /F` 回收进程树、缺少该命令时回退到按 PID 结束；单项回收失败不中断其余资源回收，残留会在标准错误逐条报告并让退出码变为 2。
- **异常退出**：SIGTERM/SIGBREAK 被转换为可捕获中断，中断与运行期异常都在向外抛出前完成回收；`--keep` 则保留全部资源供人工诊断。进程被强杀（SIGKILL）时无法执行回收，残留标记会在存活期内阻止其他运行把该库当成空库复用。

运行期验证码开关在产物副本中关闭（后端同步 `BASIC_FRAMEWORK_CAPTCHA_ENABLE=false`），原始 `dist` 不被修改。CI 作业 `browser_e2e` 使用同一入口，缺少环境时红灯。

<a id="ci-门禁工具"></a>

## CI 门禁工具

下列工具服务于 [ci.yml](../../.github/workflows/ci.yml) 的编排，只在 GitHub Linux 临时 runner 内运行；本机不是该 runner 时会受控失败，不影响开发机。

| 入口 | 用途与边界 |
| --- | --- |
| `python -B -X utf8 scripts/workflow/ci_gate.py aggregate --stage <阶段>` | 从 `NEEDS_JSON` 核对四个必需作业（docs_tools、frontend、backend、browser_e2e）真实成功且有正整数用例；跳过、取消、零用例、空报告一律失败 |
| `python -B -X utf8 scripts/workflow/ci_gate.py reports --backend <后端目录>` | 消费 JUnit 报告并要求四个真实集成测试类实际执行（含 OAuth 机器主体专项）；声明计数与真实用例不符即失败 |
| `python -B -X utf8 scripts/e2e/run_business_e2e.py --summary <路径>` | `browser_e2e` 作业的真实入口；摘要中的零用例、失败、跳过与重试通过都会让作业红灯 |
| `python -B -X utf8 scripts/workflow/ci_services.py start` / `stop` | 启动或回收本次运行自建的 MySQL、Redis、MinIO；凭据只存在于 runner 临时环境 |
| `python -B -X utf8 scripts/workflow/ci_services.py images` | 启动前的镜像预检：按 sha256 核验默认值与环境覆盖值，未配置或未固定时退出 2，不创建任何容器 |
| `python -B -X utf8 scripts/workflow/static_gate.py --kind web --execute` | 发布阶段真实执行完整前端静态检查（ESLint、Prettier、Stylelint），写出 `eslint-report.json` 与 `static-analysis-web.json`；任一工具非零退出或存在违规即失败，`skipped`、零对象或旧报告都不算通过 |
| `python -B -X utf8 scripts/workflow/static_gate.py --kind backend` | 复核各模块 `target/pmd.xml`：报告存在、晚于生产源码、只引用本模块源码、PMD 版本一致且零违规；违规退出 1，缺失或过期退出 2 |
| `python -B -X utf8 scripts/workflow/coverage_gate.py --kind <后端\|web> --stage release` | 最终阶段（`full`/`release`）在签发发布文档前必须先核验静态检查证据；缺失、跳过或指纹不符时退出 2 且不输出任何证据，`audit` 阶段仍只报告覆盖缺口 |
| `bash scripts/workflow/install_ci_maven.sh` | 在 runner 临时目录安装固定 Maven，校验官方 SHA-512 后解包 |
| `python -m pip install --require-hashes -r scripts/workflow/requirements-ci.txt` | 安装固定摘要的 CI 工具依赖；每个执行 Python 检查的作业都要自己安装 |

镜像来源都写在 [ci_services.py](../../scripts/workflow/ci_services.py) 的 `VERIFIED_IMAGES` 中，三者都拒绝只带标签的来源：`mysql` 与 `redis` 的 `sha256` 摘要已用 `docker manifest inspect` 核对过 linux/amd64 清单；`minio` 上游已不再提供匿名可拉取的官方镜像（Docker Hub `minio/minio` 与 quay.io 均拒绝匿名访问，`dl.min.io` 官方端点返回 410），因此默认值改用一个与官方镜像元数据一致的公开镜像，并已在本机真实 Docker 上按 `server /data` 启动、校验 `/minio/health/ready` 返回 200。`BF_CI_IMAGE_MINIO`、`BF_CI_IMAGE_MYSQL`、`BF_CI_IMAGE_REDIS` 都可覆盖默认值，覆盖值同样必须按摘要固定；`ci_services.py images` 是启动前的统一预检。

文档检查（`md-links`、`doc-refs`、`doc-structure`、`doc-policy`、`mermaid`）需要 `markdown-it-py` 与 `mdurl`，`skills`、`package-readmes` 需要 `PyYAML`；三者都锁定在 `requirements-ci.txt`，`docs_tools` 作业必须自己安装，不能依赖其他作业的 pip 环境。

`cryptography`、`cffi`、`pycparser` 是必需项而不是可选加固：PyMySQL 连接 MySQL 8.x 的 `caching_sha2_password` 时，服务端未缓存认证需要走 RSA 全量认证，缺少 `cryptography` 会直接抛 `RuntimeError`。

## 脚本自身的测试

仓库工具使用 pytest。修改检查器或规则时选择相关测试文件，再执行实际消费方 CLI；解析桥接测试需要管理前端已安装依赖。

```powershell
# 仓库根
python -B -X utf8 -m pytest scripts/tests
```

修改暂存检查、密钥或 Java/Python 工作区快照时，定向入口为 `python -B -X utf8 -m pytest scripts/tests/test_java_scope_git.py scripts/tests/test_staged_checkers.py scripts/tests/test_staged_quality.py`。这些用例使用独立 Git 仓库核对真实路径、无 HEAD、部分暂存、重命名、字段映射及原索引/对象库不变；仍须运行对应实际 CLI。

数据库工具的独立集成入口为 `python -B -X utf8 -m pytest scripts/database/tests/test_mysql_migrations.py -q`。需要[专用 MySQL 与客户端](../部署/数据库初始化与迁移.md#隔离验证)，实际创建和删除自有随机库，验证版本迁移、校验和与备份恢复；未包含在普通 `scripts/tests` 入口中。

CI 门禁工具的定向入口为 `python -B -X utf8 -m pytest scripts/tests/test_ci_gate.py scripts/tests/test_ci_services.py`。这些用例覆盖必需作业真实成功、跳过与取消不算通过、非字典 `outputs` 的受控失败、工作流作业输出引用链闭合（逐项核对引用的步骤 id 与真实写入 `GITHUB_OUTPUT` 的输出名）、报告零用例与关键类遗漏、镜像来源必须按摘要固定、健康检查成功与失败路径、所有权清理不误杀外部容器、客户端入口不含凭据，以及失败输出不泄漏密码；不启动真实容器，仍须核对[CI 门禁工具](#ci-门禁工具)中的未验证项。

浏览器业务端到端的定向入口为 `python -B -X utf8 -m pytest scripts/tests/test_business_e2e.py`。这些用例覆盖连接地址解析、运行期配置覆盖、代理环境隔离、Redis 命令编码、端口占用判断、Playwright 报告核对与状态判定，并用真实本地 HTTP 服务核对静态产物、路径越界拒绝与 `/admin-api` 转发；另用内存 RESP 替身核对独占所有权的取得与回收（预置外部数据、并发运行、标记被替换都不得触发清理）、用真实子进程核对精确 PID 回收与孙进程整组回收、用替身记录核对预检失败、启动失败、中断、`--keep` 与回收不完整五条资源路径；不启动 MySQL、后端、浏览器与真实 Redis，这些由实际端到端真跑覆盖。
