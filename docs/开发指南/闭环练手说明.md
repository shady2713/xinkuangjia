# 闭环练手说明

## 摘要

本页是一次闭环练手的记录：工程师提出限定在文档内的任务，DSH 在工作区完成改动，再由文档检查证明新增页面和入站链接可用，链路在会话完成时收尾。练手对象是 xinkuangjia 仓库，基线为默认分支 `main`，改动只涉及 `docs/` 下的 Markdown。

<a id="练手范围"></a>

## 练手范围

| 项目 | 内容 |
| --- | --- |
| 仓库 | xinkuangjia |
| 基线分支 | `main`，练手分支从 `main` 创建 |
| 允许改动 | `docs/` 下的 Markdown 页面及其相对链接 |
| 禁止改动 | Java、Vue 业务代码，依赖与构建配置，数据库脚本，`.obsidian` |

本页是练手产物，不含会话内容、个人信息或密钥。文中命令只用于复核，不构成启动中间件、导入数据库、提交或推送的授权。

<a id="闭环节点"></a>

## 闭环节点

「工程师 → DSH → session-complete」指三个可核对的节点，缺一项都不算闭环：

- 工程师：给出任务、允许范围和禁止事项。
- DSH：在工作区产生实际文件改动，而不是只在会话里描述改动。
- 会话完成：任务结束时记录结果，之后可凭仓库现状复核。

对应证据分别是任务描述、Git 工作区差异和文档检查输出。仅有描述没有文件，或文件存在但链接指向不存在目标，都不满足验收。

<a id="验收方式"></a>

## 验收方式

下列命令从仓库根执行，只读检查，不改写文件：

```powershell
python -B -X utf8 scripts/docs/verify_md_links.py docs/开发指南/闭环练手说明.md
python -B -X utf8 scripts/docs/verify_md_links.py docs/开发指南
python -B -X utf8 scripts/docs/verify_doc_structure.py docs/开发指南
```

结果以真实退出码为准；空范围、缺少解析器或跳过都不能作为通过证据。
