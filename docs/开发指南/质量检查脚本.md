# 质量检查脚本

## 摘要

仓库质量脚本检查 Markdown、技能、源码注释和暂存凭据。日常检查读取工作区；提交检查读取索引中的内容，两者证明的版本不同。所有工具保留真实失败状态，缺依赖、解析失败、空范围或跳过均不能作为验收通过证据。

## 准备环境

根目录工具需要 Python 3.10+；技能与前端 YAML 解析需要 PyYAML 6.0.3，工具测试需要 pytest。可在已有隔离环境中安装，不要求为执行检查改动仓库配置。

```powershell
python --version
python -m pip install PyYAML==6.0.3 pytest
```

Web 注释、Mermaid 和前端源码审计还需要 Node.js、pnpm 和管理前端锁文件对应的依赖。前端声明 Node.js >=20.19.0，使用 `packageManager` 固定的 pnpm 10.28.2；从前端根执行：

```powershell
pnpm install --frozen-lockfile
# 使用 --ignore-scripts 安装或从其他目录复制过工具缓存时执行
pnpm -r --if-present run stub
```

检查入口不自行安装依赖。Git 增量检查要求仓库和有效基线；没有 Git 基线时，文档检查仍可运行，Web 可用 `--all` 检查选定文件，不能将不存在的差异当作全量检查成功。

## 日常调用

以下命令从仓库根执行。先查清单，再按范围运行；`--list` 不执行任何检查。

```powershell
python -B -X utf8 scripts/workflow/run_checks.py --list
python -B -X utf8 scripts/workflow/run_checks.py --group docs --json
python -B -X utf8 scripts/workflow/run_checks.py --group comments
python -B -X utf8 scripts/workflow/run_checks.py --checks md-links doc-refs skills
python -B -X utf8 scripts/docs/verify_md_links.py docs/开发指南 docs/测试与可靠性
python -B -X utf8 scripts/workflow/change_scope.py --base HEAD
```

`change_scope.py` 必须提供 `--base`，`--head` 默认 HEAD。它分别报告已提交、暂存、未暂存和未跟踪路径，不自动挑选或执行测试。`--base HEAD` 的已提交范围为空；比较分支须提供实际基线引用，无法求得唯一共同祖先时失败。

## 工作区与暂存

Java、Python 工作区入口复制真实索引到临时目录，再将当前改动加入临时索引并调用暂存核心检查器；真实索引保持不变。Web 默认按相对 HEAD 的已暂存、未暂存和未跟踪变化检查当前声明；`--staged` 仅读取暂存 blob。

```powershell
python -B -X utf8 scripts/code/check_worktree_comments.py
python -B -X utf8 scripts/code/web/check_worktree_web_comments.py
python -B -X utf8 scripts/code/web/check_worktree_web_comments.py --all 前端代码/basic-framework-admin/apps/web-ele/src
python -B -X utf8 scripts/workflow/check_staged_quality.py --list
python -B -X utf8 scripts/workflow/check_staged_quality.py
```

暂存检查选择对应文档、源码、技能和被删除目标的引用方，构造私有临时视图；检查结果仅代表暂存版本。内容在检查后又被修改时重跑受影响检查。命令不授权暂存、提交或推送；也不能用旧暂存、空索引和零对象证明工作区已检查。

Java、Python 工作区包装器共用[私有快照实现](../../scripts/common/worktree_snapshot.py)，索引和新增 Git 对象都写入临时目录，保留真实暂存区、对象库及部分暂存状态。支持尚无 HEAD 的新仓库；仅暂存而未改动工作区的文件也纳入检查。没有适用文件时明确报告未验证，不把它当作源码已检查。

## 检查项目与范围

规则以当前[文档配置](../../scripts/tools/document_rules.py)和各入口实现为准。下表用于判断工具能证明什么，不把文本扫描包装成语义分析。

| 检查名 | 检查内容 | 关键限制 |
| --- | --- | --- |
| `md-links` | 相对链接、图片、引用定义、标题及 HTML 锚点 | 不联网验证 HTTP URL，不检查反引号里的普通路径 |
| `doc-refs` | 源码中的具体 .md 引用、Markdown 行内代码中的完整仓库路径 | 文本扫描无法理解任意动态拼接；不检查锚点 |
| `skills` | SKILL.md 元数据、目录与 name、一致调用提示和 YAML 重复键 | 不证明技能规则的业务事实或外部 URL 正确 |
| `package-readmes` | 包类别、元数据、必需章节、可点击目录及限制 | 只覆盖当前配置登记的包规则 |
| `doc-structure` | details/summary 配对、开发者章节折叠等 | 语义完整性和内容正确性仍需人工核对 |
| `doc-policy` | 当前配置中的禁用引用和名称规则 | 配置为空的字段不形成拦截能力 |
| `mermaid` | 提取真实 Markdown 围栏并调用 Mermaid 解析器 | 只检查语法，不渲染图片或验证图中架构事实 |
| `java-comments` / `python-comments` / `web-comments` | 相应语言的改动声明与必需注释 | 不能证明职责、参数、异常和副作用的语义准确 |
| `note-classification` / `note-format` | 项目自行建立的活动记录分类与结构 | 框架不携带维护历史；仅在业务项目使用记录功能时检查相应对象 |

源码里的 docs 路径相对于最近的 pnpm-workspace.yaml；没有该标记时使用仓库根。目标必须在所属根内存在，不回退到其他工程的同名文档。测试样例字符串的特定豁免由检查器决定，测试注释和 Docstring 仍受约束。

## 前端工作区依赖

在管理前端执行 `pnpm quality:workspace`，检查包发现、内部 `workspace:` 协议、catalog 版本和归属。修改包清单后同步锁文件，按已经声明的版本安装；通过约束检查不证明运行时依赖分类或实际导入正确。

```powershell
pnpm quality:workspace
pnpm quality:workspace:test
```

源码导入、分层和配置读取另跑[开发审计](前端开发检查与构建工具.md#源码审计)。未使用依赖的候选由 `pnpm check:dep` 报告，不自动删除仍有消费者的依赖来制造通过。

## 中文注释与解析

每个方法必须有准确中文职责注释；公共 API 和复杂方法说明参数、返回、真实异常及副作用，关键分支说明原因与边界结果。完整规则查项目 [Java 技能](../../.agents/skills/weetion-development-java-standards/SKILL.md)和 [Web 技能](../../.agents/skills/weetion-development-web-standards/SKILL.md)。

管理前端执行 `pnpm quality:comments`；全量审计用 `pnpm quality:comments:all`。增量模式只保护改动触及的声明，不能证明全库历史注释合格。历史 Git blob 无法严格 UTF-8 解码时，Web 检查扩大为当前文件全量；当前文件必须有效 UTF-8，Git、解析与依赖失败不能被忽略。Node 桥接只读取受控源码，不执行被检查代码。

Java 范围由[仓库布局](../../scripts/common/repository_layout.py)确定为 `后端代码/basic-framework-boot/`。修正目录范围不会把普通提交自动改成全部历史声明检查；需要全量调查时应使用独立完整快照。

## 暂存区密钥扫描

`python -B -X utf8 scripts/security/scan_staged_secrets.py` 检查暂存新增内容。固定凭据、私钥和认证值按规则阻断；部分字段只提示人工复核，计量元数据避免误报。输出不得回显凭据。密钥扫描未加入 run_checks，需要通过暂存入口或独立命令运行。

SQL `INSERT ... VALUES` 按显式列名或同文件 `CREATE TABLE` 的列顺序识别敏感字段；敏感表的位置 INSERT 缺少列映射时阻断。该实现不执行 SQL，也不宣称完整理解复杂 ALTER 或 INSERT SELECT。后端实际目录下的 `.env` 同样属于敏感配置范围；BCrypt 摘要、登录票据及初始化密码不能因为编码形态而自动放行。

本地真实 `.env` 不应被暂存。删除凭据文本不等于撤销泄露凭据；若发现真实泄露，按授权处理对应系统和凭据生命周期，检查器不负责轮换。

## Git 提交钩子

`check_staged_quality.py` 是可接入 pre-commit 的提交前入口；本框架文档不承诺用户仓库已经安装钩子。接入前核对实际仓库配置和调用脚本，手工验证正常、目标违规与中断路径，不能仅凭配置文件存在宣称执行过。

暂存检查会选择密钥、相应语言注释、变更文档、被删除目标的入站引用，以及清单变化影响的 README 等检查。它不运行 Maven、完整前端测试或部署验收；提交成功不能替代这些验证。

## 文档规则配置

集中规则位于 [document_rules.py](../../scripts/tools/document_rules.py)，由解析器读取明确常量，不执行该规则文件中的任意逻辑。包类别、README 必需章节、开发者标题和禁用引用按这份配置维护；不能在各检查器中添加互不一致的列表。

中央规则、桥接或扫描范围变化时，同时运行相关 pytest、前端 Node 工具测试及实际消费者 CLI，覆盖原范围和扩大的范围。不能只按源码存在某个字符串判定门禁有效，也不能排除文件、降低阈值或跳过失败掩盖问题。

## 结果和失败处理

调度器保留每项状态和输出；前置检查失败时依赖项显示跳过。最外层的退出 0 还需要非零有效对象、对应版本和正确范围才能支持完成结论。

| 退出状态 | 含义与处理 |
| --- | --- |
| 0 | 所选有效范围未发现规则问题；仍需核对对象数量 |
| 1 | 规则违规，或调度链因前置失败未完整执行；修复相关问题并复跑 |
| 2 | 无效输入、缺依赖、解析器、超时等环境错误；检查未完成 |
| 130 | 用户中断；本次无通过结论 |

保留准确命令、版本、检查对象、数量、状态和未运行项；无关存量问题单独报告，业务断言失败、缺环境和工具失败分别处理。编译、首页 200、空扫描、跳过和测试通过不能相互替代。
