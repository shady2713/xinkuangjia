# 前端开发检查与构建工具

## 摘要

管理前端提供依赖、分层、配置入口审计、模块图、构建记录及清理预览。工具只处理当前前端，源码审计不替代类型、测试和构建；生成模块图、构建记录及显式清理会写入文件。覆盖率与静态交付另见[前端测试与交付工具](前端测试与交付工具.md)。

## 环境与入口

所有 pnpm 命令在 [管理前端根](../../前端代码/basic-framework-admin/)运行。需要 PATH 中的 Python 3.10+、PyYAML 6.0.3，以及锁文件对应的 Node/pnpm 依赖。首次安装与 stub 恢复见[质量检查环境](质量检查脚本.md#准备环境)，工具不会自动安装依赖。

规则由前端 [development_rules.py](../../前端代码/basic-framework-admin/scripts/tools/development_rules.py)维护，源码解析复用当前 ESLint 配置包的 TS/Vue 解析器。工作区协议和 catalog 校验先运行 `pnpm quality:workspace`。

## 源码审计

可以选择单类检查，或一次扫描执行三类规则。退出 0 表示所覆盖范围无 findings，1 表示规则问题，2 表示配置、解析或环境错误；诊断 JSON 带相对路径、行号与规则名。

```powershell
pnpm quality:dependencies
pnpm quality:layers
pnpm quality:config
pnpm quality:development
```

| 命令 | 覆盖内容与判据 |
| --- | --- |
| `quality:dependencies` | 工作区包 src 中静态导入、重导出、类型导入、字符串动态导入和 require；跨包相对导入核对所属包依赖声明 |
| `quality:layers` | core、base、基础包不得向上依赖；应用可以使用自己的 `#/` 别名，共享包不得依赖应用；补充字符串动态导入和跨包相对导入 |
| `quality:config` | `VITE_GLOB_API_URL` 读取集中于 `packages/effects/hooks/src/use-app-config.ts`；检查其他直接读取和非空字面量 baseURL、apiKey、authToken、clientSecret，不输出实际值 |
| `quality:development` | 合并以上三类审计；不会修改源码 |

依赖检查接受包自身四类依赖声明，不将根包开发依赖当作每个子包的声明，也不证明生产/开发分类合理。变量动态导入作为 dynamicImports 提示，不能因零 findings 就推断所有运行时路径安全。Vue 只解析 script/script setup 并保留原行号；配置规则排除声明文件和测试。

`quality:source-scan` 是生产安全相关源码扫描，并非上述三类审计的别名；它已经进入 `quality:verify`，`quality:development` 仍是独立入口。未使用依赖另由 `pnpm check:dep` 分析，结果需追踪实际消费者后处理。

## 模块依赖图

工具根据当前 pnpm-workspace.yaml 和包清单生成[模块依赖关系图](../../前端代码/basic-framework-admin/docs/开发指南/模块依赖关系图.md)。根包、无边包和运行/开发/可选/宿主依赖均保留，输出顺序稳定。

```powershell
# 只读核对；缺失或过期退出 1
pnpm graph:modules:check
# 修改包关系后，重新生成并审阅差异
pnpm graph:modules
```

不要手工编辑生成结果；目标不是本工具生成文档时拒绝覆盖。图表示清单关系，不表示运行时调用、加载顺序或完整框架架构。

## 构建记录

交付前需要把来源与产物关联时，从 build:recorded 完整流程进入。它先记录提交、工作区状态、应用版本、源码与锁文件摘要，调用真实生产构建，成功后记录产物摘要。

```powershell
pnpm build:recorded
pnpm build:record:verify
```

记录位于前端 `.cache/build-record`，只对应 `apps/web-ele/dist`。构建失败不会完成记录；构建期间源码变化或重新 prepare 会使旧记录失效。verify 核对当前来源、上下文和产物，不一致退出 2。不要手工调用 finish 为旧 dist 补记，也不要在构建期间编辑本前端文件。

记录不采集环境变量、远端地址或配置值，不是签名或发布凭证；不覆盖镜像、压缩包和 Java 制品。普通 `pnpm build:ele` 不自动产生这份来源记录。

## 清理产物

默认命令只规划并显示完整 targets 与 planId，不删除文件。范围仅为已发现工作区包根的 dist、dist.zip 和 .turbo，不递归按名称删除源码同名目录，也不删除锁文件。

```powershell
pnpm clean:artifacts
```

核对输出中的绝对目标与恢复方式，停止构建和其他写入进程。获得对应删除授权后，使用该次完整 planId：`pnpm clean:artifacts --execute <planId>`。执行前会重算计划，路径、大小或时间变化使计划失效；受版本控制的文件、越界目标、符号链接和 Windows junction 会使规划失败，不能跳过拒绝继续删除。

`--dependencies` 可以把包根 node_modules 纳入计划，但 pnpm 内部常有链接，通常会被拒绝，不建议把它作为 pnpm 重装工具。旧 `pnpm clean` 和 `pnpm reinstall` 具有自己的删除行为，不享有此入口的默认预览承诺。

规划和删除不是文件系统事务，中途失败可能已删部分产物。内部工具 dist 清理后可运行 `pnpm -r --if-present run stub` 恢复入口，再重新构建；这是构建产物恢复，不是源码恢复。

## 验证与限制

修改这些工具、解析模块或规则时，在私有临时目录验证正常、失败与边界，再运行实际当前工程的只读消费方。

```powershell
pnpm quality:development:test
pnpm quality:workspace:test
pnpm quality:workspace
pnpm quality:development
pnpm graph:modules:check
```

源码审计不是完整 TypeScript 模块解析或数据流分析：不覆盖 Vue 模板自动导入、CSS 依赖、计算端点、别名传播及任意自定义 Vite 别名。分层规则在 Python 与 ESLint 中均有消费者，变更一方必须核对另一方。构建记录、模块图和工具测试均不能证明页面、权限或后端业务已通过。
