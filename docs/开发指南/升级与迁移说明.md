# 框架升级与迁移说明

## 摘要

本页记录合并到 main 后会影响业务项目源码、接口契约或运维行为的框架变更。当前需要处理的是 #26「全量质量审查，删除无用代码并修复排序与权限」：删除未被框架引用的公开类型，把 `SortablePageParam` 并入 `PageParam.sortingFields`，并收紧角色精简列表、用户导入模板、公开文件下载和锁屏状态。该变更不删除 URL、权限码、配置键或数据库 schema；业务项目按本页完成源码迁移、权限核对和回归即可，不需要执行新的数据库迁移 SQL。

## 升级步骤

1. 从 main 建立升级分支并保留可回退版本；确认本次升级不改数据库结构和配置键。
2. 升级框架代码后，在业务仓库搜索已删除符号：

   ```bash
   rg -n 'SortablePageParam|DateIntervalEnum|DataSourceEnum|QueryWrapperX|JsonConvert|MoneyConvert|AreaConvert|CollectionTypeHandlerUtils|IntegerListTypeHandler|LongListTypeHandler|LongSetTypeHandler|StringListTypeHandler|InputUpload'
   ```

   命中项按[受影响的公开类型](#受影响的公开类型)和[分页排序迁移](#分页排序迁移)替换；`LambdaQueryWrapperX` 是保留类型，不要误删。
3. 在业务后端执行编译和测试；有自定义 Mapper 时重点检查分页、联表分页和 `sortingFields` 透传。
4. 在业务前端执行类型检查和测试；直接引用已删上传/操作日志组件的页面先替换组件或改为页面接入。
5. 核对角色下拉消费方、用户导入模板授权、公开文件 URL 行为和锁屏刷新行为，见[安全收紧](#安全收紧)。
6. 按[验证与回退](#验证与回退)跑业务自己的门禁，再进入发布流程。

框架构建入口见 [Java 后端 README](../../后端代码/basic-framework-boot/README.md)与[管理前端 README](../../前端代码/basic-framework-admin/README.md)；服务器部署见[部署说明](../部署/部署说明.md)。

## 受影响的公开类型

#26 删除的类型在框架内已无引用；业务项目若直接 import 或按旧方法签名调用，需要按下表修改。

| 已删除类型或文件 | 迁移方式 |
| --- | --- |
| `DateIntervalEnum` | 字典 `date_interval` 仍在 SQL 中，但不再有 Java 消费方。业务需要日期区间常量时在业务模块定义自己的常量或枚举，不要依赖框架类型。 |
| `DataSourceEnum` | 数据源 key 仍是 `master` / `slave`；使用字符串字面量或业务自己的枚举。`application.yaml` 原本就使用字面量。 |
| `JsonConvert`、`MoneyConvert`、`AreaConvert` | 删除 `@ExcelProperty(converter = ...)` 引用，改用基础类型、格式化注解或业务自己的 `Converter`；`DictConvert` 保留。excel Starter 不再 optional 依赖 `starter-biz-ip`，`AreaUtils`、`IPUtils`、`AreaController` 仍保留。 |
| `QueryWrapperX` | 改用 `LambdaQueryWrapperX`（方法引用列）或 MyBatis-Plus `QueryWrapper`；框架 Mapper 统一使用 `LambdaQueryWrapperX`。 |
| `IntegerListTypeHandler`、`LongListTypeHandler`、`LongSetTypeHandler`、`StringListTypeHandler`、`CollectionTypeHandlerUtils` | 集合字段改用 `JacksonTypeHandler` 和 `@TableField(typeHandler = JacksonTypeHandler.class)`，按 JSON 文本持久化；不要继续注册已删除的 TypeHandler。 |
| `SortablePageParam` | 参数类型改为 `PageParam`，排序放在 `PageParam.sortingFields`；JSON 字段名仍是 `sortingFields`，客户端通常无需改。`BaseMapperX` 上只接受 `SortablePageParam` 的 `selectPage` / `selectJoinPage` 重载已删除。 |
| 前端 `InputUpload` 与 `input-upload.vue` | `components/upload/index.ts` 不再导出 `InputUpload`；使用保留的 `FileUpload`、`ImageUpload` 或业务自己的上传组件。 |
| 前端 `components/operate-log` | 该目录及 `operate-log.vue`、`typing.ts` 已删除；操作日志页面仍为 `views/system/operatelog`，需要复用时从页面或 API 层接入。 |

## 分页排序迁移

排序字段统一由 `PageParam` 承载，类型为 `List<SortingField>`。`SortingField` 保持原结构：

```json
{
  "pageNo": 1,
  "pageSize": 10,
  "sortingFields": [
    { "field": "createTime", "order": "desc" }
  ]
}
```

迁移方式：

- 原来继承 `SortablePageParam` 的请求对象改为继承 `PageParam`；原字段名 `sortingFields` 不变，已有客户端请求体无需改写。
- 调 `BaseMapperX.selectPage(pageParam, queryWrapper)` 时，框架会自动读取 `pageParam.getSortingFields()` 并追加排序；`selectJoinPage(pageParam, ...)` 同样处理。
- 如需从请求对象外单独传入排序，仍可使用保留的 `selectPage(pageParam, sortingFields, queryWrapper)` 三参重载。
- `sortingFields` 为空或为 `null` 时行为与升级前一致，不追加排序；字段名转换为下划线列名。
- 字段名只允许字母、数字和下划线（最多 64 个字符），方向只允许 `asc` / `desc`；非法值在参数校验或排序校验阶段拒绝，不会拼接任意 SQL。

升级前的典型写法：

```java
public class UserPageReqVO extends SortablePageParam {
}
```

升级后：

```java
public class UserPageReqVO extends PageParam {
}
```

## 安全收紧

#26 同时收紧以下行为。它们改变的是响应字段、权限要求或边界处理，不是新增可选开关；升级后应纳入业务回归。

- **角色精简列表**：`GET /admin-api/system/role/simple-list` 与 `GET /admin-api/system/role/list-all-simple` 改为返回 `RoleSimpleRespVO`，只包含 `id`、`name`、`status`，不再返回 `dataScope`、`dataScopeDeptIds`。依赖这两个字段的业务前端或脚本应改用带权限的角色详情/分页接口。URL 和权限码未变；下拉仍可按 `status` 禁用停用角色。
- **用户导入模板**：`GET /admin-api/system/user/get-import-template` 现在要求 `system:user:import` 权限，与用户导入接口一致。依赖模板下载的角色需要在业务项目中授予该权限；这是收紧，不是放宽。
- **公开文件下载**：`GET /admin-api/infra/file/content/**` 在解码后校验对象路径，包含父目录、绝对路径或控制字符时直接返回 404，不再访问对象存储。匿名读取契约未变，但以前可能被读取的异常路径现在会被拒绝。
- **锁屏状态**：管理前端的锁屏标记和锁屏口令不再写入本地存储，刷新页面会解除锁屏。业务若要求刷新后仍保持锁屏，应设计服务端或受控的安全存储，不能把登录口令或锁屏口令落盘复用。

以下契约保持不变，排查时不要误改：URL、权限码、配置键和数据库 schema 未删除；`MYBATIS_ENCRYPT_PASSWORD` 仍映射到保留的 `EncryptTypeHandler`。

## 验证与回退

升级后至少执行：

```bash
# 业务后端
mvn -B -ntp -Pquality-gate verify

# 业务前端
CI=true pnpm install --frozen-lockfile
TZ=Asia/Shanghai pnpm test:unit
pnpm check:type
pnpm build:ele
```

回归重点：

1. 带 `sortingFields` 的分页请求按预期列排序，空排序保持原顺序，非法字段名被拒绝。
2. 角色下拉只读取 `id` / `name` / `status`，原有页面没有因缺少数据权限字段报错。
3. 有导入权限的账号能下载用户导入模板，无该权限的账号被拒绝。
4. 文件 URL 正常读取，包含 `..`、绝对路径或控制字符的 URL 返回 404。
5. 锁屏页面刷新后按新的内存行为处理，业务没有依赖跨刷新保持锁屏。

本次变更不涉及数据库迁移或配置键调整；回退时恢复上一版框架代码和业务侧对应改动即可。若升级期间给角色补过 `system:user:import` 权限，该数据变更按业务权限管理流程保留或回收。
