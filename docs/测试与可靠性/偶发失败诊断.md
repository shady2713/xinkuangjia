# 偶发失败诊断

## 摘要

本页用于排查本地或 CI 中已经出现的概率性测试失败，从可比的失败证据定位资源冲突、生命周期、共享状态或环境问题。按证据选择复现范围，不默认运行所有并发层次，也不以一次重跑成功认定问题解决。编写测试的隔离与同步方法见[测试可靠性](测试可靠性.md)；启动服务、访问真实外部系统或重跑远程作业遵循任务授权。

<a id="evidence"></a>

## 固定可比较的证据

保留失败版本、用例与命令、运行环境、时间、退出状态和首个有意义的失败特征，区分测试输出、进程管理消息和基础设施错误。比较通过与失败时优先使用同一提交、依赖和配置；版本不同先核对相关变化。

CI 场景按实际日志与元数据确认作业是否重叠、共享宿主或资源命名空间；本地失败不要求查询 CI。一次重跑成功不证明基础设施故障，一次超时也不证明产品竞争缺陷。

<a id="causes"></a>

## 按证据区分原因

下表是调查方向，不是仅凭症状就能确定的分类。多个原因可能同时存在，分别记录依据及相互影响。

| 候选原因 | 需要寻找的证据 |
| --- | --- |
| 宿主资源冲突 | 独立进程或作业同时占用相同端口、路径、数据库或外部命名空间 |
| 生命周期未结束 | 清理返回后仍有进程、线程、后台任务、回调或状态写入 |
| 共享状态污染 | 结果随测试顺序变化，且关联环境变量、工作目录、时钟或全局替身 |
| 同步依赖负载 | 固定休眠或偶然调度顺序被当作就绪与完成条件 |
| 平台或入口差异 | 问题随操作系统、文件系统、信号、源码或构建入口变化 |
| 产品并发缺陷 | 测试已隔离自身资源，受控重叠仍能破坏产品不变量 |
| 外部服务瞬时失败 | 外部边界的响应、服务状态或网络证据支持判断 |
| 运行器基础设施故障 | 检出、依赖获取、磁盘、宿主进程或运行器存在直接故障证据 |

同一运行器池的无关分支出现类似失败，只能提示共享环境异常，不能直接证明资源争用。超时、信号、退出码和断言分别记录；证据不足时保留候选解释。

<a id="reproduction"></a>

## 选择复现范围

从失败用例或所属文件开始，依据怀疑的共享边界，逐步选择单进程、并发用例或线程、多个独立测试进程，以及实际并发配置下的工程或作业。某一层已经复现同一失败特征时，先定位责任边界；只有怀疑更高层共享资源时才扩大。

保持与失败相关的依赖、配置、平台和启动入口，每次实验尽量只改变一个假设。不要降低产品超时或引入随机负载来制造另一种失败。竞争问题使用[同步条件](测试可靠性.md#synchronization)控制重叠；资源冲突观察同时占用，或用[原子资源分配](测试可靠性.md#resources)作对照。

当前环境不能复现目标平台时，保留可行的证据分析和限制；其他环境通过不消除原失败。

<a id="resolution"></a>

## 修复与结束条件

获准修复后，修改实际负责资源分配、就绪通知、共享状态、超时或清理的组件。修复验证沿同一失败特征和相关执行方式进行，方法见[验证目标回归](测试可靠性.md#regression)。重试包装、快照归一化或弱化断言不能代替根因修复。

调查结论区分已观察事实与候选解释，说明责任边界的证据、是否复现、环境限制，以及修复后的回归和资源恢复证据。只诊断不要求同时交付修复；已有证据足够时停止扩大范围，证据不足则明确缺少的事实，不通过重复运行直到偶然成功结束调查。
