# basic-framework 测试策略

## 摘要

测试要证明受影响的行为、边界与失败后状态。basic-framework 的既有测试分别属于 Maven 模块、前端组件/工具和生产登录页；质量脚本保护可机械检查的规则。模块测试、构建、静态资源冒烟与真实中间件联调各有边界，不能相互代替。

## 测试体系与工作目录

先从当前配置确认入口，不把目录中遗留测试、旧报告或空模块当作已执行范围。下表列出框架的当前设施；命令总索引见[脚本使用索引](../开发指南/脚本使用索引.md)。

| 工程与工作目录 | 测试入口 | 已有覆盖与边界 |
| --- | --- | --- |
| [Java 工程](../../后端代码/basic-framework-boot/) | 各模块 src/test/java；`mvn test` | 缓存工具、加密、异常脱敏、XSS、配置绑定和 IP 工具；不是完整 system/infra 业务套件 |
| [管理前端](../../前端代码/basic-framework-admin/) | `pnpm test:unit` | 共享工具、Store、组件、表单与部分应用数据；伪 DOM 不验证真实浏览器布局和接口装配 |
| 管理前端应用 | `pnpm test:e2e` | 生产登录页能打开，密码不预填；不代表认证成功或角色/菜单权限通过 |
| 管理前端应用（业务链路） | 仓库根 `python -B -X utf8 scripts/e2e/run_business_e2e.py` | 随机隔离库、种子管理员、真实后端与构建产物上的字典类型 CRUD 与重名拒绝；缺少连接变量、后端或浏览器时失败 |
| 仓库根 | `python -B -X utf8 -m pytest scripts/tests` | 文档、范围、解析桥接、暂存隔离和质量规则的工具行为 |
| 管理前端 | `quality:*:test`、`quality:test` | 前端开发与交付工具本身；不替代页面业务验收 |

## Java 模块与配置

从 Java 工程根运行目标模块及依赖测试。修改公共 core 或装配边界后，再运行聚合测试和质量 profile；不要在正在写入同一 target 的 Maven 进程间并发执行。

```powershell
# Web 公共组件及所需依赖
mvn -pl basic-framework-core/basic-framework-spring-boot-starter-web -am test
# 本地 YAML 环境绑定及服务依赖
mvn -pl basic-framework-server -am test
# 实际 reactor 聚合测试
mvn test
# 单元测试、JaCoCo 与 PMD
mvn -Pquality-gate verify
```

结果位于各实际模块 `target/surefire-reports`；核对 XML 中 tests、failures、errors、skipped。Java 编译目标由父 POM 的 `java.version=17` 管理，运行时和 Maven 环境先查 [Java README](../../后端代码/basic-framework-boot/README.md)。`-DskipTests` 打包和启动不能算测试通过。

| 修改边界 | 必需验证 |
| --- | --- |
| Controller、VO 与响应 | 参数校验、权限拒绝、字段转换、错误码及敏感字段裁剪 |
| Service | 业务状态、重复操作、事务失败后的数据、并发覆盖和外部调用失败 |
| Mapper、SQL、数据权限 | 真实映射、条件、分页、逻辑删除、唯一约束和越权读写；Mock Mapper 无法证明 SQL 正确 |
| Redis、Job、外部 Client | 缓存失效、重复执行、超时、重试边界和资源释放 |
| 配置绑定与启动 | 显式环境变量、默认值/缺失失败和实际 profile 装配；绑定测试不是启动联调 |

当前 server 配置测试读取真实 YAML，并隔离宿主环境；包含数据源/Redis、从库回退、管理站点地址和 MinIO 协议变量缺失的绑定失败。它不建立 MySQL、Redis、MinIO 连接，不能证明这些服务可用。

`quality-audit` 与 `quality-gate` 都在测试前重置当前模块的覆盖数据并绑定源码输入，随后生成 JaCoCo 与 PMD 报告；没有测试的模块也报告未执行的实现。audit 允许输出明确的覆盖缺口，不能作为交付通过；quality-gate 对每个纳管手写生产文件要求 LINE 和 METHOD 全部覆盖，不能用平均值抵消某个文件的缺口。

[覆盖率检查器](../../scripts/workflow/coverage_gate.py)独立枚举生产源码，缺失文件、旧输入、空报告和无依据的零计数均阻断。接口、注解和可核实的 Lombok 纯声明单列不适用；MapStruct 只有生成路径、处理器来源和受管 Mapper 均可核实才作为生成物另列。声明与生成成员不伪装为已测试，源码目录也不能仅因来自第三方就整包排除。最终检查必须覆盖完整 reactor，局部 `-pl` 结果只证明该范围，覆盖达到 100% 仍须有业务边界、并发与故障验证。

## 前端组件与生产入口

先跑改动相关单测，再核对类型和生产资源。下列命令均在管理前端根执行。

```powershell
# 现有应用组件示例，替换为本次改动对应测试文件
pnpm test:unit apps/web-ele/src/components/table-action/table-action.test.ts
pnpm check:type
pnpm quality:comments
pnpm quality:workspace
pnpm test:unit
pnpm build:ele
pnpm quality:prod-scan
pnpm test:e2e
```

`test:unit` 使用 Vitest run 与伪 DOM，当前配置在 [vitest.config.ts](../../前端代码/basic-framework-admin/vitest.config.ts)。影响表单时至少验证创建/编辑区别、取消、不合法输入、提交失败时状态和重复提交；影响 Store/路由时验证缓存、切换身份与重新登录后的权限更新，不能仅断言实现内部的同名字段。

生产 E2E 的 [配置](../../前端代码/basic-framework-admin/apps/web-ele/playwright.config.ts)自动启动预览于 `http://127.0.0.1:4173/admin/`，`reuseExistingServer=false`。执行前必须先有当前生产 dist、空闲 4173 端口和已安装的 Playwright Chromium。浏览器缺失时使用当前前端 `pnpm exec playwright install chromium` 准备环境；缺环境、启动失败和用例失败分别报告，不连接陈旧预览冒充当前版本。

[既有用例](../../前端代码/basic-framework-admin/apps/web-ele/e2e/production-security.spec.ts)检查首页响应、管理平台标题和空密码框。增加业务场景时应通过真实操作与外部可观察结果断言，不据该用例宣称登录、权限、上传或系统 CRUD 已完成。代理隔离、覆盖率与 ZIP 校验见[前端测试与交付工具](../开发指南/前端测试与交付工具.md)。

业务链路的浏览器证据由[浏览器业务端到端](../开发指南/脚本使用索引.md#浏览器业务端到端)提供：入口真实建库、写入种子管理员、启动后端与构建产物预览，再用 Playwright 完成登录、菜单进入、新建、列表可见、编辑与删除，并覆盖重名新建被拒的失败路径。它只覆盖当前登记的规格；其他业务页面、上传与数据权限仍需各自补充浏览器用例。

## 真实中间件与权限联调

改变持久化、权限或外部服务时，用专用测试库、缓存命名空间和测试桶建立隔离环境。依赖参数按 [Java README](../../后端代码/basic-framework-boot/README.md)配置，目标环境按[部署说明](../部署/部署说明.md)验证；框架不规定个人机器的中间件安装方式。不把开发者正在使用的业务数据当作可销毁夹具，不输出凭据或完整令牌。

| 场景 | 需要独立观察的结果 |
| --- | --- |
| 认证与刷新 | 合法登录和无效凭据、过期令牌、退出后令牌失效；检查实际错误码，避免只看 HTTP 200 |
| 角色与菜单 | 无权限用户拒绝直接接口访问；前端隐藏按钮不能代替后端权限；变更授权后刷新/重登录行为符合契约 |
| 数据权限 | 当前身份可见的数据范围、不可见数据的读取/写入拒绝，分页总数不泄漏越权记录 |
| 用户、部门与字典 | 创建/更新/删除后的真实数据库状态、引用约束、禁用和空值；失败不能留下部分关联 |
| 文件上传 | 当前 MinIO 上传、元数据写入、可读 URL 与删除/失败补偿；静态首页或桶存活不代表上传链路通过 |
| Job、短信及外部调用 | handler 存在且参数正确、失败/重复执行行为；真实短信另核对成本和授权，不从测试运行推导发送许可 |
| 目标部署 | `/admin/` 资源与客户端路由、`/admin-api/` 转发、缓存/跨域和实际配置；开发代理通过不证明 Nginx 正确 |

文件服务已有隔离 MySQL 与 MinIO 测试入口，所需参数和运行命令见[文件上传验证](../部署/文件上传协议.md#隔离验证)。认证集成使用专用 MySQL/Redis、真实事务和 Mapper，不能用纯 Mock 替代会话撤销竞争。

上表的字典类型创建、更新与删除已由浏览器业务端到端在真实隔离库上覆盖：删除用例断言记录不再出现在分页列表，重名新建被拒作为关键失败路径单独断言。认证刷新、数据范围、文件上传、Job 与短信仍按各自入口单独验证，不从一次业务用例推导其他场景通过。

Mock 用于控制明确外部边界，不替代真实数据库映射、Spring 安全链和对象存储协议。既有套件未提供上述完整自动验收，应由新增业务的测试与受控联调覆盖，不生成虚假的全链路通过结论。

## 按变更选择回归

以下表格按影响选择，不要求为普通文案变更运行所有业务测试。没有适用用例时补充能因目标缺陷失败的验证，而不是仅增加镜像实现的断言。

| 变更 | 最小有效范围 | 扩大条件 |
| --- | --- | --- |
| Java 局部行为 | 目标模块与相关消费者测试、增量注释 | 公共 core、接口或事务变化加聚合与联调 |
| 页面/组件 | 目标 Vitest、类型、注释 | 路由、登录、生产资源变化加构建和浏览器 |
| 依赖清单/导入方向 | 工作区约束、对应源码审计、类型 | 运行时包或公共组件变化加构建与消费者测试 |
| SQL/认证/授权 | 目标测试与真实隔离数据库/身份验证 | 跨表与事务、权限范围变化加完整受影响业务路径 |
| YAML/环境/代理 | 配置边界、实际装配、目标服务启动 | 改变部署入口加生产资源与真实 API |
| Markdown/Skill | 链接、路径、结构、元数据与事实核对 | 跨文档规则或入口变化加真实消费者 |
| 检查器/中央规则 | 相关工具测试、合法输入和目标反例 | 扫描范围变化运行扩大的实际范围 |

## 检查器与中央规则

修改检查器、公共解析、钩子、阈值或扫描范围时，同时测试规则自身和实际消费方。根工具使用 pytest，前端 Python 工具使用 package.json 中 unittest 入口，Web/Mermaid 使用 Node 工具测试；具体入口见[脚本自身测试](../开发指南/脚本使用索引.md#脚本自身的测试)。

合法场景应通过，受控反例须因目标原因失败；源码含某字符串不是有效负对照。未暂存版本检查工作区，已暂存版本检查索引，不能用旧内容、空暂存和零对象支持交付。不得跳过失败、改预期迎合结果、降低阈值或增加忽略项制造通过。

<a id="结果与限制"></a>

## 数据、结果与完成判据

用例独立创建和回收自有资源，准确区分未提供、null、空集合、零和 false；时间、随机值及身份关联只按契约归一化。并发、子进程和平台差异见[测试可靠性](测试可靠性.md)，概率失败按[偶发失败诊断](偶发失败诊断.md)调查，不能重复直到偶然变绿。

报告准确版本、环境、命令、有效对象/用例数量、失败与跳过、实际副作用和未覆盖事项。行为、构建、覆盖率、浏览器和性能结果分别陈述；编译、HTTP 首页 200、空扫描和列表发现用例都不能替代测试通过。功能与性能分工见[通用测试原则](通用测试原则.md)。
