## 确认的问题

### P1：凭据扫描器的误报修正引入漏报

位置：`scripts/security/scan_staged_secrets.py` 第 1232–1235 行、`:1295–1301`，辅助函数 `:1077–1103`。

多字段 SQL/JSON 文本中，辅助函数识别到后续敏感赋值会返回真，调用方随即返回空发现；因此多一个敏感字段反而使整条字面量豁免。另有仅凭变量名、字符串包含描述词或运行时表达式形状放行的问题，影响带非空固定 fallback 的环境变量表达式等情况。

本轮用隔离 Git 仓库和人工构造的非真实凭据做实际 CLI 对照：相同 3 个文件在旧版扫描器产生 5 项 sensitive-assignment 并退出 1；当前版退出 0、报告未发现疑似凭据。635 项工具测试通过没有覆盖住这些反例。

修复要求：保留引号和语法语义，逐字段检查；同时检查动态表达式的固定回退分支。不得根据“INVALID”、变量名或普通描述词直接相信值安全。新增真实 staged CLI 正反例，保留合法占位符和引用表达式的放行能力。

### P1：E2E 在尚未取得资源时也会清空 Redis

位置：`scripts/e2e/run_business_e2e.py` 第 947 行、`:953–956`、`:873–875`，默认 Redis 库在 `:895`，正常启动的清空在 `:971`。

资源登记发生在端口等前置检查之前。即使端口已经占用、服务尚未启动，finally 仍调用 cleanup，对登记的 Redis 库执行 FLUSHDB。只禁止库 0 不能证明默认库 5 归本次运行独占；并发运行时后启动的失败进程可能清掉先启动进程的数据。

本轮用替身记录副作用：强制端口检查失败，未启动任何服务，仍记录到 `flush_redis_database(..., 5)` 调用；未向真实 Redis 发命令。

修复要求：使用实际独占实例或可证明所有权的隔离方案；只有本次成功取得的资源才可回收。覆盖预检失败、启动失败、并发运行、异常退出、保留资源等路径；预置的外部数据不得受影响。

### P2：稳定 Form 引用使旧异步操作穿过重新挂载

位置：`前端代码/basic-framework-admin/packages/@core/ui-kit/form-ui/src/form-api.ts` 第 316 行、`:553–557`、`:645`、`:696–698`。

mount 改成 Object.assign，修复了消费方持有稳定 form 引用的问题；但异步失效检查仍只比较对象引用及 isMounted。旧 validate/submit 等待期间发生 unmount→mount 后，对象引用仍相同，检查放行旧结果。本轮针对当前 FormApi 与实际 StateHandler 的受控复现中，旧提交执行了旧业务回调并写回旧提交值。真实消费方包含共享 API 的条件挂载及锁屏表单；resetForm 不等于取消所有在途 Promise。

修复要求：保留公共引用稳定性，同时给每次挂载建立代次标识，在等待前捕获，并在每个异步回调/等待后校验。新增延迟验证、延迟提交跨卸载重挂的判别测试，同时保留锁屏真实交互回归。
