### 第二步：修复高优先级缺陷

先重现，再修复并用同一判别用例证明修复有效：

- **扫描器漏报**：`scripts/security/scan_staged_secrets.py` 第 1232–1235,1295–1301 行。多敏感字段的 SQL/JSON 字符串不能因命中后续字段而放行；敏感固定值不能因变量名或“password”等描述词而豁免；环境表达式的非空固定 fallback 和含运算符形状的普通字符串仍要检查。使用合成、非真实凭据做隔离 Git 暂存和真实 CLI 正反例，兼顾合法占位符/变量引用。
- **E2E 清理所有权**：`scripts/e2e/run_business_e2e.py` 第 947,873–875 行。预检失败、第二个并发进程失败时不得 FLUSHDB 清除外部数据。使用可证明独占的资源，只清理本次成功获得的对象；覆盖预检、构建、启动、用例失败、中断和保留资源。修复 Windows 的 os.getpgid/os.killpg 问题，保证已启动子进程精确回收且其他清理不被一个失败中断。
- **Form 异步跨挂载**：`packages/@core/ui-kit/form-ui/src/form-api.ts` 第 316,553–557,645,696–698 行。保持公共 form 引用稳定，同时校验挂载代次；旧验证/提交在卸载重挂后不得执行旧业务回调、滚动新表单或覆盖新提交值。用延迟 Promise 及真实消费场景验证，保留锁屏回归。
