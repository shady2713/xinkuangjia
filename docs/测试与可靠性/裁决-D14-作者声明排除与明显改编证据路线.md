## A1 的确切判据与记录字段

采纳 A1，记为独立的 `E1-author-only` 分支，归属路线 2。本裁决直接确定下列条件，实施方只能落实为版本化契约；不得自行扩大可忽略范围。它允许短文件采用完整内容一致路线，不取消 D12 对通用结构、R5/R6 全等或相似率判派生的禁止。

### 确切判据

只有以下条件全部满足，才可认定该分支成立：

1. 固定双方完整原始输入：本地基线版本、原始字节 SHA-256；上游仓库、完整提交 SHA、文件路径、原始字节 SHA-256。已知多源逐一保留，不以文件名或一个作者行选择来源。
2. 在原始输入上逐项标识作者声明范围。可排除对应注释中的独立 `@author` 行，以及同处紧随、经解析和语义复核确认只延续作者身份或角色的声明行。不是只要“紧随”就能排除：职责、参数、业务约束、本地修改、版权、许可证、普通说明和其他块标签均不得排除；混合作者与其他事实的一行不能整行忽略。源代码或字符串中的 `@author` 不能被识别为作者声明。
3. 每个排除范围必须绑定实际文件、注释块和声明对象，保存原文。上游没有对应作者行时明确记录为空及理由，不伪造一对一对应；多作者、多行作者均完整登记。两个文件都无作者差异时采用原 E1，不借此分支删除其他内容。
4. 仅排除上述声明后，按 D10 §0.3 **原列的 R1–R4** 比较全部剩余内容，结果须逐行完全一致，剩余实质内容非空。不能使用 R5/R6、删除 package/import、去普通注释、裁剪文件、字符串替换或相似率容差补成一致。额外类名前缀映射等变换不能默认为既有 R2，须另有明确批准及逐项记录。
5. 完整原始 diff 中每一处差异都能解释为获准的 R1–R4 变换或已登记的纯作者声明；任何剩余差异都使本分支不成立。该项仍可按其他合法路线另行核实，不能把 A1 失败误写成必然原创或必然无来源。
6. 检查现有本地创建、共同贡献、其他来源及历史作者记录。出现无法解释的反证时，该项继续“未核实或冲突”。通过 A1 只提供内容关系证据，作者处理仍按 D10/D12 的各自条件作出。

请求 A1 中“不得用于作者未声明以外的场景”不采纳为字面限制：它与上游明确声明作者的最小复现相冲突。准确限制是“只用于双方差异仅包含作者声明及获准 R1–R4 变换的场景”。上游有作者时依 D10 保留或恢复**证据支持且适用于该内容的作者**；上游确无作者时，完整满足 D12 后才可采用来源说明。不得把有作者的上游放入“未声明作者”例外。

在原有唯一来源账本中扩展 schema，保留既有字段组和旧值；不得建立另一个可写批准名单。字段名可按既有 schema 映射，以下信息不可缺少。

| 字段组 | 必需内容 |
| --- | --- |
| 对象与版本 | `local_path`、范围、基线提交、比较时本地原始指纹、候选最终原始指纹；上游仓库 URL、提交、路径、固定文件 URL、取得时间及原始指纹；public 类型、嵌套类型及注释绑定 |
| 比较契约 | 规则/schema 版本、`evidence_route=路线2`、分支 `E1-author-only`、R1–R4 的精确映射表与执行顺序、工具版本及指纹；完整原始输入或受控可重取地址、完整 diff 及其指纹 |
| 排除记录 | `excluded_author_declarations[]`：双方文件及输入指纹、原始行区间、逐字原文、所属注释/类型、声明种类、对应关系；续行为什么仅含作者声明，缺对应行时的明确空值和理由 |
| 一致结果 | 双方剩余规范化内容指纹、行数、逐行全等结果、剩余差异为零；每处原始差异的归因，不能只写“R1–R6 后一致” |

| 复核及验收 | 实施者、复核者、日期、逐项结论、所用最终输入指纹；对照输入和输出位置、实际命令、规则版本、扫描数、诊断与退出码；原判断、迁移原因及本裁决引用 |

格式整改可能新增来源说明或修改作者行，导致最终文件与上游不再符合 A1 的比较形状。此时保留**整改前比较输入**及其指纹，并用完整整改 diff 绑定最终文件；不得为了重新得到一致而把新来源说明也加入 A1 排除列表。最终类型行号、JavaDoc 指纹和文件指纹必须重新生成。

## 合入前置条件与负对照

负对照是 A1 规则合入、启用该分支及据此验收署名整改的前置条件。本轮的比较探针说明判据可区分作者与其他差异，不能代替将来规则和真实消费者的测试。B1 同样须证明不会因两个通用内容串或重复证据而自动通过。

| 对照输入 | 必须观察到的结果 |
| --- | --- |
| `OAuth2ClientConstants` 的原始双输入，只差作者及合法包名映射 | A1 内容比较成立；仍分别检查作者适用性及历史缺口 |
| 作者移除后仍有一个常量、控制流、字段、职责或普通注释差异 | A1 不成立；没有其他充分路线的受控反例不得判派生 |
| 作者声明后紧随职责、许可证、版权、参数或其他说明；或一行混合作者与业务事实 | 不得整行排除；比较器应保留差异或明确拒绝无法安全识别的声明 |
| 字符串、行注释或代码中出现 `@author` | 不得被当作可排除的声明 |
| 真实多作者、HTML 作者、明确的纯作者续行、上游无作者 | 识别与完整记录正确，不丢作者，不补造对应行；无作者例外另受 D12 约束 |
| 仅有 R5/R6 全等、模板结构或高相似率，R1–R4 加作者排除后仍不同 | A1 拒绝，不能将候选相似当完整内容一致 |
| 篡改输入字节仍沿用旧指纹，或排除行号/原文不符 | 拒绝版本绑定或排除记录，不可只检查状态值 |
| B1 两个通用校验串、同一字段的注释和注解重复描述、同一句拆为两点 | 不满足 B1；行距足够或 df 很低也不能通过 |
| B1 真实不同的非通用业务事实，双方最终片段可定位且反证已解释 | 合格语义复核可批准该路线；机械消费者只认绑定版本的逐项结论 |

对反例应保持其余输入有效，并在需要验证判定能力时同步实际输入指纹，防止只因“旧指纹不符”失败而掩盖比较逻辑误放行。记录比较器的 A1/B1 判断及真实消费者的目标诊断；反例如果另有充分路线，只能证明 A1 不成立，不能要求整个派生判定拒绝。

实施后须运行规则测试、真实工作区或隔离暂存消费者，以及全量入口，覆盖纯注释变更、嵌套类型、只改清单/快照及最终输入变化；保存实际扫描数、完整诊断、退出码与指纹。测试工具退出 0 表示测试符合预期，反例消费者应因目标原因退出非零。零对象、跳过、旧规则结果或仅比较助手结果均不满足前置条件。

## B1 的裁决与逐项处置

有条件批准“两个独立且有区分力的内容对应点可单独构成路线 3”。D10 **原裁决**已列非通用业务内容与独特注释，要求至少两个独立有区分力的对应点，并未强制跨种类配对；D10 **取证证据 §0.5** 又将它收窄成合取式。此次明确增加内容独立路线，消除两者歧义；不将旧工具的数量判断追认成已经满足原合取式。

### 内容点的确切门槛

新增分支记为 `C2-independent-content`，与原 E2 分开表达。E2 原义是至少两个稀有区分性字面量，P2 注释点并不自动属于它。实施文本应表达为“原有充分路线，或 C2”，并分别记录命中分支，不能直接改成无条件 `E2=true` 即通过。

合格 C2 须同时具备：

1. 两个点来自同一固定上游文件的对应内容；多源分别证明，不能各取一个弱点凑数。双方完整原文、上下文、所绑定输入及具体行号均可取得。
2. 每个点分别体现非通用的业务事实或独特表达，例如特定数据关系、错误码与条件的组合、专门业务约束或有具体理由的注释。同类名、方法名、标准协议串、通用 CRUD、惯用校验、自动生成描述和常见示例值不计为有区分力。
3. 两个点有不同的证据依据，不是同一字段/行为的注释与注解复述，不是一个句子的不同截段、同一模板的替换槽、同一理由的重复出现，也不能把一个组合内部互相依赖的字符串分开计数。P1/P2 类型不同本身不能证明独立。
4. 逐项说明为何在不依赖点一的匹配或描述时，点二仍提供另一项非通用事实的对应，反之亦然。双方片段不重叠及行距可辅助去重，不能取代这项说明。这里要求证据依据独立，不要求证明概率意义上的统计独立。
5. 原 P1/P2 的长度、频率等条件可以沿用作候选筛选；记录语料提交、范围、指纹、计数口径及频率。`df≤30` 或只在一个上游文件中出现，均不足以证明该内容不会独立产生或来自通用惯例。
6. 解释完整文件的重要差异和可靠反证，落实 D12 的逐类型映射、署名撤回理由及最终版本复核。只摘两条字符串、不看完整上下文不得批准。

每项补充 `content_points[]` 的原文、片段指纹、双方路径/输入指纹/行号、所属类型及字段或行为、点种类、候选频率及语料绑定、`discrimination_reason`，并记录 `independence_reason`、反证及差异解释、最终路线、复核者和逐项结论。整改前与最终版本行号须明确区分；当前索引的旧行号不能直接当成最终位置。

现有记录的 `AuthLoginReqVO` 只有“登录账号不能为空”和“密码不能为空”，不能仅凭 df=1/11 与分隔行数获得 C2 批准。`XssCleaner` 的“对 html 文本中的有 Xss 风险的数据进行清理”与“清理有 Xss 风险的文本”是同一职责的复述，不能作为两个独立事实。`DataSourceEnum` 的主/从库注解推荐语也须核对是否只是标准用法的成对模板。上述是现有点不足以证明通过的具体例子，不是对这些文件最终来源的否定；可另补合格内容或其他路线。

### 49 项及其他候选的处置

## 独立复核与关闭条件

需要独立复核最终结果，但**不要求在已有独立复核者之外，再增加第二位独立复核者**。D12 复核字段的原文是“独立复核或针对该项争议的裁决”，并没有规定必须两名独立复核者。“第二名”应区分是实施者之外的复核参与者，还是第二名独立审查者。

`d10review` 已提供实施者之外的独立核对，本裁决承认其实际覆盖的版本、对象和结果，不因旧字段仍写“无独立复核者”就否定已经发生的复核；也不将其工具缺陷或未覆盖范围算作通过。修复后的最终版本可继续由该独立复核者验证；若其参与了相关条目的证据选择、实现或改判，则对应条目需要另一个独立负责方，或有完整具体材料的逐项争议裁决。机械辅助重跑不等于完整逐项语义复核。

本 D14 只裁判规则和有限样例，不能填写成 136 项或整个 431 项通用的 `independent_review=通过`。复核记录至少绑定负责方、独立性、日期、范围、规则和输入版本、逐项判断、失败与未覆盖项；旧字段须保留历史事实并关联新增记录，而非覆盖成笼统通过。
