# 测试可靠性

## 摘要

编写或评审涉及并发、共享状态、时钟、子进程和资源清理的测试时，按问题查阅本页。目标是让测试在实际运行方式下保持隔离，并用可观察的条件证明就绪、操作重叠与清理完成。纯业务计算测试不必加载本页；已有概率性失败使用[偶发失败诊断](偶发失败诊断.md)，测试层级与命令按项目[测试策略](测试策略.md)选择。

<a id="concurrency"></a>

## 确定竞争范围

从目标测试、启动命令和框架配置确认实际并发层次：同一套件内的用例、不同线程或工作进程、独立测试命令，以及共享宿主的作业。配置不能排除重叠时，共享资源按可能并发使用处理；不要求每次测试都核查无关的 CI 层次。

进程隔离不会隔离宿主端口、固定路径、数据库、缓存和后代进程。对活动资源明确所有者、分配方式、就绪条件与结束信号；必须共享时，互斥或隔离范围须覆盖真实竞争方。单文件串行不能保护其他进程，不因一个设施冲突就默认串行化整个套件。

<a id="resources"></a>

## 分配独立资源

由资源所有者原子分配，避免先检查可用、稍后才占用的竞争窗口。

- 网络测试绑定环回地址，在绑定时由系统分配端口，再读取监听地址；支持时使用端口 0。不要先寻找空闲端口、关闭占位监听器，再交给被测服务绑定。
- 用框架或运行时临时目录设施创建私有目录；要求路径原先不存在时使用排他创建，不能仅先检查。
- 数据库、缓存、容器、会话及输出位置采用测试独有的命名空间。固定资源确属被测契约时，用覆盖真实竞争范围的隔离或互斥。
- 仅作解析输入或预期值的固定 URL、路径和标识不是活动资源，不必改写。录制标识需要稳定时，由测试设施映射到实际分配的资源。

<a id="shared-state"></a>

## 恢复共享状态

环境变量、工作目录、模拟时钟、时区、模块替身、注册表、日志钩子和全局网络拦截可能影响其他用例。先确认作用于进程、线程还是实例，优先采用实例局部替身或依赖注入。

必须修改共享状态时，记录原值及原先是否存在，修改后立即登记恢复；异常、初始化失败和取消路径也要覆盖。局部清理可能尚未生效就失败时，使用框架级兜底。恢复操作不解决同时读写的竞争：会被并发用例观察时，采用必要范围的互斥或独立进程；拦截范围限制在当前测试负责的调用。

<a id="synchronization"></a>

## 同步条件与超时预算

等待就绪事件、握手、明确状态或可归属的异步结果。固定休眠不能证明工作已完成；轮询须有明确条件和截止时间，不能仅靠延长等待让断言通过。

竞争测试用事件、屏障或可控异步结果安排争议位置，并证明操作确实重叠。除非顺序属于被测契约，不断言调度器的偶然顺序。模拟时钟须覆盖组件实际使用的时间来源并在结束后恢复；真实调度边界仍需相应集成证据。

核对用例、初始化、清理、子进程及运行器的超时和优先级，不假定命令行预算一定覆盖局部设置。测试产品超时时，外层等待要留出调度与清理余量；只调整有证据不足的预算，不统一放大所有超时。

<a id="cleanup"></a>

## 确认清理完成

获取资源后立即登记清理，按依赖关系停止新工作、处理在途工作、恢复共享状态并关闭自有资源。观察完成信号，不能把停止请求已被接受当作资源已经结束。

子进程要回收，服务器要确认关闭，后台任务和线程要确认退出。迟到回调可能污染后续用例时，验证关闭后不再写入共享状态；取消不得被清理逻辑转换成成功。

清理等待须有边界。到期仍未结束时保留原始失败和剩余资源信息；一个资源清理失败时，尽可能继续清理其他独立资源，并保留再次清理所需信息，不把未完成报告为成功。

<a id="platform"></a>

## 平台差异

仅针对项目声明支持的平台建立断言，按实际运行时确认环境变量、文件系统、权限和进程信号语义。

- 文件时间戳写回可能损失精度；需要比较往返结果时，先读取已写入的基准值，操作后再按契约比较，不能把最终结果直接当作预期。
- Windows 环境变量名的大小写语义与 POSIX 不同，多个大小写名称可能对应同一条目，恢复时避免相互覆盖。
- 删除或重命名受句柄占用影响时，先确认所有者关闭资源；只有可恢复争用有证据时才有限重试。
- 确实不支持的信号、权限或链接场景，按项目策略跳过并说明覆盖缺口；另一平台通过不能代替失败平台的验证。

<a id="regression"></a>

## 验证目标回归

验证应证明原问题及相关隔离条件，按风险选择下列证据，不把整张表变成每次必跑的清单。

| 变更 | 需要证明 |
| --- | --- |
| 共享状态 | 正常、失败和取消后准确恢复 |
| 生命周期与子进程 | 资源实际结束，迟到结果不污染后续测试 |
| 端口、路径或命名空间 | 在真实相关的并发层次仍隔离；跨进程问题用独立进程验证 |
| 竞争修复 | 操作确实重叠，目标不变量成立 |
| 检查器或规则 | 合法场景通过，受控反例因目标原因失败 |

可行时在隔离环境验证修复前状态或受控反例，再验证修复后的行为，不破坏用户工作区。重复运行和压力测试只能补充证据，不能替代确定性回归；观察真实状态或资源释放，不只依赖组件的成功报告。主动终止子进程时区分超时、信号与普通退出码。

偶尔重跑通过、全局串行化、增加固定休眠或盲目放宽超时均不能证明根因消失。明确的预算配置错误、可恢复争用或外部瞬时失败，可按其证据和项目策略局部调整，保留首次失败及验证缺口；具体调查见[偶发失败诊断](偶发失败诊断.md)。
