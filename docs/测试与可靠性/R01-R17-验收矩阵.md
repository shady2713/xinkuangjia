**判定：测量口径问题（非测试写法问题）**，已校准且未破坏报告完整性。

### 根因（地面真值证据）
包装内置 v8 provider 打印转换入参后确认：`apps/web-ele/src/layouts/basic.vue` 的 V8 原始数据里
**存在** `setup`、`_sfc_render` 真实函数区间，但转换后 `fnMap`/`branchMap` 为空、60 条语句计数
全部停在默认值 1。机制是 `v8-to-istanbul` 的 `offsetToOriginalRelative` 要求区间两端都能回查
源码映射，而 `<script setup>` 的 `setup(...) {` 包装行由编译器生成、映射中没有对应段，端点解析
失败即丢弃整个区间与分支；语句却来自 `_statementsToIstanbul` 的行对象默认值 1。

**排除"测试只 import 未渲染"**：`qrcode-login.test.ts` 真实 `mount` 该 SFC 并断言渲染产物，
校准前 `fnMap` 依旧为 0；159 个被引用且含 `mount(` 的 SFC 中 81 个为 0 函数。

### 措施
新增 `vitest.coverage-provider.mjs`：包装内置 v8 provider，只把"落在无映射行"的区间端点对齐到
**区间内**最近的映射列（起点向后取首列、终点向前取末列），**不改命中数、区间层级与块顺序**；
`getProvider` 找不到 `v8ToIstanbul` 直接抛 `TypeError`（升级失效显式失败，不静默退回假通过）。

**被证据否决的替代方案**：`@vitest/coverage-istanbul` 3.2.4 虽恢复函数分母，但导致
**215 个文件从报告消失**（`source-missing-from-report` × 215、`invalid-evidence`），已完整回退。
