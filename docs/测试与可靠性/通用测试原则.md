# 通用测试原则

<a id="summary"></a>

## 摘要

<a id="layers"></a>

## 验证层次与证据边界

先从目标项目规则和配置确认测试入口，再按变更影响选择覆盖层次。不存在可直接套用所有项目的命令、运行时版本或覆盖率数字。

| 层次 | 主要用途 | 不能单独证明 |
| --- | --- | --- |
| 单元与契约测试 | 边界、错误、状态迁移、事件顺序和竞态 | 真实装配、外部依赖和交付入口可用 |
| 集成与入口测试 | 模块协作、启动、配置和实际协议 | 未接入的真实外部服务行为 |
| 端到端验证 | 用户动作到外部可观察结果 | 未覆盖负载与环境下的所有行为 |
| 快照或预期结果 | 稳定输出和协议的可评审差异 | 输出正确的完整因果关系 |
| 性能基准 | 特定负载下的开销和资源约束 | 功能语义正确或所有环境都更快 |

覆盖率说明哪些代码被执行过，不能代替结果断言。遵守项目已有门槛，不通过排除受影响文件、跳过用例或降低阈值让检查变绿。

<a id="quality-gates"></a>

## 质量门禁与执行证据

把可机械检查的约束落实到目标项目实际使用的检查入口，并确认违规时能产生明确的失败结果。门禁配置本身也需要评审，尤其是检查范围、排除项、阈值和跳过条件的变化；不能仅凭配置存在就认为它已执行或覆盖本次变更。新增或调整工具仍遵循任务授权，不为迁入原则自动建设整套门禁。

类型检查、静态分析、单元测试、覆盖率和交付入口验证各有边界。例如测试运行器执行成功未必意味着类型检查通过，覆盖率达标也不能证明断言有效。具体工具和阈值由项目配置决定，不套用其他项目的语言选项、按文件 100% 覆盖率或运行时矩阵。

分别核对本地钩子、手动命令和 CI 的实际执行集合、对应版本与结果。钩子可以只负责低成本检查，其成功不能替代项目规定的完整验证；CI 也必须核对实际触发、筛选和覆盖范围。未配置、未运行、跳过、失败或未知都应明确报告，不把没有结果当作通过。

自动门禁不能证明需求理解、接口契约和设计取舍正确，仍需语义评审。

<a id="real-entry"></a>

## 真实实现与交付入口

保留被验证路径上的真实实现，仅在高成本或不确定的边界使用受控替身，并明确其覆盖限制。纯手工装配测试不能证明真实加载器、配置、插件注册或启动流程有效；影响这些边界时补充实际入口验证。

按产品交付方式选择源码、构建产物、容器或部署入口。测试中的源码解析和正式运行解析各有用途，不能混入陈旧产物后仍假设同一套模块实例。子进程的解释器、依赖、参数和解析方式沿用项目设施，不默认继承开发加载器。

回归测试应能因目标缺陷而失败；在需要证明其敏感性时，使用隔离的原始版本或受控负对照。测试通过数量不能替代有效断言。

<a id="observations"></a>

## 从外部观察结果

优先重新读取文件、查询持久状态或独立观察实际输出，不只信任被测程序自报成功。涉及文件变更时，同时检查应当改变的内容和不应改变的内容。

断言正常路径，也覆盖失败位置及后果：重试是否重复产生副作用、取消是否仍发布结果、部分失败是否留下错误状态。稳定字段可精确比较，随机值与时间只在约定边界归一化，不消除业务身份和关联关系。

预期输出的更新必须审阅差异，自动化验证不能悄悄改写预期来迎合当前结果。涉及持久化兼容性时保留项目要求的历史格式样本与迁移覆盖，不因生成新样本而覆盖仍受支持的旧证据。

<a id="resources"></a>

## 资源隔离与真实服务

进程隔离并不隔离端口、文件路径、外部命名空间或后代进程。每个测试拥有自己的资源，失败、重试和超时后也要清理；共享辅助模块与测试入口分开，防止导入测试入口导致重复注册或重复外部调用。

涉及并发、共享状态、时钟、子进程与异步清理的测试，按问题查阅[测试可靠性](测试可靠性.md)；已有概率性失败按[偶发失败诊断](偶发失败诊断.md)定位。只在单独运行时通过的用例应调查其隔离与生命周期，不直接归咎于运行器。

真实外部服务验证需要可用环境、凭据和对应操作授权。成本、网络访问、数据发送及副作用按项目和任务约束处理，不能从原项目的成本判断推导许可。缺少条件时报告未运行或跳过；无密钥测试通过不等于真实服务验证通过。

<a id="performance"></a>

## 性能与功能验证的分工

性能测试沿用[性能基准与回归门禁](../性能优化/性能基准与回归门禁.md)的负载、时间、资源及校准口径。功能测试负责行为语义，基准负责达到真实完成点与衡量开销；二者互补，不在基准内复制整套语义测试。

验证报告列出准确版本、环境、实际执行入口、结果和缺口。编译通过、局部测试通过、外部链路通过及性能门禁通过分别陈述，不能相互替代。
