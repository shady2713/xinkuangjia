## 批准理由与适用边界

来源路径的语义是定位固定版本的完整文件，物理换行只是表达方式。只要段序、全部字符、来源绑定与证据核验保持一致，换行不会改变该断言；逐字节全等比较可阻止截断、替换和省略。相反，提高全局行长会扩大所有注释的容许范围，不能只解决路径表达问题。

D12 的四个字段继续各自承担原职责：固定来源、完整上游路径、历史依据和实际本地修改。来源说明仍位于对应 public 类型的职责 JavaDoc 正文、全部块标签之前，职责说明仍独立保留。多来源分别成块，续行仅绑定紧邻的那个来源；嵌套类型仍需各自映射。

索引必须从 D12 的唯一证据清单派生，不能另外建立可手工放行的名单。拼接匹配只证明声明与索引一致，不证明来源真实；上游快照、本地最终字节、固定提交、无作者结论、内容证据及逐项复核继续按 D12 检查。未核实或冲突项不能因本次格式批准获得例外。

## 固定语法与段数上限

本裁决直接确定语法和上限，由实施方落实到所有解析消费者及测试；不得自行改成无限续行。“总段数 ≤3”包括首行，不是允许三条续行。

```text
来源：<仓库标识> @ <完整40位小写SHA>（该版本未声明作者）
上游文件：<段1>
上游文件续：<段2，可选>
上游文件续：<段3，可选，仅在段2存在时>
来源依据：<D12允许且与证据一致的固定取值>
本地修改：<与实际差异一致的说明>
```

尖括号内容仅用于说明语法，不能原样用于验收。具体约束如下。

1. 每个来源块恰有一个 `上游文件：` 首行，载荷非空；续行不得替代首行，也不得借无效首行重新构造路径。每条续行载荷非空，不接受只有空白的段。
2. 续行前缀固定为全角冒号的 `上游文件续：`，紧随首行或上一条续行。中间不得插入空行、其他字段、块标签或另一个来源；孤立、错位及超过两条的续行一律拒绝。
3. 路径按原字符序列切分，优先在 `/` 后换行，斜杠归前段；必要时可在完整 Unicode 字符边界切分。不得自动补 `/`、空格、换行、反斜杠或连字符。不得使用省略号、占位符或转义表达来替代原路径字符。
4. 解析仅移除 JavaDoc 外框、行首缩进、装饰星号及其约定分隔空格，再移除字段前缀。**不得对路径载荷或索引值执行 `strip`、空白折叠、大小写转换、URL 解码、Unicode 规范化或路径归一化。** 前缀后的空白属于载荷，不得作为排版空白自动删除；无效空白应明确拒绝，不能先裁剪再比较。
5. 设各段为 `s1…sn`，必须满足 `(s1 + … + sn).encode("utf-8") == upstream_path.encode("utf-8")`。右侧是受控索引字段解码后的原始字符串值，不是 JSON 文本中引号或转义符的序列；必须先确认它与权威清单字段原值一致。即使规范化后指向同一文件，只要字节不同也拒绝。拼接结果仍接受 D12 的相对路径、目录穿越及来源绑定检查。
6. 每个物理注释行按 PMD 实际过滤后的 UTF-16 长度不得超过 120，前缀也计入：`上游文件：` 占 5，`上游文件续：` 占 6。整个 JavaDoc 仍须满足 PMD 的 30 行限制，不能把该限制解释为每个来源块各有 30 行。

无续行时兼容原四行格式；一条、两条续行时分别为五行、六行。当前最长路径行为 152，使用两段已足够；第三段提供有界余量，不能据此删除职责或证据信息。未来超过三段或整块超过 30 行的对象继续阻断并另行裁决，不自动扩大上限。

## 合入前置条件

必须针对最终实现执行正负对照，并使用实际工作区、暂存及全量入口核验 D12 的消费链。成功输入实际检查目标类型并退出 0；失败输入须因预期问题退出非零，不能以不相关失败、零对象或测试运行器自身退出 0 证明拒绝有效。

| 输入或变更 | 必须观察到的结果 |
| --- | --- |
| 同一合法完整证据的一段、两段、三段路径 | 均通过且拼接字节一致；首行加三条续行，即四段，必须拒绝 |
| 删除任一段、截掉一个字符、遗漏或重复 `/`、添加省略号、替换字符、调换不同段顺序 | 因路径与清单不一致或非法载荷拒绝；不能自动修复后放行 |
| 缺少首行、首行前缀错误、首段为空但续行能构成有效路径 | 因来源块语法错误拒绝，不能只验证最后拼接结果 |
| 空续行、孤立续行、续行跨来源或位于依据/修改行之后、中间插入空行或标签 | 因位置或内容错误拒绝 |
| 在段边界插入空格、制表符，或篡改索引字段首尾空白 | 未经裁剪的值与原值不同，必须拒绝；不能靠 `strip` 获得全等 |
| 合法换行后仍使用旧本地源码指纹，或仅篡改嵌套类型来源 | 按 D12 因最终字节或类型映射不符拒绝；规范化指纹不能替代原始指纹 |
| 只改来源 JavaDoc，不改声明；暂存和工作区内容不同；只改证据索引 | 对应入口仍检查受影响类型，准确区分版本并拒绝失配 |
| 同文件的合法路径续行与 130 字符自然语言、其他超长注释并存 | 仅路径长行消失，自然语言及其他违规继续由 `CommentSize` 报出 |
| PMD 过滤后行长 120/121，注释长度 30/31 | 120、30 不因尺寸失败；121、31 分别因行长、行数失败，且没有处理错误 |

保留 D12 原有负对照，包括无清单、上游实际有作者、证据不足、多来源漏列、真实作者兼容等，不用上述新增用例取代它们。保存最终候选、规则和证据输入指纹、命令、检查对象数、目标诊断、退出码及报告错误数；更新来源注释的物理换行后，必须重新绑定本地最终原始字节指纹，保留旧证据记录。

当前工作区的 [解析器](../../scripts/code/java/check_staged_java_comments.py)已经包含续行实现，但尚不符合本裁决：第 1024–1046 行没有总段数上限，对首段和续段使用 `strip`，且首行匹配失败后仍可由续行组成有效路径。本轮直接调用 `_parse_source_notes`，确认四段路径、错误首行前缀加合法续行、载荷前导空格三类输入均返回来源对象且无解析错误。这是解析层结果，尚未证明完整门禁最终放行；它足以证明不能认定现有解析契约及负对照已通过。

**在修正上述问题并完成真实消费者对照之前，现有实现不得以本裁决为依据合入或验收。** 本轮按用户限定只记录这些事实，不修改实现。

## 剩余违规与替代方案

方案 A 解决的是路径的表达冲突，不单独解决全部 194 条基线违规。仅处理 80 条路径长行时，105 条本地修改长行及 9 条悬空 JavaDoc 不会因此获得豁免；不能承诺门禁已经可绿，也不能笼统断言“没有其他违规消失”而不做差分验证。

`本地修改：` 继续维持一个必需字段和一行表达。实施时应依据真实差异写不超过 120 的准确摘要，把完整差异及支撑事实保留在同一权威清单与证据材料中；不得改成虚假的“无。”、空泛的“已适配”，或删掉重要行为变化来凑行长。本裁决不批准新增 `本地修改续：`。确有无法准确压缩的对象应登记阻断并单独提出证据，不自动套用路径续行。

9 条 `DanglingJavadoc` 须沿实际声明、注释和消费者定位后处理，不能假定路径换行会修复它们。最终 PMD 差分须解释每条违规为何消失，确保其余应检问题没有被抑制或漏扫。

| 方案 | 裁定 |
| --- | --- |
| A：格式侧续行 | 按本文语法及前置条件批准；与准确摘要及悬空注释修复分别验收 |
| B：维持四行并永久红 | 不接受为完成或发布方案。A 未满足验收时暂时保持阻断，不能把暂时阻断写成永久可接受状态 |
| C：把全局行长放宽到 ≥335 | 否决；会使本应检出的 130 字符自然语言行通过，削弱原判据 |
| 用 XPath、正则或文件排除绕开来源注释 | 不批准；本次没有逐行精准且保留其他违规的合格证据，错误报告的零违规更不能作为通过依据 |
| 新增自定义 Java 规则 | 本轮不采用；格式侧已能保留完整定位信息，无须为此增加构建和规则维护范围 |

本裁决已经批准 A，所以不触发“不批准”的分支。若实施方不能满足前置条件，执行的是暂时阻断和继续修正 A；不得自行切换 C 或扩大抑制范围。若后续决定必须维持 D12 单行路径，则在另有同等证据与检测能力的方案获批前只能保持阻断，不能宣布完成。
