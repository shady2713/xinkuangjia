# 用户功能图

## 摘要

本页把管理前端的关键用户路径登记到唯一的「关键路径」表，并链接到覆盖它们的 Playwright e2e 规格。功能图与 `apps/web-ele/e2e/*.spec.ts` 必须双向一致：表中每个规格文件都要存在且至少包含一条用例，每个规格文件也必须登记在表中。发生漂移时[功能图对齐测试](../../scripts/tests/test_feature_map.py)失败，而不是依靠人工核对。运行前提、测试数据和执行命令见 [e2e 说明](../../前端代码/basic-framework-admin/apps/web-ele/e2e/README.md)。

## 关键路径与 e2e 对齐

下表是功能图的机器可读部分，固定使用「用户路径」「规格文件」「断言要点」三列。规格文件列必须是仓库相对路径，并包在行内代码中；对齐测试按此格式逐行解析，不接受改用散文描述。断言要点概括规格中实际校验的可观察结果，具体步骤以源码为准。

| 用户路径 | 规格文件 | 断言要点 |
| --- | --- | --- |
| 登录成功：管理员使用正确账号密码进入概览页 | `前端代码/basic-framework-admin/apps/web-ele/e2e/login.spec.ts` | 登录接口返回 `code=0`；页面跳转到 `#/dashboard`；管理菜单和管理员身份可见 |
| 登录失败：错误密码停留登录页并提示失败 | `前端代码/basic-framework-admin/apps/web-ele/e2e/login.spec.ts` | 登录接口返回非 0 错误码；地址保持 `#/auth/login`；显示「登录失败，账号密码不正确」 |
| 权限拒绝：受限账号无菜单且直达路由与接口被拒绝 | `前端代码/basic-framework-admin/apps/web-ele/e2e/permission.spec.ts` | 系统管理与用户管理菜单均不可见；直达 `#/system/user` 落到未找到页；用户分页接口返回 `code=403` |
| 权限放行：管理员进入用户管理并使用导入入口 | `前端代码/basic-framework-admin/apps/web-ele/e2e/permission.spec.ts` | 用户列表可见；带权限的「导入」按钮可见 |
| 文件上传下载：上传图片后下载内容与上传字节一致 | `前端代码/basic-framework-admin/apps/web-ele/e2e/file-upload-download.spec.ts` | 上传提示成功且列表出现同名记录；记录显示图片类型；下载响应为 200 且字节比对为 0 |
| 用户导入后可检索：上传 Excel 并查询导入账号 | `前端代码/basic-framework-admin/apps/web-ele/e2e/user-import.spec.ts` | 导入提示匹配「新增 N 个，更新 N 个」；按账号搜索后列表出现导入用户和姓名 |
| production 登录页不预填开发账号 | `前端代码/basic-framework-admin/apps/web-ele/e2e/production-security.spec.ts` | 首页响应成功；标题包含「管理平台」；密码输入框值为空 |
| CI 关键登录路径：SM2 加密登录成功进概览、错误密码停留并提示失败 | `前端代码/basic-framework-admin/apps/web-ele/e2e/ci-critical-login.spec.ts` | 临时 SM2 密钥校验密文回环；正确输入跳转到 `#/dashboard` 且渲染「系统管理」与「管理员」；错误输入保留 `#/auth/login` 并显示失败提示 |

## 尚未覆盖的产品功能

以下产品功能当前没有关键路径 e2e，列出它们是为了区分已登记覆盖和待补范围，不参与功能图对齐门禁。未覆盖项缺少登记行不会使测试失败；一旦为它们新增 `*.spec.ts`，必须先补充规格中的用例，再在本页登记对应行。

- 系统日志、字典、部门与岗位等 CRUD 页面。
- 角色与菜单授权变更后重新登录、权限缓存刷新和跨角色数据范围。
- 定时任务的执行、失败重试和调度配置。
- 短信回调、外部客户端签名校验及其失败处理。
- 文件私有桶签名、网关转发和对象存储异常补偿。
- 首页统计、个人中心和主题切换等非关键交互。

## 漂移检查与维护

功能图与规格文件的双向对齐由 [scripts/tests/test_feature_map.py](../../scripts/tests/test_feature_map.py) 强制，解析逻辑集中在 [feature_map_support.py](../../scripts/docs/feature_map_support.py)。检查读取本页的关键路径表和 `apps/web-ele/e2e/` 下的规格文件，不启动浏览器，也不执行 Playwright 用例：

```powershell
# 在仓库根执行
python -B -X utf8 -m pytest scripts/tests/test_feature_map.py
```

新增、删除或重命名关键路径时，按以下顺序更新：

1. 先在规格文件中补充或调整真实用例，确保断言来自页面操作或接口的可观察结果。
2. 再修改本页表格，保持三列、单个行内代码路径和唯一表头。
3. 执行上述测试和仓库文档检查；未登记的规格文件、表中不存在的路径或没有用例的登记都会失败。

其中 `production-security.spec.ts` 与 `ci-critical-login.spec.ts` 已通过 `pnpm run test:e2e:ci` 接入 GitHub Actions `frontend` 门禁并在 `GITHUB_STEP_SUMMARY` 记录实际执行结果；涉及真实数据库/Redis/对象存储的全量路径仍需本地环境运行，功能图测试只证明登记关系一致，不能替代浏览器用例真实通过。

<a id="limitations"></a>

## 已知限制与暂缓工作

对齐检查覆盖的是功能图登记与规格文件结构，不覆盖浏览器环境和用例运行结果；以下边界决定了它不能替代哪些验证。

- 关键路径表只支持三列固定格式；调整列名或列数必须同步修改解析模块和检查测试。
- 一个规格文件可以登记多条用户路径，但每条用户路径必须独立成行；表格不表达用例级别的执行顺序或依赖。
- 「尚未覆盖的产品功能」是人工维护的提醒列表，没有机器检查；它不能证明对应功能不可用，也不能代替新增用例。
- 对齐检查验证规格文件存在且至少有一条 `test(` 声明，不验证用例在本地环境实际执行通过。
