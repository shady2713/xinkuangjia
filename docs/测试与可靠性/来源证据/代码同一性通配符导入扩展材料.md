- 候选变体「展开后按限定名比较」：equal=True
- 候选变体「展开后只按简单名比较」：equal=False
- 候选变体「丢弃未使用导入后按限定名比较」：equal=True
- 会放过该差异的变体：展开后按限定名比较、丢弃未使用导入后按限定名比较
- 展开虚构出的不存在的类型：上游 `java.lang.annotation` ← `Demo`
- 结论：当前规则拒绝；候选变体「展开后按限定名比较、丢弃未使用导入后按限定名比较」会放行

### CE-4 多个通配符导入会让“按正文简单名展开”生成不存在的类型（展开会虚构不存在的类型）

- 待回答的问题：展开结果里有没有 JDK 中并不存在的类型？

- 当前规则：equal=False（当前规则实现保留全部 import 条目并逐字节比较，形态不同即拒绝）
- 候选变体「展开后按限定名比较」：equal=False
- 候选变体「展开后只按简单名比较」：equal=False
- 候选变体「丢弃未使用导入后按限定名比较」：equal=False
- 会放过该差异的变体：无
- 展开虚构出的不存在的类型：上游 `java.lang.annotation` ← `Demo、List、String`；上游 `java.util` ← `Demo、Documented、String`
- 结论：当前规则与三个候选变体都保留该差异（可作为正向对照）

```java
// 本地
package p;

import java.util.List;

public class Demo {
    List<String> value;
}
// 上游
package p;

import java.lang.annotation.*;
import java.util.*;

/** 上游：两个通配符。 */
@Documented
public class Demo {
    List<String> value;
}
```
