## 二、判定口径：什么算「保持契约」

改判这 5 条能否成立，取决于检查器的复算口径。以下行号对应 HEAD `7576c8b` 的
`scripts/code/java/check_staged_java_comments.py`（整文件 SHA-256 见[来源证据说明](来源证据/README.md)登记值）。

### 2.1 B 类的封闭性：改证据路线不能解除

`_member_identity_contract_reasons`（L5390 起）在做任何成员比较之前先命中两个拦截：

- `_member_identity_boiler_c_object`（L5360）：C 类 4 条「已点名对象即使带着再完整的成员证据也不放行」。
- `_member_identity_ineligible_object`（L5378）：按 `upstream_path` 精确匹配 `branch_ineligible`，命中即返回
  「D17 §B 类五条在当前固定输入与登记变换下没有任何逐字节相等的完整成员，本分支不接受它们；**改判需另按 D10 路线 1/3 取得独立证据**」（L5463–L5470）。

**因此 B 类的唯一合法出口是「路线 1／3 或可靠导入记录」（`成员同一性成员清单.json` 的 `required_verification` 与 `exclusion_basis`），而不是换分支、换分类或改契约。**

### 2.2 路线 3 的机器门槛

- `_route_reasons`（L6196–L6201，未声明分支时）：`evidence_points` 按 `；`/`;` 切分后**至少 2 段且互不相同**，且**每段至少含 2 个数字**（双方行号）。
- `_content_independent_reasons`（L2956，`C2-independent-content` 分支）：`content_points[]` 至少 2 点，每点必填
  `fragment / fragment_sha256 / local_path / local_sha256 / upstream_path / upstream_sha256 / local_lines / upstream_lines / owner_type / field_or_behavior / point_kind / corpus_binding / discrimination_reason`（L370–L384）；
  `point_kind` ∈ `("内容点","注释点")`——**结构点不得充当 C2 内容点**（L3010）；
  另需记录级 `independence_reason` 与 `counter_evidence_conclusion`（L2978–L2981）。
  机械拒绝的形状：片段重复或互为包含、同一 `owner_type+field_or_behavior` 复述、双方行号重合、`CONTENT_POINT_GENERIC_PATTERNS` 命中（L454–L461）。
- `_branch_route_reasons`（L6137）：`C2-independent-content` **只允许** `evidence_route = 路线 3`。

`CONTENT_POINT_GENERIC_PATTERNS` 的六条（L454–L461）是本轮判定「替换能否换到内容点」的关键：

1. `^(?:校验|验证)?(?:不能为空|必须|长度不能超过|格式不正确|已存在|不存在|不正确)` —— 吃掉全部 `…不能为空` / `…必须` 校验串；
2. `^(?:管理后台 - |获得|获取|创建|修改|删除|导出|导入|新增|更新|查询|分页|列表)` —— 吃掉「管理后台 - …」模板描述；
3. `^(?:Request|Response) VO$`；
4. `^@(?:Schema|NotNull|NotBlank|Size|Min|Max|Valid|ApiModelProperty|ApiOperation)\b`；
5. `^(?:true|false|null|0|1|示例|example|test|demo)$`；
6. `^[A-Za-z_$][A-Za-z0-9_$]*$` —— **裸标识符样例值**。

**结论（对本材料最关键的一条）**：五条现有的候选片段全部落在第 1/2/5/6 条或字段标签之列。即便把上游的样例值原样恢复，`yudaoyuanma` 命中第 6 条、`1` 命中第 5 条，**换不来任何一个合格 C2 内容点**。D14 §106–§108 的人工判定与机器口径在此一致。

### 2.3 与「保持契约」相关的另外三处

- `_local_modification_reasons`（L6249）：本地修改行必须与索引 `local_modification_facts` 一致；只有在记录登记「无本地修改」时，本地才允许写 `LOCAL_MODIFICATION_NONE_LINE`。**替换成上游逐字节后，这条才可能改写为「无。」——但那本身就要改索引记录。**
- `_type_mapping_reasons`（L6205）：`type_evidence.types[].javadoc_sha256` 必须等于**当前类型 JavaDoc** 的 SHA-256。**任何生产字节改动都会使该指纹失效并把该条从「已登记阻断」升级为硬失败**（[裁决 D18](裁决-D18-认证入参契约与旧配置键.md)已实测：`registered_blockers` 162→161、`hard_failures` 0→1）。
- `_history_reasons`（L6094–L6134）：这是**「可靠引入版本记录」**的实现。若来源依据写成「已核实引入版本」，索引必须绑定
  `history.basis`、`introduced_commit`（40 位小写 SHA）、`introduced_repo_url`、`introduced_path`、`introduced_sha256`、`file_url`，且 `_verify_upstream_snapshot` 必须通过。

## 四、逐条论证

### B-1 `BasicFrameworkTranslateAutoConfiguration`

**阻断性质（与 B-2…B-5 不同）**：这是 5 条里**唯一**落在「署名类 33 条」的。检查器 finding 为
「public 类型 … 的**署名未被独立验收**」，因为本地类型仍带 `@author 李杰`，而固定上游版本该文件**没有**
`@author` 标签（`upstream_author_declared: false`）。索引里它也是 5 条中**唯一没有 `retraction_reason`
的记录**——另外 4 条已按 D12 §62/§64 完成受控撤回、改为逐项来源说明，它没有。

**替代基线**：受控快照 `YudaoTranslateAutoConfiguration.java`（`30d0d8a2…`，696B，20 行）。

**重新引入 or 替换：明确建议「都不做」，另立独立议题。**

理由三条，按强度排序：

1. **路线 3 不是它的出口。** 补足 C2 内容点只能解决「来源说明」一侧；`@author 李杰` 在上游无任何声明，
   按 D12 §99/§109 不得凭项目名或所有者补造。对这条而言「替换成上游」也不会让 `@author` 变得可核验——上游
   自己就没有。**换证据路线解决不了署名问题。**
2. **替换会引入运行期空指针。** 上游在 Bean 方法上有 `@ConditionalOnBean(TransService.class)`，本地删除了它。
   `TranslateUtils` 用 **static** 字段持有 `TransService`，`translate()` 直接 `transService.transBatch(data)`
   （`…/framework/translate/core/TranslateUtils.java:19,38`）。若按上游形状静默跳过注册，
   `OperateLogController.java:108` 的 `TranslateUtils.translate(...)` 会在运行期 NPE，而不是启动期失败。
   现有测试 `BasicFrameworkTranslateAutoConfigurationConditionalRuntimeTest` 逐条锁定了当前形状：
   `missingTransServiceFailsContextStartup` 断言「缺少翻译服务时当前实现会让上下文启动失败」且失败原因含
   `TransService`；`upstreamShapedVariantSilentlySkipsSoAssertionDiscriminates` 用**契约违反变体**
   证明该断言有判别力。该测试自述：「不对『无条件装配是否是目标契约』下结论：**该判断属于有权者处置范围**」。
3. **依赖坐标会悬空。** 上游 import `org.dromara.trans.service.impl.TransService`；本地 import
   `com.fhs.trans.service.impl.TransService`，且 `basic-framework-dependencies/pom.xml` 只声明
   `com.fhs-opensource:easy-trans-*`（`easy-trans.version = 3.0.6`），仓库内**没有** `org.dromara` 声明。
   按上游替换会在编译期找不到 `org.dromara` 包。
