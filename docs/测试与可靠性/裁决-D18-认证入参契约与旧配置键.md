# 裁决 D18：认证入参格式契约与已删除短信配置键的处置

## 摘要

有权者就两个议题作出决定，方向原样如下，**未作任何改动**：

1. **认证入参格式契约**：按 **32 位十六进制摘要**校验。**禁止**改回上游 `@Length(4,16)`——实测会把
   100% 合法登录判为参数错误（前端提交的是 32 位 MD5 摘要）。落地形态是 `@Pattern` 之类的**格式**校验，
   不是长度范围。
2. **已删除的旧短信配置键** `begin-code` / `end-code`：改为**启动时 WARN 告警 + 迁移文档**。
   **不是**严格绑定失败，**不是**继续静默忽略。

裁决日期：2026-10-08。核对版本：`dc30cc55737c554c092384c5759fd1cec1abc291`（分支
`codex/framework-remediation`）。决定前的实测材料与选项成本在仓库外
`.bf-local/decide2/证据.md`（核对 HEAD `10b1021`），本裁决只固定**决定内容、落地形态与验收读数**。

本裁决签发时**未 commit、未 push**；工作树内只有本轮实现与记录改动。

## 决定一：登录口令的入参格式契约

### 落地方式

`AuthLoginReqVO.password` 现在的约束面是两条：`@NotEmpty`（既有）+ `@Pattern`（本次新增）。选择
`@Pattern` 而不是 `@Length` 的理由已由上一轮实测给出：登录报文里的 `password` 是前端 `md5(...)` 的产物
（`apps/web-ele/src/store/auth.ts:81`），恒为 32 位十六进制；上游 `@Length(4,16)` 会拒绝**全部**合法登录。
新约束与仓库既有的 `AuthResetPasswordReqVO.password`（`@Pattern(regexp = "^[a-fA-F0-9]{32}$")`）完全同形，
属于同类形态内部对齐，不引入新语义。

### 「合法登录未被破坏」的逐条复核

| # | 消费点 | 提交的 `password` 形态 | 依据 | 判定 |
| --- | --- | --- | --- | --- |
| 1 | `前端代码/…/apps/web-ele/src/store/auth.ts:81`（`authLogin` 默认分支） | `md5(明文)` → 32 位小写十六进制 | 源码逐行 | **通过** |
| 2 | `login.vue:64`（无验证码路径）与 `login.vue:86`（验证码完成路径） | 两者都调 `authStore.authLogin('username', …)`，即 ① | 源码逐行 | **通过** |
| 3 | `前端代码/…/apps/web-ele/src/api/core/auth.ts:68`（`/system/auth/super-admin-login`） | 透传 ① 的载荷，不二次处理 | 源码逐行 | **通过** |
| 4 | `scripts/perf/measure_endpoints.py:215`（性能基准登录） | `hashlib.md5(...).hexdigest()` → 32 位小写十六进制 | 源码逐行 | **通过** |
| 5 | `后端代码/basic-framework-boot/README.md:91` 与 `docs/部署/数据库初始化与迁移.md:82` 的 curl 样例 | 明示「口令按前端协议先做 MD5」，样例值是 MD5 占位符 | 文档逐行 | **通过** |
| 6 | `AuthenticationSessionMySqlIT`（真实 MySQL 登录链路） | `UUID.randomUUID().toString().replace("-","")` → 32 位小写十六进制 | 源码逐行 | **通过** |
| 7 | `OAuth2MachinePrincipalHttpMySqlIT`（真实 HTTP 登录链路） | 原本是带连字符的 36 位 `UUID.randomUUID().toString()`（**明文且非十六进制**），与现行协议不符 | 源码逐行 | **本轮修正**为去连字符的 32 位十六进制，与 ⑥ 同一写法 |
| 8 | `docs/测试与可靠性/整改审查与接续.md:131` 记录的实测 | 「登录接口的 `password` 字段接收的是明文的小写 MD5 十六进制……直接传明文会得到 `账号密码不正确`」 | 历史实测记录 | 与本次约束一致 |
| 9 | `TokenAuthenticationFilter` 等过滤器 | 不读取 `password`（只处理令牌），不受影响 | 源码核对 | **不受影响** |
| 10 | `AdminAuthServiceImpl#login` / `#superAdminLogin` / `#authenticate` | 不声明格式约束，只做 `BCrypt` 比对 | 源码核对 | **不受影响** |

**已知且如实登记的一处不一致**：注册侧 `AuthRegisterReqVO` 仍带 `@Password`（6-16 位且含大小写字母与数字），
在本协议下 32 位摘要会被拒绝。该项**属于另一议题**，本裁决**没有**改动注册侧（见「明确未决的事项」）。
`AdminAuthServiceImplTest`、`AuthControllerTest` 直接调用对象/控制器，不经过 Spring 校验代理，行为不变。

## 决定二：已删除短信配置键的启动告警

### 落地方式

新增 `SmsCodeDeprecatedKeyReporter`（`com.basicframework.module.system.framework.sms.config`），实现
`EnvironmentPostProcessor`，通过 `basic-framework-module-system/src/main/resources/META-INF/spring.factories`
注册——与仓库既有的 `IdTypeEnvironmentPostProcessor` 同一接线方式。

- 检测面：本地前缀 `basic-framework.sms-code.begin-code` / `.end-code`，以及固定上游前缀
  `yudao.sms-code.begin-code` / `.end-code`（上一轮实测后者同样既不报错也不生效）。
- 判定：`ConfigurableEnvironment#containsProperty`，因此 YAML、system properties、环境变量
  （含 `BASIC_FRAMEWORK_SMS_CODE_BEGIN_CODE` 这类大写下划线写法）与命令行参数都会被命中。
- 告警文案给出键名、**该配置已移除**、**没有替代配置键**，以及现在由什么决定验证码取值
  （`SmsCodeServiceImpl` 的常量）。
- **不打断启动**：只调用 `log.warn`，不抛异常、不改属性面、不改 `ignoreUnknownFields`。

迁移说明写入 [`docs/部署/部署说明.md` 的「已删除配置键与迁移说明」](../部署/部署说明.md#已删除配置键与迁移说明)。

### 已知且如实登记的检测边界

YAML 里把键名写成驼峰 `beginCode` 时不在检测范围内（`containsProperty` 按字面键名查找）。该限制已写进
迁移文档与生产类注释，不隐藏。

## 受控来源索引的事实指纹刷新

`AuthLoginReqVO.java` 在 `docs/测试与可靠性/来源证据/d12-source-index.json` 中有一条受控记录
（`record_kind: derived-upstream-author-undeclared`）。任何生产字节改动都会使该记录的
`local_sha256_after` 与绑定 JavaDoc 的 `javadoc_sha256` 失效，检查器随即把这一条从「已登记阻断」
升级为**硬失败**（实测：`registered_blockers` 162→161、`hard_failures` 0→1）。

因此本轮**只**刷新了该记录的事实性指纹：

| 字段 | 刷新为 | 说明 |
| --- | --- | --- |
| `local_sha256_after` / `local_bytes_after` / `local_bytes_final` | 当前文件真实字节的 SHA-256 与长度 | 事实字段，记录的是「本地最终版本」 |
| `type_evidence.file.local_sha256_final` | 同上 | 同上 |
| `type_evidence.types[0].javadoc_sha256` | 当前类 JavaDoc 文本的真实 SHA-256 | 事实字段 |
| `type_evidence.types[0].declaration_line` / `javadoc_start_line` / `javadoc_end_line` | 29 / 14 / 22 | 行号随新增 import 与字段注释整体下移 |
| `evidence_points`、`d12_correspondence_points` 中的本地行号 | `登录账号不能为空` L35、`密码不能为空` L51 | 共享字面量的实际行号 |

**未改动**（逐字保持）：`d12_verdict`、`d12_blocker_reason`、`blocker_reason`、`open_gap`、
`review_conclusion`、`review_date`、`retraction_reason`、`b1_review`、`evidence_route`、`author_status`
及其它判词字段；也**未删除任何条目**、未改阈值、未加排除。刷新后 `hard_failures` 回到 0、
`registered_blockers` 回到 162，与决定前逐项一致。

类 JavaDoc 的 `本地修改：` 行同步追加了 12 字符的事实性说明「；新增@Pattern约束」（保持 ≤120 字符以满足
PMD `CommentSize.maxLineLength=120`；该规则是首轮 `verify` 真实报出的唯一违规
`basic-framework-module-system/…/AuthLoginReqVO.java:20 Comment is too large: Line too long`，已按既有阈值
压缩说明文字后重跑转绿，未改阈值）。

### 由本次指纹刷新连带必须重生成的材料

`docs/测试与可靠性/来源证据/d12-source-index.json` 的 SHA-256 被 D16 / D17 复核材料登记为输入指纹，
因此指纹刷新后这两个机器生成包**必然过期**。已用仓库自带的生成器就地重生成
（`scripts/tools/build_d16_review_package.py --build`、`build_d17_member_review_package.py --build`），
逐条差异只有三类机械字段：`repository.head`、`inputs.source_index.sha256` /
`inputs.source_index.records_sha256`、材料 Markdown 首段的生成时间。**判定列、逐条材料内容、
`d12_verdict` 分布（11 / 58 / 18 / 77 / 22）逐项未变**，未手工编辑任何一字节材料。

若不重生成，`pytest scripts/tests -q` 会以 `test_d16_review_package` /
`test_d17_member_review_package::test_generator_cli_rebuilds_identical_materials` 失败退出 1（已实测复现）。
重生成后实测 **1441 passed / 0 failed**，与决定前基线一致。

### 必须披露的一处门禁影响

`AuthLoginReqVO.java` 本身是 D12 已登记阻断的 162 条之一。工作树增量入口
（`check_worktree_java_comments.py`，即 `run_checks` 里的 `java-comments`）**没有维护模式**，
任何**触碰已登记阻断文件**都会把它作为 finding 报出并退出 1。已实测这是结构性行为：在隔离工作树里对
与本议题无关的 `UserTypeEnum.java`（同为已登记阻断）追加一行注释，同一入口同样退出 1 并报出
`type-author` finding。

全量入口 `java-comments-full` 的验收计数不受影响：`accepted 31 / registered_blockers 162 /
hard_failures 0`，与决定前逐项一致。消除该退出码需要关闭 D12 对 `AuthLoginReqVO` 的登记阻断，
属[待有权者决定事项](待有权者决定事项.md) D6 的范围，本裁决**无权代做**，也未因此放宽任何规则或加排除。

## 明确未决的事项

以下三项**不在**本裁决范围内，本轮**没有**代为决定，实施方也**没有**擅自改动：

1. **`AuthRegisterReqVO` 的 `@Password` 与 MD5 协议冲突**：注册侧仍要求 6-16 位明文强口令，32 位摘要会被
   拒绝。当前默认部署关闭注册（`basic-framework.auth.registration-enabled` 默认 `false`，服务层
   `AdminAuthServiceImpl#register` 首行即拦截），运行期无影响；一旦重开注册而前端仍按现行协议送摘要，
   合法注册请求会全部返回业务码 400。**需要认证策略签认方单独裁决。**
2. **`UserProfileUpdatePasswordReqVO`（个人改密）、`UserUpdatePasswordReqVO`（管理员重置）、
   `UserSaveReqVO`（新增用户）** 三个管理端入参类仍只有 `@NotEmpty`，与登录侧同形态但未同步收紧。
   上一轮建议随登录侧一起处理，**本轮未做**。
3. **`release_verified=false` 与 162 条已登记阻断**：属[待有权者决定事项](待有权者决定事项.md)的
   D6，**本裁决不影响其状态**，也不构成对该决定的任何倾向。
