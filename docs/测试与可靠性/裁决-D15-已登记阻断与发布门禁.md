## 方案裁定及与前序裁决的关系

保留候选来源文本、拒绝将其作为已充分核实的来源，这两项要求可以同时成立。真正需要裁定的是：未验收是否阻止维护检查完成，以及是否阻止发布验收。CI 红灯并不证明 D14 自相矛盾；将维护可继续和发布可批准混为一个布尔状态，才造成所述冲突。

1. **采纳有界 A。** 已有未验收项满足完整登记、就地标注、版本绑定及报告一致性要求时，维护检查可记为“已登记阻断”。它表示缺口被正确识别与纳管，不表示来源关系、作者身份或交付义务已通过。未知状态、未登记缺口、新增但未复核的对象不得自动进入此类别；新增或范围变化须有逐项结论。
2. **不采纳 A 的自动降级。** 将 81 条长期登记并改称“已知非阻断限制”，直接令最终条件②成立、release 变绿，实质改变了 D10/D12/D14 的验收条件。本裁决不作这项变更。158 也只是在当前 186 条索引内核实的未验收数，不能冒充全 D10 或实际发布范围的全部阻断数。
3. **D 为补证手段。** 不要求所有条目继续硬凑路线 3，不将历史检索作为每项必经过程；按具体证据选用 D10 已允许的其他充分路线。
4. **B 保留在发布边界。** 原发布条件未满足时维持非零退出。维护模式可以完成，不要求所有工具检查长期只能以失败结束；但当前这个 release run 不能仅通过重新分类恢复全绿。
5. **C 不作为批量完成路径。** 不为通过门禁移除 81 条来源说明、恢复旧姓名或隐藏索引记录。具体事实核实后可以有依据地修正文案，但这不等于来源已验收。

本 D15 补充 D14 §120 的维护状态表达，并限定调整独立复核 Q4“真实消费者拒绝”的含义：**维护消费者可以允许已登记状态继续流转，来源验收与发布消费者仍拒绝把它算作通过。** 未显式选择维护模式时，既有验收入口保持严格拒绝，避免旧消费者把退出 0 自动解释为来源已通过。最终 release 无论上游怎样选择维护模式，均须独立读取并裁决来源状态。

D14 要求保留旧状态、整改前文本及失败依据，不要求永久冻结当前 Java 文件字节。允许保留原来源正文并增加验收标注；改动前的原始文件、diff 和指纹另行冻结留证。已证实不准确的“本地修改”摘要也应在后续有授权的整改中据真实 diff 修正，原文仍留在历史证据中。rev2 因其当次“不改 81 条 Java 文件”的任务边界未回填标注，可以解释未完成，不能转成 D14 禁止标注的规则。本轮只作裁决，未执行这些文本变更。

D12 的来源例外、D13 的路径拼接与长度约束、D14 的区分力、独立性、真实作者、多源和独立复核条件继续有效。增加标注后重新生成文件、类型及 JavaDoc 指纹和行号；仍执行 PMD，不扩大抑制或排除。本 D15 不给予任何具体条目新的 accepted 结论。

## CI 报告与汇总的强制呈现

“已登记阻断”必须是可独立核验的报告状态，不能仅在日志里打印一个警告。以下是待实现的最低语义契约，字段名可依现有协议映射，但不能丢失状态、逐项内容和消费者校验；不能将当前 v1 协议直接填入一个未知状态而仍宣称兼容。

| 层次 | 必须呈现与校验的内容 |
| --- | --- |
| 检查器 | 实际扫描范围与计数；执行是否完成；真实进程退出码；硬违规清单；独立的已登记阻断清单；已验收来源及独立 A1 分支结果。维护完成态使用独立状态，例如 `completed-with-registered-blockers`，不得使用 `passed` |
| 逐项阻断 | 唯一记录标识、本地路径、每个受影响 public/嵌套类型及行号、来源说明或作者标签形态、当前判词、阻断原因、缺口、所用路线、原与当前文本/输入指纹、逐项复核依据、负责方及下一步材料。文件数、声明数与诊断数分别统计，不重复累加同一个文件 |
| CI 制品及摘要 | JSON 制品保存全部逐项结果；作业摘要醒目显示已登记阻断数、硬违规数和未覆盖数，并链接可取得的完整清单。上传与摘要在失败时也执行；不得截断唯一清单、仅给本机路径或删掉原始失败证据 |
| `run_checks` 与报告复核 | 同步版本化协议、解析、调度和 `verify_report`；维护完成态不进入通过检查数，也不增加已验收对象数。复核清单、当前输入及实际计数，不能只信子工具声明。登记的已知证据缺口可以存在，登记完整性和对象绑定缺口不能被一并豁免 |
| `ci_gate` 汇总 | 实际取回本次来源报告，核对 run/提交、规则与工具版本、唯一账本及派生索引指纹、最终对象指纹、范围、逐项状态和计数；作业输出可作定位信息，但计数不能代替报告。无报告、未知 schema、旧提交、计数不符或范围漏项均受控失败 |
| 交付报告 | 已验收来源、A1 局部验收、未验收来源、未验收署名及历史缺口分列。已登记阻断仍列在“未解决阻断/未验收”，不得移到“已知非阻断限制”以满足原关闭条件 |

对未验收来源说明，正文必须具有且仅具有一条与索引相符的 `来源验收：尚未验收`，绑定实际声明；无标注、重复/冲突标注、未知值或自称已验收均硬失败。来源说明转 accepted 时须同步调整标注并完成对应证据验收，不能只改单侧。已经登记为未验收不要求补齐其恰好缺失的两个内容点才能纳管；但索引、对象、保留文本、状态及最终版本必须能核对，任何其他新失败不能借“未验收”提前返回而消失。

阶段与退出码须明确区分，禁止用一个通用 `passed` 兼任执行与验收结论。

| 情形 | 检查/作业结果 | 汇总与发布结论 |
| --- | --- | --- |
| 显式维护模式，扫描完成，只有合规登记的未验收项 | 可退出 0；文档与工具作业可 success，报告仍为维护完成且有阻断 | audit/functional 维护汇总可退出 0，但状态必须明示有阻断、来源未验收，`release_verified=false`；不能宣称完整验收通过 |
| 严格来源验收模式，存在适用未验收项 | 退出 1，列出逐项阻断 | 来源验收不通过 |
| release，仍有适用未验收项，即使四作业均 success | 取回并复核来源报告后拒绝 | 汇总退出 1，输出明确阻断状态与 `release_verified=false`，条件②、⑤未满足 |
| 缺登记/标注、版本错配、accepted 证据不足、其他规则违规 | 规则违规退出 1；报告不可读、环境错误、超时依现有受控非零语义 | 不得降为已登记阻断或通过；报告失败与原因 |
| 所有适用来源与其他发布条件真实通过 | 原有各项真实通过 | 只有 release 且其他发布证据也通过时才可 `release_verified=true`；来源零阻断单独不充分 |

当前完整全量诊断 130 条必须留证；新实现可以将已合规纳管的状态转列到独立阻断集合，不能把旧诊断删除后只留下 `findings=[]` 与 `status=passed`。当前 125 个来源文件补齐标注后可作为维护纳管候选；33 个署名文件同样必须纳管，不能把新清单缩成 81 条。实际逐类型数由扫描器重算，不把文件数硬编码为声明数。其他 D10 阻断与实际制品范围仍须从权威账本冻结核对，不用本索引范围替代。

## 合入前置条件与负对照

**要求正、负对照实际通过后才能合入及启用这项状态变更。** rev2 的五条 CLI 对照与变异验证证明旧“未验收一律拒绝”逻辑有辨别力；它们没有验证新的维护状态、缺失标注拒绝、报告传递和 release 聚合拒绝，不能直接作为 A 的完成证据。

| 对照 | 必须观察到的结果 |
| --- | --- |
| 合法 accepted 与合法 A1，其他输入有效 | 各自路线可通过；不因 A1 判词不在来源 accepted 集合而误阻断。来源 accepted 不自动证明历史作者恢复 |
| 已登记、正确标注且绑定有效的未验收来源 | 维护消费者实际扫描并列入独立阻断，退出 0 但不记 `passed`；严格验收消费者退出 1；release 汇总退出 1、标志 false |
| 去掉未验收标注、写为已验收、出现相互冲突/重复标注 | 维护和严格入口均因目标标注问题退出 1。同步更新该反例的合法指纹，避免仅因旧哈希失败掩盖逻辑遗漏 |
| 无索引记录，缺判词/原因/缺口，伪造未知判词，改路径/类型映射 | 维护也硬拒绝，不自动当作“已登记”；不能靠任意非 accepted 字符串触发豁免 |
| 把未验收状态改为 accepted，仍缺合格路线、对应点绑定或复核 | 因目标验收证据不足拒绝，不能只认状态值；其他本应有效的绑定保持有效 |
| 篡改实际源码/上游输入沿用旧指纹；只改清单或快照；只改注释/嵌套类型 | 真实消费者拒绝失效绑定，扫描所有受影响声明；来源或作者形态切换不得绕过 |
| 原阻断仅有合法形式的 `@author`，删除来源说明或换成普通作者标签 | 仍报告未验收署名；有登记也只能维护纳管，不能消失于汇总或变成已验收。已核实真实作者和合法多作者正例仍通过 |
| 四个必需作业 success 且均有正计数，但来源报告仍有已登记阻断 | release 聚合必须退出 1、输出 false；证明来源状态直接被聚合消费，不依赖 docs_tools 的 job failure 间接保护 |
| 删除报告、改计数、减清单、换旧提交、缺阶段/规则指纹、缺来源索引 schema | 真实报告复核/汇总拒绝；不能用默认 0、空集合、旧账本降级或 skipped 代替本次来源验收 |
| 无适用阻断的受控完整 release 正例；恒真/恒假变异 | 合法发布证据能通过；分别注入“全当登记/全通过”和“全拒绝”时，对照必须失败，避免恒真或恒假门禁 |

验证链须包含检查器 → 全量、工作区及隔离暂存入口 → `run_checks` → `verify_report` → CI 作业输出/制品 → `ci_gate`，覆盖报告缺失与失败后的制品保存。所有层使用最终候选版本；记录命令、输入指纹、实际对象数、目标诊断和退出码。测试工具退出 0 只证明预期成立，被拒绝的 release 对照自身仍须退出 1；编译、PMD 或零对象检查不能替代。

最终实施范围的逐项状态和文本须由实施者之外的负责方复核，或有具体材料的逐项争议裁决；本轮不新增代理、不替现有复核记录填“全通过”。旧 full-semantic/point-level 强度和未覆盖范围继续明示。

## 81 条及其他来源阻断项的收口

“当前登记点不够”与“该文件永远不可能取得证据”不是同一事实。单块 Mapper、通用校验器或枚举的类型名，不能证明路线 3 客观不可能；浅克隆与当前材料缺失也仅能证明此次未取得历史。不得为了关闭，把通用模板拆成两个点、按两个方法凑数或扩大 A1 的忽略范围。

逐项按下列顺序形成可验收结论，不要求同时满足全部路线：

1. 核对完整双方内容、现有点与反证，记录为何当前路线 3 不成立；有真实不同且有区分力的内容或结构点时，按 D14/D10 原条件复核。
2. 不成立者可转 D10 路线 1：可靠导入记录、发布源码清单或可核验历史补丁，绑定具体固定版本、本地内容及实际差异并解释反证。也可转路线 2 或已批准 A1，但须满足完整内容比较和作者处理条件。直接来源记录是原有充分路线，无须创设降低门槛的“短文件例外”。
3. 逐方法/片段取证可帮助定位真实保留内容及多源映射，不是新的低门槛路线；单方法两个通用动作不能算两个独立证据，片段成立也不能自动授权整个文件全部类型。片段汇总须覆盖声明范围及重要差异。
4. 取得可靠本地创建和贡献记录的，可以按 D10 核实原创或共同贡献，解释相似候选后迁移；“找不到上游”“补证太难”不是原创结论。
5. 仍无充分证据时保持 `未核实/未验收` 和适用阻断，登记已尝试材料、未取得原因、负责方与复查条件。可以在维护阶段继续开发，不能宣称本项或整个 D10/D12 完成。

**不要求伪造第二点，也不批准永久登记作为完成路径。** 若最终希望交付仍含这些内容而放弃原“无未解决适用阻断”条件，须另有逐项且绑定制品范围的明确验收条件变更，说明哪些义务被调整、风险承担及发布语义；该决定不等于来源已证明。本 D15 未授予这样的整体豁免。另一个可能的收口是有授权地停止分发对应实现，并证明最终制品及消费方确实不再包含它；仅从扫描清单中排除文件不能成立。此次不删除实现或调整发布范围。

以上同样适用于 44 条原阻断来源说明；它们不能因不属于新复核的 81 条而获得不同待遇。保留候选说明须清楚标成未验收，已核实的正文错误据实修正并留存旧证据；不要把暂时不能核实的来源关系写成已证实错误，也不要恢复未经证实的旧姓名。

## 33 条作者标签残留的处置

这 33 条属于当前索引的原阻断记录，D12 已要求保持原状直至新的逐项证据支持变更。作者标签格式可解析，仅说明注释满足语法条件，不证明姓名真实或来源已核实。

- **必须同等纳管。** 验收状态消费以清单对象及声明为入口，覆盖“来源说明”和“作者标签”两种形态。这 33 条必须逐项列入未验收署名集合及发布适用阻断，不能只修改 `_verify_single_note` 而继续让作者分支绕过。当前登记总数按文件为 158，而非只报 125 或 81。
- **保持姓名的待核实状态。** 在证据支持新判断前不删、不换、不补造姓名，不批量转成来源说明或原创。后续实现增加独立的就地署名验收标注，与索引的未验收状态绑定；标注不能塞进 `@author` 值、不能描述该姓名为已核实。具体语法须版本化并提供负对照。标注缺失或与索引冲突时不能进入维护完成态。
- **支持逐项迁移。** 证明真实作者或共同贡献后准确保留；满足 D10 的来源与作者条件后恢复相应作者；满足 D12 的无作者来源例外后采用来源说明。每次迁移保留前后原文、理由、真实 diff、最终指纹及逐项复核。
- **不扩大误判。** 11 条有效 A1、其他已核实作者、多作者或 HTML 标签正例不能因“有 `@author`”被一律拒绝。发现权威账本内其他未验收项时按实际发布范围登记；不能因为它不在 186 条派生索引里就默认为已验收，也不能仅因索引未覆盖就断言该姓名虚假。
