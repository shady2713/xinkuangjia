# 性能基准与回归门禁

<a id="summary"></a>

## 摘要

为性能基准选择真实入口、可复现负载、可比较的时间与资源口径；需要自动回归判定时，再建立并验证门禁。普通调查可复用现有测量设施，读取本次涉及的章节，不要求建立门禁。本文不指定语言、运行时版本、目录名或统一阈值；先查阅目标项目现有测试与 CI 配置。

## 基准归属与生产入口

局部诊断跟随所属模块，跨模块基准按被测用户路径组织，并接入项目已有测试通道。沿用现有校准、报告和资源清理设施；只有实际需要时才提取共享辅助代码，不为每个场景复制一套基础设施。

basic-framework 当前提供前端体积分析及功能/工具测试入口，见[前端测试与交付工具](../开发指南/前端测试与交付工具.md#构建体积分析)和[测试策略](../测试与可靠性/测试策略.md)；这些入口不构成 API 延迟、浏览器响应或内存的自动性能门禁。需要建设基准时，先明确业务入口与测量卡，再随对应模块维护可执行用例与可评审预算，不能宣称框架已有统一吞吐量或响应时间保证。

被计时的入口应对应交付方式。产品交付构建产物时使用相应产物和运行时，源码加载器或测试解析产生的额外成本应排除或单独标明；产品本身以源码运行时，按实际部署方式验证。容器交付时核对镜像、启动参数和资源限制，并说明是否计入容器启动。测试替身只控制明确的外部边界，不复制产品算法，也不为测量随意增加生产导出。

浏览器测量使用真实浏览器与适用产品资源，通过真实键盘或指针等输入观察对应界面更新。分别说明服务端、传输、界面更新和交互覆盖；一次调度或渲染机会不能直接证明用户已看到画面或完成输入响应。仅有服务端处理、伪 DOM 或自定义定时事件也不足以证明浏览器响应。

<details>
<summary>帧、输入与流式负载的测量细节</summary>

帧与输入采样应覆盖测量窗口内最后一次卡顿，区分计时器调度与真实输入响应。限制合成生产方的发送节奏，避免延迟后追赶式突发生成改变被测负载。记录首次绘制、滚动、分页、实时更新和已激活但隐藏视图分别是否覆盖，不把其中一个场景的结果推广到全部界面行为。

</details>

<a id="workload"></a>

## 负载与测量卡

可复现合成基准的输入由经过审查的固定常量或种子生成，记录维度、分布及代表性。字节数、记录数、并发度和可见对象数可能触发不同成本，不能只用一个总量替代。此类基准不依赖用户主目录、周边仓库、私有材料或实时外部服务。

真实外部链路另行验证，注明依赖、数据发送范围、已有授权、成本及副作用，并报告网络与服务波动、外部版本等可比性限制。合成基准与真实链路结果分别呈现，不把前者当作后者已经验证的证据。

获准查看私有材料时，只提取必要的聚合负载特征；不得把凭据、身份、真实路径、原始内容或可识别片段带入测试数据、日志、截图、PR、报告或其他产物。

| 测量卡字段 | 必须明确的内容 |
| --- | --- |
| 目标与约束 | 主要指标的单位、方向、代表性负载、判定依据，以及不可退化指标和允许波动 |
| 用户动作与完成点 | 生产入口、开始和结束事件、必须完成的工作，以及被替身替代的外部边界 |
| 输入与状态 | 维度、分布、种子或常量、冷态或热态 |
| 环境 | 准确修订、构建方式、运行时、硬件及并发干扰 |
| 时间 | 准备、排队、启动及外部开销的计入和排除 |
| 资源 | 完成点存活对象、基线、保留量与峰值、资源上限，以及适用时的垃圾回收策略 |
| 判定 | 原始样本、统计口径、比较方式及证据缺口；采用预算时记录适用依据，建设回归判定时记录负对照方式 |
| 行为 | 对应功能验证、允许差异与未覆盖范围 |

## 样本隔离与资源终点

冷启动或进程资源测量使用新的进程或项目认可的等价隔离方式，每份样本拥有独立临时资源。准备数据不得悄悄预热冷场景；热态测量说明保留了哪些缓存。为运行设置合理超时，成功、失败和取消后都等待自有任务退出并清理资源。

在同等输入、校验、完成条件和输出存活状态下比较基线与候选，不能将解析后丢弃与校验后保留的数据直接比较。对会干扰样本的自有 CPU 密集任务串行安排或提供有效资源隔离；独立 CI 作业不保证物理主机隔离，应记录共享运行器上的可比性限制。

按主要指标及受影响风险选择延迟、吞吐和资源测量，不要求无关场景执行全部指标矩阵。涉及内存或资源上限时，完成点的保留内存不能替代峰值或受限资源下的完成验证；按平台选择堆、进程驻留、外部分配或设备内存等指标，不能把含义不同的数值混用。即使只优化延迟，也须核对修改是否引入无界保留或改变资源释放责任，存在风险时补充对应资源验证。

<details>
<summary>内存采样与首次打开场景</summary>

运行时支持受控垃圾回收时，注明回收发生在何处及是否排除在计时外；保持需交付的对象可达，避免基线提前释放而候选保留。资源受限运行与正常时间采样分开解释，受限环境的额外开销不能冒充正常延迟。

涉及格式升级时，分别覆盖首次升级、升级后重开、只读准备和可写恢复。观察完整用户操作，避免通过推迟发布或恢复工作让某一阶段看似变快。

</details>

<a id="calibration"></a>

## 校准与预算

报告全部原始样本及实际用于判定的统计量，例如中位数、分位数、绝对值或缩放比率。样本数量、波动容差和阈值由目标场景的噪声与风险决定，不直接复制其他机器或历史项目的数值。

优化前后比较须确认版本、运行时、硬件、负载、环境干扰和统计口径可比，收益判断须有样本波动依据。可比条件下的调查和优化不要求先新建自动预算；缺少稳定性或可比性证据时只能报告观察结果及缺口，不能宣称收益已被证明。

采用性能预算时，在实际目标运行器、运行时和负载上建立依据。需要跨环境时间校准时说明参考环境、测量方式与适用范围；不得把时间倍率应用于字节数、对象数或无量纲比率，也不得把后端校准直接套用到浏览器。

自动门禁的预算必须位于受版本控制、可评审的配置或源码中，不能用环境变量悄悄覆盖。变更运行时、硬件、运行器或负载后重新核对可比性；预算调整有独立理由与证据，不能用放宽预算掩盖代码回归。没有可靠校准时只报告数字及条件，不能宣称已有有效预算或可靠门禁；手动诊断和自动运行均可与适用于当前条件的既有有效预算比较，并注明依据。

<a id="verdict"></a>

## 有效断言与失败判定

基准断言证明已到达真实完成点；详细语义由所属功能测试维护，避免计时中重复整套功能断言。准备失败、运行失败、超时和预算超限分别报告，不能把没有执行测量当作通过。

建立或修改性能回归检查的接受条件、失败路径或预算时，运行原始实现或受控负对照，证明目标回归会因预期的性能原因触发失败，并保留基线与候选的可比证据。对照在隔离环境完成，不破坏用户工作区或发布故意引入的回归；无法执行时记录原因、替代证据与缺口，不能声称已证明门禁有效。预算不能宽松到放过目标回归，也不能低于已验证的噪声下限；不得挑选幸运样本隐藏退化。

只运行已有门禁时，核对其版本、负载、环境、预算及已有负对照证据是否仍适用；未变且仍有效的证据可复用，不必每次重新构造回归。环境、负载或判定机制变化影响适用性时，重新验证相关预算与回归识别能力；项目明确要求每次运行的检查仍执行。普通调查或优化比较本身不要求新增自动失败阈值，但不能将没有回归识别证据的测量脚本称为有效门禁。

本地结果、CI 结果和历史报告分别标注版本与环境。校准依据、排除项及维护取舍随基准配置和测量结果保留；通用证据口径见[性能调查与证据](性能调查与证据.md)。
