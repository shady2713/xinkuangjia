# 文件上传与故障恢复

## 摘要

后端上传和浏览器直传均先建立持久化预约，再验证真实文件内容并登记元数据。最终 URL 保持公开且长期有效；预约和暂存对象不代表上传完成。数据库与对象存储使用独立资源，发生异常后由预约状态协调重试与清理，调用方不得因为请求报错就直接删除最终对象。

## 使用与限制

普通上传使用既有文件上传组件。上传成功以服务端完成元数据登记为准；失败显示为失败，切换账号会取消旧身份后续登记及界面写入。文件内容继续使用明确的后缀与 MIME 白名单，HTML 改名为文本、SVG 改名为栅格图片均不接受。

| 配置 | 默认值 | 口径 |
| --- | --- | --- |
| `FILE_UPLOAD_MAX_BYTES` | 10485760 | 单文件 10 MiB，可配置范围 1 字节至 32 MiB |
| `FILE_UPLOAD_DAILY_BYTES` | 209715200 | 每身份、每 UTC 日累计预约 200 MiB |
| `FILE_UPLOAD_DAILY_REQUESTS` | 100 | 每身份、每 UTC 日累计预约次数 |

失败、过期或未完成的预约也消耗当日预算，不能靠重试绕过限制。内部无用户文件 API 使用独立系统身份预算；HTTP 上传必须有认证用户。预算限制的是每日新增申请量，不是已保存文件的总存储配额。已保存文件的保留期限和业务删除仍由使用项目确定。

Servlet 单文件上限使用同一字节配置，整个 multipart 请求硬上限为 33 MiB。网关可以使用更低限制，不能据放宽网关参数推断应用限额已经放宽。现有字节数组下载入口上限为 32 MiB，大文件业务需另行提供经过验证的流式交付。

## 浏览器直传

直传要求浏览器能访问配置中的 S3 endpoint，并由对象存储单独允许管理站点的精确跨域来源、PUT 方法及返回的签名请求头。应用 API 的 CORS 配置不会自动配置存储桶。部署前需以实际浏览器验证预检、上传和完成接口，普通 HTTP PUT 测试不能代替浏览器跨域验收。

1. 请求上传预约时提交文件名、精确字节大小及可选目录。服务端从当前登录身份建立预约、扣减日预算，分配独立的暂存键和最终键。
2. 按响应中的上传 URL 和请求头发送原文件。URL 有效期五分钟，签名绑定字节大小、`Content-Type: application/octet-stream` 和 `Content-Disposition: attachment`；浏览器自动生成真实 Content-Length。
3. 对象上传成功后等待文件完成接口。服务端核对预约所有者、状态、期限和实际对象内容，再写入独立最终键及元数据。客户端回传的名称、大小、MIME 或 URL 不能覆盖服务端核实结果。
4. 完成接口成功后才使用最终 URL。同一预约重复完成返回原文件编号；文件删除后，重复完成不会重新创建它。

签名地址只允许写暂存键。即使有效期内重复 PUT，也不能覆盖已经登记的最终文件。暂存对象按附件输出，应用公开下载入口拒绝暂存路径；文件下载域名仍应独立于管理站点，不在公开桶存放私人资料。

## 升级与恢复

新装和升级均按[数据库迁移流程](数据库初始化与迁移.md)登记版本与校验和，[空库快照](../../数据库文件/basic_framework.sql)用于核对当前结构。已有库先停止旧上传写入口，核实目标和可恢复备份，再由独立 Flyway 入口执行[文件预约迁移](mysql-migrations/V202610020001__infra_file_upload_lifecycle.sql)，随后一起升级服务端及前端。迁移新增预约和预算表，不修改既有文件记录，不由应用启动自动执行，也不可绕过迁移记录直接重放。

预约先于对象写入独立提交。元数据与完成状态在同一数据库事务内提交；数据库已提交但响应传输失败时，重试或清理会读取已提交状态，保留最终对象。数据库回滚、进程中断和清理失败均保留预约记录。清理器每分钟读取最多 50 条到期记录，完成项只清理暂存对象，取消项清理最终对象与暂存对象；存储失败五分钟后再试，成功后每日再核对迟到对象写入。

不要手工清空预约表或把请求异常等同于数据库回滚。恢复时数据库、对象和配置需作为同一业务状态核对：只恢复旧数据库可能使新对象失去登记记录，只回退 JAR 不能撤销新协议的数据。正式恢复必须先在隔离环境验证，已有对象与预约记录的清理依据也要保留。

## 隔离验证

集成测试自行建立随机数据库和随机桶，使用生产 DDL、Mapper、Spring 事务及 S3 客户端。测试环境必须是专用环回 MySQL 与 MinIO，不能提供业务库或现有桶；缺少环境直接失败。环境变量由测试进程注入，不放在命令参数或版本控制文件中。

| 环境变量 | 用途 |
| --- | --- |
| `AUTH_TEST_MYSQL_URL` | 不带数据库名的环回测试 MySQL JDBC 地址 |
| `AUTH_TEST_MYSQL_USERNAME`、`AUTH_TEST_MYSQL_PASSWORD` | 仅有测试环境用途的数据库凭据 |
| `BF_TEST_S3_ENDPOINT` | 带显式端口的环回测试 MinIO 地址 |
| `BF_TEST_S3_ACCESS_KEY`、`BF_TEST_S3_SECRET_KEY` | 可管理随机测试桶的隔离凭据 |

在 [Java 工程](../../后端代码/basic-framework-boot/)执行：

```powershell
mvn -B -ntp -pl basic-framework-module-infra -am '-Dtest=FileUploadMySqlS3IT,FileServiceImplTest,FileControllerTest,FileUploadPropertiesTest' '-Dsurefire.failIfNoSpecifiedTests=false' test
```

在[管理前端](../../前端代码/basic-framework-admin/)执行：

```powershell
python -B -X utf8 scripts/quality/run_frontend_tests.py --suite unit apps/web-ele/src/components/upload/upload-direct.test.ts apps/web-ele/src/api/core/file.test.ts
```

核对 Surefire 与 Vitest 的实际测试数量、失败和跳过。数据库提交后异常、真实锁等待、存储清理失败、签名大小绑定、元数据伪造、重复完成和身份切换分别由用例观察；这些测试不证明整个应用、生产网关或所有浏览器场景已通过。

## 实现与运维边界

预约状态提供跨资源恢复依据，不能将其描述为跨数据库与对象存储的原子事务。终态记录持续参与迟到写入核对，长期容量和清理吞吐需要按真实上传量测量；当前没有自动删除终态记录或日预算历史的保留策略，运行环境应监测记录增长、清理积压和失败日志。
