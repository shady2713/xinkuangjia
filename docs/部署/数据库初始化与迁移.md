# 数据库初始化与迁移

## 摘要

数据库通过独立运维命令安装与升级，应用启动不执行迁移。新库没有管理员、示例组织、历史会话或运行日志；权限、菜单、字典等必需元数据由版本化 SQL 提供。已有库必须先核对目标和旧结构、完成备份恢复演练，再显式接入迁移历史，不能导入空库快照覆盖业务数据。

## 工具与凭据

使用 [独立 POM](../../scripts/database/pom.xml) 中固定的 Flyway Maven 插件 11.7.2、MySQL 扩展 11.7.2 和 Connector/J 9.7.0；版本与当前应用 BOM 对齐，工具不属于应用 reactor。需要 JDK 17 以上、Maven 和可访问的 MySQL 8.x。断网交付须在交付前准备并验证对应 Maven 依赖，不能只复制 POM。

由受控环境为本次进程注入 `FLYWAY_URL`、`FLYWAY_USER`、`FLYWAY_PASSWORD`。URL 使用明确的单个主机、端口和库名，不把密码放进 URL、命令参数、脚本或日志。迁移账号与应用运行账号分开，只授予指定库所需的 DDL/DML 权限；远程连接由部署环境配置并验证 TLS。

所有命令从仓库根运行。执行前先用 MySQL 客户端连接同一目标，核对 `SELECT DATABASE(), @@hostname, @@port, VERSION()`、已有表和备份位置；随后检查 `flyway:info` 显示的目标。不要使用来历不明的 `FLYWAY_*`、JVM 参数或个人 Flyway 配置覆盖项目设置。[Flyway 官方配置说明](https://documentation.red-gate.com/flyway/reference/usage/maven-goal)列出了环境变量和参数的覆盖顺序。

```powershell
mvn -B -ntp -f scripts/database/pom.xml flyway:info
```

项目禁用 `clean` 和自动 baseline，要求校验脚本名称、位置与已执行文件的校验和，禁止乱序迁移。此配置不替代运维授权与目标确认；不得通过命令参数关闭这些保护，也不使用 `repair` 掩盖校验和变化。

## 空库安装

先由部署者创建并确认独立空库，再执行迁移。数据库非空且没有迁移历史时，命令失败；不会自动把任意现有库认作项目基线。

```powershell
mvn -B -ntp -f scripts/database/pom.xml flyway:migrate
mvn -B -ntp -f scripts/database/pom.xml flyway:validate
mvn -B -ntp -f scripts/database/pom.xml flyway:info
```

首次安装依次执行初始结构、文件上传预约、短信来源与注册默认配置及 default 客户端授权修正，成功后 `flyway_schema_history` 记录实际脚本、版本、校验和及执行结果。再次执行没有待处理版本时不重复写入。版本化初始脚本是稳定的旧结构起点；[空库快照](../../数据库文件/basic_framework.sql)描述应用当前结构，两者通过真实数据库测试核对演进结果。

快照不含 DROP，也不含迁移历史，主要用于结构核对及隔离测试。正式新装选择版本化迁移入口，不先导入快照再无条件执行 `baseline`。管理员创建使用受控的一次性初始化入口；不能在 SQL 中补写默认口令或直接保存明文、单次 MD5。

## 创建首个管理员

使用本次构建的应用 JAR 运行[独立初始化入口](../../后端代码/basic-framework-boot/basic-framework-module-system/src/main/java/com/basicframework/module/system/bootstrap/AdminBootstrapMain.java)。该入口不启动 Spring、Web 或定时任务，不读取应用 `.env`，只连接本次显式指定的数据库。

| 进程环境变量 | 要求 |
| --- | --- |
| `BOOTSTRAP_JDBC_URL` | 明确的单主机 MySQL JDBC URL，必须包含库名，不得内嵌凭据 |
| `BOOTSTRAP_CONFIRM_DATABASE` | 与 URL 库名完全相同；连接后再次核对实际数据库 |
| `DB_USERNAME`、`DB_PASSWORD` | 此次初始化的数据库凭据，必须非空 |
| `BOOTSTRAP_ADMIN_USERNAME` | 4–30 位字母或数字，与现有登录用户名协议一致 |
| `BOOTSTRAP_ADMIN_PASSWORD` | 可选受控进程环境；省略时在真实终端无回显输入并再次确认 |

在仓库根运行，交付包中将 classpath 路径替换为同版本 JAR 的实际位置：

```powershell
java '-Dloader.main=com.basicframework.module.system.bootstrap.AdminBootstrapMain' -cp 后端代码/basic-framework-boot/basic-framework-server/target/basic-framework-server.jar org.springframework.boot.loader.launch.PropertiesLauncher
```

管理员口令使用明文输入，由命令适配当前登录协议后以 BCrypt 保存。要求 12–128 个 Unicode 码点，并至少包含大写、小写、数字、特殊字符中的三类；不接受控制字符或首尾空白，内部普通空格保持原样但不计类别。不得把口令放在命令参数、普通重定向 stdin、仓库文件或日志中；无真实终端且未注入口令时直接拒绝。

初始化只接受用户、用户角色、用户岗位和访问/刷新令牌表完全为空的身份库，逻辑删除或孤立记录也会拒绝。角色元数据中必须有同平台、启用的内置超级管理员角色。数据库锁串行化并发初始化，账号与角色关联在同一事务创建，不绑定示例部门，也不产生登录会话。

成功输出 `BOOTSTRAP_CREATED` 及用户编号，退出 0；配置/业务拒绝为 2、存储错误为 3、其他运行错误为 4。提交响应失败可能已经创建账号，先查询确认，不能通过清表重试。成功后清除临时口令环境，在真实登录入口验证账号；该命令不实现首次登录强制改密，也不能用于重置已有管理员密码。

## 已有库升级

首次接入仅支持已经核对与 [202610010000 初始结构](mysql-migrations/V202610010000__initial_schema.sql)一致的旧库：已有业务表，尚无上传预约表，短信 `create_ip` 为 15 字符，且没有 Flyway 历史。比较表、列、索引、约束、字符集和排序规则；旧库的账号、部门及文件行可以存在，历史自增位置无需与空库一致。结构不同、部分迁移已执行或来源未知时先调查，不选择一个版本号强行跳过。

停写并完成下节备份恢复验证后，首次接入显式执行一次：

```powershell
mvn -B -ntp -f scripts/database/pom.xml flyway:baseline
mvn -B -ntp -f scripts/database/pom.xml flyway:migrate
mvn -B -ntp -f scripts/database/pom.xml flyway:validate
```

baseline 只登记已经核对的旧结构起点，不执行初始 SQL，也不证明实际结构自动匹配。后续正常升级只执行 migrate/validate。已应用的版本文件不可改写；新增变化用新的唯一版本文件，并同步当前空库快照。

升级保留既有账号、角色关联、组织和文件数据。文件迁移新增预约与预算表；认证迁移扩大 IPv6 来源字段并关闭开放注册。客户端授权迁移收回 default 客户端的 client_credentials 授权，其余客户端配置不变。恢复服务前核对这些结果，并执行与改动相关的真实业务验证。MySQL DDL 可能隐式提交；中途失败后对象可能已经存在，失败记录必须先调查，不能假定整体回滚或继续重放。此限制由 [Flyway 的事务说明](https://www.red-gate.com/hub/product-learning/flyway/managing-database-changes-using-flyway-an-overview/)解释。

[202610020004 补救迁移](mysql-migrations/V202610020004__system_default_client_remove_all_machine_grants.sql)补齐 202610020003 只删除一个值及下划线通配符匹配的边界。它按 JSON 字面值移除有效数组中的全部 `client_credentials`，保留其他值、大小写差异及原顺序；重跑不改变已清理的数据。NULL、空串、非法 JSON 和非数组配置保持原值，需由运维另行核对；脚本以数据库 CHECK 约束断言有效数组的 `JSON_CONTAINS` 为 0，检查失败即阻止迁移成功。已应用 202610020003 的库继续执行新增版本，不改写其校验和。

若 202610020003 已误删 `clientXcredentials` 等非目标值，202610020004 无法从当前数组推回原配置；须核对迁移前的备份或配置记录，并在受控恢复中补回已确认的值。

## 收回机器主体会话

client_credentials 机器令牌以 `user_id=0`、`user_type=ADMIN` 落库。令牌校验只在 `user_id>0` 时核对真实用户状态，因此占位主体不受账号禁用约束；框架兜底的 `anyRequest().authenticated()` 会放行只要求登录的后台接口。当前框架采取以下止血措施：机器主体不再签发刷新令牌；刷新入口拒绝 `user_id<=0` 的存量刷新会话及机器哨兵值，即使尚未过期且客户端匹配也不能续期；default 客户端通过 202610020004 补救迁移精确收回全部 client_credentials 授权。

刷新拒绝同时保护升级前的凭据，但升级前已签发的机器**访问令牌**在其有效期内仍然有效，必须由人工在受控环境执行[作废机器主体会话](作废机器主体会话.sql)一次性收回。该脚本按框架逻辑删除约定置 `deleted=b'1'`，保留行记录以便核对与回滚，不做物理删除。

执行要求：

- 先完成本目录[备份与恢复](#备份与恢复)演练，确认目标数据库、主机与端口，并停写后执行。
- 按脚本内置的“前检”查询记录待作废数量与主键；执行后“后检”两个计数都应为 0，非 0 必须调查后再恢复服务。
- 框架以数据库为权威判定令牌有效性，但 Redis 中可能残留 `oauth2_access_token:{token}` 缓存键。作废后需同步清理这些键（`SCAN` 匹配后 `DEL`，不要在生产使用 `KEYS` 或 `FLUSHALL`），避免旧值被误读为有效会话。
- default 客户端配置变更同样受 `oauth_client` 缓存影响（默认 TTL 1 小时，见 `spring.cache.redis.time-to-live`）。变更后需清理对应 `oauth_client:default` 键，否则旧授权类型在缓存有效期内仍然生效。
- 回滚方式为按执行前导出的主键清单将 `deleted` 置回 `b'0'`；已被业务复用的记录需人工确认后再恢复。

## 备份与恢复

备份必须能在另一个新建空库恢复，才能作为升级的恢复依据。先停止应用写入和结构变更，核对业务表引擎为 InnoDB；`--single-transaction` 不保护并行 DDL 或非事务表。以下 Linux 示例中的主机、端口、用户、数据库和恢复库变量由负责人设置，`-p` 交互输入密码。

```bash
umask 077
mysqldump --no-defaults --protocol=TCP --host="$MYSQL_HOST" --port="$MYSQL_PORT" --user="$MYSQL_USER" -p --default-character-set=utf8mb4 --single-transaction --no-tablespaces --set-gtid-purged=OFF --hex-blob --routines --events "$MYSQL_DATABASE" > database-before.sql
sha256sum database-before.sql > database-before.sql.sha256
sha256sum -c database-before.sql.sha256
mysql --no-defaults --protocol=TCP --host="$MYSQL_HOST" --port="$MYSQL_PORT" --user="$MYSQL_USER" -p --default-character-set=utf8mb4 --database="$RESTORE_DATABASE" < database-before.sql
```

每步必须成功才执行下一步，导出非零退出或空文件不能算备份。恢复前单独确认 `RESTORE_DATABASE` 是授权新建的空库，且与源库不同；备份里的 DROP 只允许用于这一恢复目标。导出时不使用 `--databases`，防止恢复文件自带源库 USE 指令。备份包含敏感业务数据和凭据哈希，保存于受控仓库外目录。

恢复后比较全部表结构、行数及业务数据摘要，包含 Flyway 历史和自增状态，再验证相同版本应用的必要读写。升级中途失败时先停写，从升级前备份恢复到隔离新库核验，再由运维负责人安排切换；不得自动删除或覆盖原库。数据库、对象存储和应用版本需要共同恢复，文件故障边界见[文件上传协议](文件上传协议.md#升级与恢复)。

## 隔离验证

[迁移测试](../../scripts/database/tests/test_mysql_migrations.py)只接受带端口、无库名的环回 MySQL 地址，在专用测试实例中创建随机库，并在结束后只删除自己创建的库。它调用实际 Flyway、mysql 与 mysqldump，不模拟 DDL 或备份；缺依赖、缺环境或命令失败直接失败。

使用已有 pytest 环境，并安装固定 [PyMySQL 测试依赖](../../scripts/database/requirements-test.txt)。从仓库根执行：

```powershell
python -m pip install -r scripts/database/requirements-test.txt
python -B -X utf8 -m pytest scripts/database/tests/test_mysql_migrations.py -q
```

所需环境为 `AUTH_TEST_MYSQL_URL`、`AUTH_TEST_MYSQL_USERNAME`、`AUTH_TEST_MYSQL_PASSWORD`，与认证隔离测试一致。mysql/mysqldump 不在 PATH 时设置 `BF_TEST_MYSQL_CLIENT`、`BF_TEST_MYSQL_DUMP` 为真实可执行文件路径；不得传入业务数据库地址。Maven 从 PATH 获取。

覆盖新装结构等价、零账号、显式接管、升级保留数据、重复迁移、校验和篡改、DDL 中途失败、清库禁用、缺失脚本及备份真实恢复。default 客户端补救覆盖重复值、下划线干扰值、大小写差异、幂等重跑、非法 JSON、标量、近列长上限、低会话拼接上限恢复和后检真实失败，并从已应用 202610020003 的状态经 Flyway 升级到新增版本。用例通过只证明所用 MySQL 和客户端版本中的这些路径，不能替代目标生产环境或整个应用的恢复演练。
