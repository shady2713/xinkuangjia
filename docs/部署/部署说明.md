# basic-framework 服务器部署

## 摘要

在构建机生成Java JAR、管理前端dist和运行镜像，在目标服务器安装或复用MySQL、Redis、MinIO，再运行Java、前端与HTTPS入口网关。本文是仓库唯一官方部署路径：Linux服务器上的独立容器安装流程，不依赖个人开发目录、本地Compose或Jenkins脚本；已有中间件可按对应配置复用。

## 环境与交付基线

先确认Linux发行版、CPU架构、磁盘容量、Docker版本及外部访问域名。以下容器方式要求目标已安装可用Docker Engine；安装命令随操作系统选择，不能把某个系统的安装包用于其他发行版。断网服务器按[离线部署包](构建离线部署包说明.md)先准备安装资源。

| 组件 | 当前依据与要求 |
| --- | --- |
| JDK / Maven，构建机 | 编译目标Java17；兼容JDK、Maven3.8+；先用java -version和mvn -version核对 |
| Node / pnpm，构建机 | Node >=20.19.0；pnpm packageManager固定10.28.2，使用已有锁文件 |
| Java运行 | 当前Dockerfile使用eclipse-temurin:17-jre-alpine（非root用户appuser）；不修改源码编译目标 |
| 前端运行 | 当前Dockerfile使用nginxinc/nginx-unprivileged:1.27-alpine（非root用户，容器监听8080）；生产路径/admin/，hash路由 |
| MySQL | 框架使用8.x；安装示例mysql:8.0.46，版本变化须检查SQL与驱动兼容 |
| Redis | 安装示例redis:7.4.10-alpine；项目未固定补丁版本，换版本须复验 |
| MinIO / mc | 本文使用固定镜像摘要；对应MinIO RELEASE.2025-09-07T16-13-09Z、mc RELEASE.2025-08-13T08-35-41Z |
| 网络 / 数据 | 容器独立内网、数据库和对象持久卷、备份位置、真实TLS证书及域名 |

目标服务器运行应用镜像时无需Maven、Node或pnpm。示例固定镜像按linux/amd64使用；其他CPU架构须取得匹配镜像并独立验证。正式包登记镜像摘要和平台，不以可变标签代替版本证据，也不自动升级既有中间件。

## 仓库脚本与官方入口

本文是仓库唯一的官方部署路径：

- [http-client.env.json](../../后端代码/basic-framework-boot/script/idea/http-client.env.json)及其[说明](../../后端代码/basic-framework-boot/script/idea/README.md)是IntelliJ IDEA HTTP Client的本地调试环境，令牌由使用者在本机填写，不参与服务器部署、镜像构建或交付包制作。

## 构建应用

构建机使用同一源码版本完成后端与前端验证，再装配镜像。以下SOURCE_ROOT由部署者设为源码根，RELEASE为本次发布标识。

```bash
export RELEASE=your-release
cd "$SOURCE_ROOT/后端代码/basic-framework-boot"
mvn -q -Pquality-gate verify
docker build -t "basic-framework-backend:$RELEASE" basic-framework-server

cd "$SOURCE_ROOT/前端代码/basic-framework-admin"
pnpm install --frozen-lockfile
pnpm check:type
pnpm test:unit
pnpm build:ele
docker build -t "basic-framework-admin:$RELEASE" apps/web-ele
```

门禁与构建任一步失败就停止交付；其他适用前端检查按[脚本索引](../开发指南/脚本使用索引.md)执行。JAR为 `basic-framework-server/target/basic-framework-server.jar`，前端dist为 `apps/web-ele/dist`。前端 `pnpm build:docker` 串联构建与镜像装配，默认标签basic-framework-admin:local仅用于该脚本，正式交付另打版本标签。

[Java Dockerfile](../../后端代码/basic-framework-boot/basic-framework-server/Dockerfile)的构建上下文是server模块；[前端Dockerfile](../../前端代码/basic-framework-admin/apps/web-ele/Dockerfile)的上下文是apps/web-ele，两者只复制已有产物，不在目标机编译源码。记录JAR/dist/镜像及SQL的SHA-256和版本，实际秘密不打包。需要跨机器传送镜像时使用docker save/docker load，见离线说明。

## 准备目录与配置

在目标服务器准备独立发布目录。以下/opt路径与域名是布局示例，应替换为现场位置；RELEASE须与构建机一致。

```bash
export DEPLOY_ROOT=/opt/basic-framework
export RELEASE=your-release
install -d -m 700 "$DEPLOY_ROOT/config" "$DEPLOY_ROOT/backup"
install -d "$DEPLOY_ROOT/release" "$DEPLOY_ROOT/gateway"
docker network create basic-framework-net
```

已存在同名网络时先检查是否属于本框架，不重复创建或删除其他网络。将本次SQL放入release/basic_framework.sql，把应用镜像导入目标。配置文件在仓库外管理，以受控编辑器填写，chmod 600限制秘密文件访问。

创建config/mysql.env，以下密码字段必须填入现场生成的非空值，空值不能用于首次初始化：

```dotenv
MYSQL_DATABASE=basic_framework
MYSQL_USER=framework
MYSQL_PASSWORD=
MYSQL_ROOT_PASSWORD=
```

创建config/minio.env，填写现场MinIO管理凭据，不复用其他项目秘密：

```dotenv
MINIO_ROOT_USER=
MINIO_ROOT_PASSWORD=
```

创建config/redis.conf，替换占位密码；配置文件不会由应用自动生成：

```text
bind 0.0.0.0
protected-mode yes
appendonly yes
dir /data
requirepass <现场Redis密码>
```

Java的config/backend.env按[环境样例](../../后端代码/basic-framework-boot/.env.example)填写真实值。下面列出同容器网络方式的关键参数，密码与中间件配置一致，域名替换为现场站点：

```dotenv
SERVER_PORT=48080
```

`.env.example` 仅保留已在 `application.yaml` 实际绑定的环境变量。应用无自动数据库迁移；需要调度或跨域调整时使用实际 Spring 属性或 `basic-framework.web.cors-allowed-origins`。Quartz 默认配置未接入 JDBC JobStore，`infra_job` 表不等于 `QRTZ_*` 调度持久化。

## SM2 密码传输与首次改密

管理后台登录、重置密码、个人改密和管理员创建/重置密码都要求把密码加密为 SM2 密文后提交。服务端只配置私钥，公钥通过 `GET /admin-api/system/auth/sm2-public-key` 下发；私钥缺失或格式错误时应用拒绝启动。

生成现场密钥（示例输出不得提交）：

```bash
openssl ecparam -name SM2 -genkey -noout -out sm2-private.pem
openssl ec -in sm2-private.pem -text -noout
```

把 `priv:` 后的 64 位十六进制值填入 `config/backend.env` 的 `SM2_PRIVATE_KEY`，文件权限保持 `600`。不要将私钥写入 `application.yaml`、镜像、SQL 或发布包。修改私钥后重启后端并刷新管理页面。

初始化 SQL 不包含管理员明文密码，也不提供默认口令。部署负责人必须通过受控流程写入管理员 BCrypt hash，并保留该账号的 `password_change_required=1`；管理员创建用户或重置密码后，用户首次登录会被强制跳转修改密码。`system.user.init-password` 也必须由管理员设置符合等保二级策略的值后再执行用户导入。

详细协议、配置项和会话策略见 [SM2 密码传输与密码策略](../开发指南/SM2密码传输与密码策略.md)。

## 安装中间件与初始化数据库

以下命令只用于新的独立实例；已有库与数据卷不得用初始化流程重建。MySQL、Redis和MinIO不发布公网端口，只由应用内网或HTTPS网关访问。

在联网构建机上用 [MinIO 镜像定义](../../tools/minio/Dockerfile) 构建同版本服务端和客户端，再将镜像交付到目标机。构建会核验官方发布资产的 SHA-256。离线安装按离线说明加载镜像并保留对应标签。

```bash
docker build -t "basic-framework-minio:$RELEASE" "$SOURCE_ROOT/tools/minio"
export MINIO_IMAGE="basic-framework-minio:$RELEASE"
export MC_IMAGE="$MINIO_IMAGE"
```

```bash
docker run -d --name basic-framework-mysql --restart unless-stopped --network basic-framework-net --env-file "$DEPLOY_ROOT/config/mysql.env" -v basic-framework-mysql-data:/var/lib/mysql mysql:8.0.46 --character-set-server=utf8mb4 --collation-server=utf8mb4_unicode_ci
docker run -d --name basic-framework-redis --restart unless-stopped --network basic-framework-net -v basic-framework-redis-data:/data --mount "type=bind,source=$DEPLOY_ROOT/config/redis.conf,target=/usr/local/etc/redis/redis.conf,readonly" redis:7.4.10-alpine redis-server /usr/local/etc/redis/redis.conf
docker run -d --name basic-framework-minio --restart unless-stopped --network basic-framework-net --env-file "$DEPLOY_ROOT/config/minio.env" -v basic-framework-minio-data:/data "$MINIO_IMAGE" minio server /data --console-address :9001
docker logs basic-framework-mysql
docker exec -it basic-framework-redis redis-cli --askpass PING
docker logs basic-framework-minio
```

MySQL日志出现ready for connections，Redis输入现场密码后返回PONG，MinIO日志无初始化错误，再继续。MySQL镜像的MYSQL_*只在空数据目录生效，改env不会重置已有账号密码。

核对[SQL](../../数据库文件/basic_framework.sql)中的库名、DROP/CREATE语句和版本；当前导出含DROP TABLE，仅向授权空库导入：

```bash
docker cp "$DEPLOY_ROOT/release/basic_framework.sql" basic-framework-mysql:/tmp/basic_framework.sql
docker exec -it basic-framework-mysql mysql -uroot -p
```

在MySQL交互界面输入现场root密码，执行：

```sql
USE basic_framework;
SOURCE /tmp/basic_framework.sql;
SHOW TABLES;
SELECT username, user_type, status FROM system_users WHERE deleted = 0;
```

用户、角色与菜单的平台类型应匹配认证入口。框架不公布默认口令，账号与初始密码由数据库提供者或部署负责人通过受控流程交付，并在首次登录后强制修改；不用直接SQL重设密码替代账号管理。

默认混合模式保留旧公开 URL。网关、桶策略和后端统一保留以 ASCII 空格开头的键，以及首段为 `private`（忽略 ASCII 大小写、允许后跟 ASCII 空格）的键。`private-assets/` 与 `public/private/` 仍按公开路径处理。

新建或复用桶时，先生成与后端 `MINIO_PUBLIC_ACCESS` 对应的策略，再用包含 `mc` 和 `jq` 的本次交付镜像应用并读回。先停用旧公开入口或保持目标网关未启用。读回或配置校验失败就停止升级，待桶和后端配置一致且私有访问验证通过后再放行新网关。

```bash
MODE=mixed  # MINIO_PUBLIC_ACCESS=false 时此处设置为 private
python -B -X utf8 "$SOURCE_ROOT/scripts/runtime/render_minio_bucket_policy.py" --bucket basic-framework --mode "$MODE" > "$DEPLOY_ROOT/config/minio-policy.json"
docker run --rm -it --network basic-framework-net \
  --mount "type=bind,source=$DEPLOY_ROOT/config/minio-policy.json,target=/policy.json,readonly" \
  --mount "type=bind,source=$DEPLOY_ROOT/config/apply-bucket-policy.sh,target=/apply-bucket-policy.sh,readonly" \
  --entrypoint /bin/sh "$MC_IMAGE"
```

把本次 [策略应用脚本](../../tools/minio/apply-bucket-policy.sh) 放入交付目录的 `config/`，并在临时容器内按提示输入受控凭据。两个访问模式都执行同一读回流程。整桶私有模式用显式匿名拒绝替换旧桶策略，并保留经过授权的签名访问。

```sh
set -eu
mc alias set framework http://basic-framework-minio:9000
mc mb --ignore-existing framework/basic-framework
sh /apply-bucket-policy.sh /policy.json framework/basic-framework
exit
```

应用通过已授权的 `/admin-api/infra/file/private/content` 或限时 GET 预签名接口提供下载。预签名默认 900 秒，有效期为 60 至 3600 秒。应用业务凭据只授予对应桶必需权限。混合策略超过 MinIO 20 KiB 上限时，选用较短的桶名或整桶私有模式。

后端通过 `MINIO_ENDPOINT` 在容器网内直连存储，`MINIO_PUBLIC_URL` 用于浏览器稳定公开链接。按 [网关片段](object-storage.conf) 将公开链接挂载到 `/files` 时，显式设置 `MINIO_SIGNING_ENDPOINT` 为同一浏览器可达的 HTTP(S) 根地址。限时 GET 和直传 PUT 使用该地址，网关原样转发签名路径、原始 Host（含非默认端口）和查询参数。旧配置的公开地址若是根地址或仅含桶名路径，可继续自动推导签名根地址。升级时验证公开文件仍可读取、私有文件只经授权访问、直传完成及限时链接到期。

## 启动Java与管理前端

Java与前端加入同一网络，后端名称必须和前端模板的basic-framework-backend一致。

```bash
docker run -d --name basic-framework-backend --restart unless-stopped --network basic-framework-net --env-file "$DEPLOY_ROOT/config/backend.env" -v basic-framework-backend-logs:/basic-framework-server/logs "basic-framework-backend:$RELEASE"
docker logs --tail 100 basic-framework-backend
docker run -d --name basic-framework-admin --restart unless-stopped --network basic-framework-net "basic-framework-admin:$RELEASE"
docker logs --tail 100 basic-framework-admin
```

先确认Java Started，再运行前端，避免Nginx上游DNS尚不存在。日志默认在Java工作目录logs，容器卷负责保留，轮转和备份另行配置。两个应用不发布主机端口，由下一节网关提供入口。

直接运行JAR只用于本机或临时排障，不构成第二条官方部署路径：工作目录放置受控.env，使用 `java -Dfile.encoding=UTF-8 -jar basic-framework-server.jar`，配置地址改为进程可达的中间件地址。若前端容器代理宿主机Java，加入 `--add-host basic-framework-backend:host-gateway`，并确认宿主机监听与防火墙。容器运行是本文的官方路径；JAR方式仅作临时替代，不在相同端口重复启动，也不随正式交付包发布。

生产构建VITE_BASE=/admin/、hash路由；运行配置从docker/app.config.js覆盖到站点根_app.config.js，API默认/admin-api，值对浏览器可见，禁止秘密。构建参数变更需重建dist，运行参数变更需更新配置制品并刷新页面。内层[Nginx模板](../../前端代码/basic-framework-admin/apps/web-ele/docker/nginx.conf)按最小权限仅代理管理API（`/admin-api/`）与OAuth2（`/system/oauth2/`）。模板仅接纳http/https转发协议及1至65535的十进制端口，其他值回退自身连接；外层网关必须覆盖这些头，不能直接转发用户伪造值。

## 配置HTTPS网关

取得真实域名和证书，将fullchain.pem与privkey.pem放在受控config/tls目录。下列域名只是示例，必须替换；私钥权限限制并独立保管。

将以下配置写入 `gateway/default.conf`，并把 [对象存储网关片段](object-storage.conf) 放在同一目录。示例使用桶 `basic-framework`。自定义桶时同时修改网关片段的路径、策略生成参数和后端桶名。

```nginx
server {
    listen 80;
    server_name admin.example.com;
    return 301 https://$host$request_uri;
}
server {
    listen 443 ssl;
    server_name admin.example.com;
    ssl_certificate /etc/nginx/tls/fullchain.pem;
    ssl_certificate_key /etc/nginx/tls/privkey.pem;
    # 单文件 50MB；55m 为 multipart 边界与表单字段预留开销，与内层 Nginx、Spring 配置一致。
    client_max_body_size 55m;
    include /etc/nginx/object-storage.conf;
    location /system/oauth2/ {
        access_log off;
        proxy_pass http://basic-framework-admin:8080;
        proxy_set_header Host $http_host;
        proxy_set_header X-Forwarded-Host $http_host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-Port $server_port;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
    location / {
        proxy_pass http://basic-framework-admin:8080;
        proxy_set_header Host $http_host;
        proxy_set_header X-Forwarded-Host $http_host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-Port $server_port;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

在网关配置与证书就位后，先做语法校验，再启用80/443入口：

```bash
docker run --rm --network basic-framework-net --mount "type=bind,source=$DEPLOY_ROOT/gateway/default.conf,target=/etc/nginx/conf.d/default.conf,readonly" --mount "type=bind,source=$DEPLOY_ROOT/gateway/object-storage.conf,target=/etc/nginx/object-storage.conf,readonly" --mount "type=bind,source=$DEPLOY_ROOT/config/tls,target=/etc/nginx/tls,readonly" nginx:1.27-alpine nginx -t
docker run -d --name basic-framework-gateway --restart unless-stopped --network basic-framework-net -p 80:80 -p 443:443 --mount "type=bind,source=$DEPLOY_ROOT/gateway/default.conf,target=/etc/nginx/conf.d/default.conf,readonly" --mount "type=bind,source=$DEPLOY_ROOT/gateway/object-storage.conf,target=/etc/nginx/object-storage.conf,readonly" --mount "type=bind,source=$DEPLOY_ROOT/config/tls,target=/etc/nginx/tls,readonly" nginx:1.27-alpine
```

已有80/443网关时复用其站点配置，不另起冲突容器；只把上述应用、文件路径和转发头并入实际代理。确保仅受信网关能访问内层前端与Java，不能直接相信公网客户端提供的X-Forwarded头。后端会从右向左解析 `X-Forwarded-For` 并跳过私网代理节点，因此仅由最外层边缘网关设置 `X-Real-IP` 与追加 `X-Forwarded-For`，内层容器 Nginx 禁止覆盖 `X-Real-IP`。证书续期、入口防火墙、访问日志保留与上传大小由现场维护。

## Redis 降级与短信能力边界

### Redis不可用策略

`REDIS_UNAVAILABLE_STRATEGY` 当前默认 `local-fallback`，可选 `fail-closed`，作用于登录失败锁定、短信登录限流和令牌空闲校验。默认值不在本文修改；部署时按实例数量和安全要求选择：

| 策略 | 行为 | 适用场景与风险 |
| --- | --- | --- |
| `local-fallback`（默认） | Redis读写异常时，登录失败锁定和短信登录限流改用当前实例的有界内存计数（最多10000条，带TTL）；单实例内仍能约束连续尝试 | 可用性优先，避免Redis短时故障阻断全部登录。风险是多实例计数不共享，攻击者可分散到不同实例；实例重启或切换后计数和锁定状态丢失 |
| `fail-closed` | Redis不可用时锁定检查按已锁定处理，登录和短信登录被拒绝 | 安全优先，适合多实例、强安全或等保要求。代价是Redis故障期间登录不可用，需要持久化、高可用、监控和恢复演练 |

令牌空闲校验不跟随该策略：Redis不可用时无法可靠读取跨实例的活动标记，始终按失败关闭返回401，避免空闲限制被绕过。SM2 nonce防重放同样始终失败关闭；只有显式设置 `SM2_REPLAY_CHECK_ENABLED=false` 才退化为仅时间戳校验，并在启动时告警。完整行为、配置项和取舍见[Redis 不可用时的行为](../开发指南/SM2密码传输与密码策略.md#redis-不可用时的行为)。

### 短信能力边界

- 发送侧按手机号执行发送间隔和每日上限（`basic-framework.sms-code`）；`SMS_LOGIN_LOCK_IP_MAX_FAILURES` 是短信登录失败锁定的IP维度。
- 短信回调入口 `/admin-api/system/sms/callback/{aliyun,tencent}` 强制执行 HMAC-SHA256 签名与时间戳窗口校验（通过 `basic-framework.sms-callback.secrets.ALIYUN`、`basic-framework.sms-callback.secrets.TENCENT` 与 `basic-framework.sms-callback.timestamp-tolerance` 配置）；未配置对应渠道签名密钥或验签失败时默认失败关闭并返回 403。
- 短信通道、模板、签名、回调验签密钥和回调地址需现场配置并完成真实发送验证；应用构建通过不代表短信链路可用。

## 验收与故障排查

访问现场域名的/admin/，先检查资源和接口，再验收业务。不要把401响应当作认证成功，也不把端口存在当作全栈健康。

```bash
curl -I https://admin.example.com/admin/
curl -I https://admin.example.com/_app.config.js
docker logs --tail 100 basic-framework-backend
docker logs --tail 100 basic-framework-admin
docker logs --tail 100 basic-framework-gateway
```

_app.config.js应禁止缓存，静态资源路径匹配/admin/。通过页面完成验证码、现场账号登录，检查/admin-api/system/auth/get-permission-info返回code=0及用户、角色、菜单和权限码。用未授权账号验证关键操作拒绝；用允许类型的测试文件验证上传、元数据列表和返回URL读取。短信、OAuth2与定时任务按现场配置另验，JAR或静态构建不会自动证明这些链路可用。

| 现象 | 优先定位 |
| --- | --- |
| Java配置绑定失败 | backend.env空值、引号、实际变量名、MinIOsecure布尔和region |
| 数据库认证/表错误 | 应用账号、库名、导入版本与主从地址 |
| 网关502 | 容器网络、上游名称、JavaStarted和前端Nginx日志 |
| 登录401/403或菜单缺失 | Token、平台类型、角色授权、组件映射与权限缓存 |
| 文件URL打不开 | MINIO_PUBLIC_URL与/files代理、桶公开策略、对象是否存在 |
| HTTPS重定向或回调错误 | 现场域名、ADMIN_UI_URL、证书与逐层X-Forwarded头 |
| 上传413或存储失败 | 两层网关限制、文件白名单、MinIO容量和桶权限 |

记录真实版本、命令、用例数量、失败、跳过和未验项。本文的安装步骤是部署操作规范，不代表已经在客户服务器安装验收。

## 停止升级与恢复

升级先保留旧镜像与配置，数据库结构或数据变化单独设计迁移与回滚方案；全新空库初始化统一使用 [`basic_framework.sql`](../../数据库文件/basic_framework.sql)。容器重启不重新初始化数据卷，不能通过删除卷升级应用。

停止应用用docker stop对应gateway、admin、backend容器；仅在确认本次实例身份后替换应用容器，保留中间件卷。升级顺序为备份、数据库兼容变更、装配新应用、验收；失败切回兼容镜像与配置。

数据库备份先进入本框架MySQL容器，交互输入密码：

```bash
docker exec -it basic-framework-mysql sh
mysqldump -uroot -p --single-transaction --routines --events --triggers --result-file=/tmp/basic-framework-before.sql basic_framework
exit
docker cp basic-framework-mysql:/tmp/basic-framework-before.sql "$DEPLOY_ROOT/backup/basic-framework-before.sql"
sha256sum "$DEPLOY_ROOT/backup/basic-framework-before.sql"
```

备份期间不并发改表结构，SQL备份含用户和令牌，受控保存。恢复先在隔离库验证；真实恢复前停止写入、确认目标，再docker cp备份入容器，用交互MySQL的USE目标库与SOURCE备份路径恢复。旧JAR回退不能替代数据库恢复，数据库导出不能恢复MinIO对象。

MinIO按现场备份策略保留对象、元数据与存储策略，在隔离桶校验恢复后再用于真实故障。不要对卷执行删除或清空作为排障。无数据库、对象与配置恢复证据时，只能说明应用版本可切回，不能承诺完整数据回滚。
