# 上游来源与许可证证据

## 摘要

本文只记录能在仓库内或上游公开地址核实的证据，并明确区分“已核实”“仅有派生迹象”“找不到证据”三种状态。管理前端保留了上游 Vben 的 MIT 许可证文件；Java 后端的错误码与业务错误文本与 `YunaiV/ruoyi-vue-pro` 高度一致，仓库根仍没有该来源的许可证、版权声明或第三方声明，交付产物中也没有随附许可证文件。**例外**：按 D7 授权，[最小固定上游证据快照](../测试与可靠性/来源证据/上游快照/README.md)已作为**证据材料**纳入版本控制，随附上游 MIT 许可证原文与哈希清单；这不改变仓库自有代码的声明义务状态。根许可证、来源声明和分发条件属于权利决定，本文不代替有权者确定。

## 仅有派生迹象：Java 后端

仓库内**没有**任何 Java 后端的许可证文件、版权声明、来源说明或第三方声明，`pom.xml` 也不含 `<licenses>` 或 `<organization>` 段。以下只是可核实的**派生迹象**，不构成授权证据：

| 核实方式 | 结果（2026-10-05） |
| --- | --- |
| 特征错误码比对 | 本仓库 `ErrorCodeConstants` 与上游 [ruoyi-vue-pro 的 system 错误码](https://raw.githubusercontent.com/YunaiV/ruoyi-vue-pro/master/yudao-module-system/src/main/java/cn/iocoder/yudao/module/system/enums/ErrorCodeConstants.java) 相比：本仓库 103 个 `new ErrorCode(码, 中文消息)` 常量中有 **85 个与上游逐字节一致**，例如 `1_002_000_000 登录失败，账号密码不正确` |
| 结构特征 | 模块命名（system / infra / core Starter）、表名前缀（`system_*`、`infra_*`）、`CommonResult`/`PageResult`/`BaseDO` 形态、`@ss.hasPermission` 权限表达式均与上游一致，包名由 `cn.iocoder.yudao` 替换为 `com.basicframework` |
| 全文检索 | 仓库内检索 `yudao`、`iocoder`、`芋道`、`若依` 均无命中，说明改名是完整的，**没有任何指向来源的线索留在仓库里** |
| 上游许可 | [ruoyi-vue-pro/LICENSE](https://raw.githubusercontent.com/YunaiV/ruoyi-vue-pro/master/LICENSE)：MIT，`Copyright (c) 2021 ruoyi-vue-pro`（2026-10-05 核对） |

需要明确：**“上游是 MIT”不等于“本仓库的派生作品已经完成声明义务”。** MIT 要求在所有副本或实质性部分中保留版权声明和许可声明，而当前仓库与交付产物都没有做到。是否存在其他来源、是否存在未公开的授权安排，本文无法判断。

## 分发条件与当前缺口

| 对象 | 当前状态 | 缺口 |
| --- | --- | --- |
| 管理前端源码 | 保留 Vben MIT 许可证文件 | 无 |
| 管理前端交付产物 | [构建离线部署包说明](../部署/构建离线部署包说明.md)要求清单登记源码版本与产物哈希；前端交付包包含 `交付清单.json`（提交、源码指纹、锁文件指纹、产物摘要） | 交付包与前端镜像均**不含许可证文件**，而交付物包含 Vben 派生的工作区源码构建出来的静态资源 |
| Java 后端来源证据快照 | 已按 D7 授权把**最小**固定上游证据快照纳入版本控制（186 个上游文件、1 份上游许可证原文、12 个 A1 本地比较输入），见[最小固定上游证据快照](../测试与可靠性/来源证据/上游快照/README.md) | 快照只覆盖来源判定真正消费的上游文件（上游仓库共 8744 个文件）；上游仓库的其余文件未纳入 |
| Java 后端源码 | 无许可证文件、无来源声明 | 来源许可与声明义务未落实 |
| Java 后端交付产物（JAR、`basic-framework-backend` 镜像） | JAR 内只有 `pom.properties`（groupId/artifactId/version），无提交修订、无来源声明 | 无许可证、无来源声明、无构建来源绑定 |

前端交付包的打包规则只接受带后缀的文件类型（见 [delivery_rules.py](../../前端代码/basic-framework-admin/scripts/tools/delivery_rules.py) 的 `ALLOWED`），而 `LICENSE` 没有扩展名，无法原样进入交付包；如要携带许可证，需要同时调整打包规则并重新验证交付范围。

<a id="missing"></a>

## 找不到证据的部分

- 找不到 Java 后端的许可证证据：没有 `LICENSE`、`NOTICE`、`COPYING`，也没有任何来源声明文件。
- 找不到根目录许可证：仓库根没有 `LICENSE`；`README.md` 与 `AGENTS.md` 只说明前端“基于 Vue Vben Admin”，没有说明后端来源。
- 找不到授权文件、采购合同或书面许可的记录：仓库内没有相关文档。
- 找不到第三方资源清单：`后端代码/.../resources/captcha/jigsaw/original`（7 张图）与 `resources/images/pic-click`（10 张图）没有来源与许可记录，需另行核实后再分发。
- 找不到上游版本对应关系：后端没有记录对应上游的版本号或标签；85 个一致错误码常量无法确定对应上游哪个发布版本。
- 未核实 Java 依赖树的许可证汇总：`mvn` 依赖的许可证需另行生成清单；本文没有做这项统计。
- 未核实字体与图标资源：前端产物包含 `.woff`/`.woff2`/`.ttf` 字体，来源与许可未在仓库内记录。

<a id="decisions"></a>

## 待有权者决定

1. **根许可证与后端来源声明**：是否为仓库根确定许可证、是否声明 Java 后端派生于 ruoyi-vue-pro 并随附其 MIT 声明。这属于权利决定，执行者无权代定。
2. **是否需要与上游权利人确认**：若项目认为现有派生关系需要额外授权或确认，应在发布前完成。
3. **交付物是否携带许可证**：是否把许可证（含第三方声明）作为交付包与镜像的一部分；前端如要携带，需要修改打包规则并重新验证。
4. **字体、图标与验证码图片等资源的来源核实**：确认可分发后再进入交付包。
5. **后端构建来源绑定的实现方式**：是否引入构建信息插件以记录提交修订与依赖指纹，或用运维登记的方式替代。
6. **快照分发范围的确认**：D7 已授权把最小快照纳入版本控制，但**授权的是证据用途**。是否把同一份上游正文进一步随交付产物（JAR、镜像、离线包）分发，仍需有权者确认；当前交付包不含上游快照。
7. **索引 `license_path` 的登记值**：`d12-source-index.json` 把许可证位置登记为 `yudao/LICENSE@ac022b15…`，而检查器按 `<仓库名>@<提交>/<上游路径>` 定位，该登记值不可解析、历史上从未被消费。快照按上游树真实位置交付许可证并登记同一指纹；是否把索引 `license_path` 改正为可解析形态，需要有权者决定（索引属派生数据，本轮未改写）。
