# 交付物第三方许可实查

## 摘要

本文按**交付物本身**盘点第三方组件与许可证文本，而不是按依赖声明推断。盘点入口 [license_inventory.py](../../scripts/license/license_inventory.py) 只读取本机已有的 Maven 仓库、已安装的 npm 包与交付物本身，不下载任何外部资源；读不到的许可证一律记为 `unknown`，不用推测值填充。

三个结论：**后端 JAR 打包了 192 个第三方组件、0 份随包许可证文本**；**前端交付包 188 个条目、0 份许可证或 NOTICE**；**仓库纳入的上游证据快照不随交付包分发**，其 MIT 原文只存在于仓库内。本文的盘点结果不构成合规结论，也不代表任何许可选择已获批准。

## 盘点口径

| 维度 | 口径 | 理由 |
| --- | --- | --- |
| 事实来源 | 交付物本身：后端 `basic-framework-server.jar`、前端 `.cache/release/前端交付包.zip` | 依赖声明只能说明"打算带什么"，交付物才说明"实际带了什么" |
| 组件坐标 | 从交付物**内部**的 `META-INF/maven/**/pom.properties` 读取 | 不按文件名反推，坐标以构件自身声明为准 |
| 许可证元数据 | 本机 `~/.m2/repository` 中该构件的 POM，沿父 POM 链继承 | 离线可核实；沿父链解析能把 Spring 生态大量继承声明纳入统计 |
| 读不到时 | 记为 `unknown` 并单列 | 许可证推断属合规判断，不属于事实盘点 |
| 自有代码 | `com.basicframework:*` 单独归类为 first-party | 自有模块没有许可证声明是**权利决定未决**，不是第三方合规缺口，两者必须分开统计 |
| 锁文件 | 只作为依赖树交叉核对 | 锁文件登记的是**全部**已解析依赖（含构建期与开发期），不等于交付物实际包含的组件 |

复现命令（仓库根，输出目录在仓库外）：

```bash
python -B -X utf8 scripts/license/license_inventory.py \
  --jar 后端代码/basic-framework-boot/basic-framework-server/target/basic-framework-server.jar \
  --frontend-archive 前端代码/basic-framework-admin/.cache/release/前端交付包.zip \
  --lockfile 前端代码/basic-framework-admin/pnpm-lock.yaml \
  --out /仓库外目录/license-inventory.json
```

本轮实测输出：后端 204 个组件、随包许可证文本 0 份；前端交付包 188 个条目、随包许可证文本 0 份；锁文件登记 2022 个包。退出码 **0**。

## 前端依赖锁文件核对

按 `pnpm-lock.yaml` 登记核对（`packages` 段，2026-10-07 实查）：

| 项 | 实测值 |
| --- | --- |
| 锁文件登记的包总数 | 2022 |
| 本地安装中读不到 `license` 字段的包 | 1467 |
| SHA-256 | 见盘点输出 `frontend_lockfile.sha256` |

读不到的主要原因是**平台可选依赖未在本机安装**（例如 `@ast-grep/napi-darwin-arm64`、`@ast-grep/napi-win32-*`），不是包本身没有许可证。这属于跨平台核验范围，需要联网在目标平台安装后重跑。

**口径提醒**：2022 是锁文件登记的全部已解析依赖，**包含构建期与开发期依赖**，不等于交付物实际包含的组件。静态产物不含源码映射，**无法从交付物本身证明其静态资源包含哪些第三方运行期代码**。要得到准确的运行期闭包，需要在构建期保留依赖到产物的映射，这属于新增构建能力，需要单独授权。

## 上游快照的分发义务

仓库已按 D7 授权纳入最小固定上游证据快照（`ruoyi-vue-pro@ac022b15…`，MIT，199 条哈希清单，含上游 LICENSE 原文 1 份）。本轮核对结论：

| 问题 | 结论 | 依据 |
| --- | --- | --- |
| 快照是否属于最终交付物的一部分？ | **不属于** | 后端 JAR 实查 204 个组件、0 份许可证文本；前端交付包实查 188 个条目、0 份许可证或 NOTICE。两者都不含快照目录，也不含上游 LICENSE 原文 |
| 上游 LICENSE 是否随包提供？ | **否** | 同上；上游 LICENSE 只存在于仓库内 `docs/测试与可靠性/来源证据/上游快照/ruoyi-vue-pro@ac022b15…/LICENSE`（SHA-256 `772daf1f…`，1080 字节） |
| 快照自身的 MIT 义务是否已履行？ | **在仓库内已履行** | 同目录存在上游 LICENSE 原文，满足「在所有副本中保留版权声明与许可声明」 |
| 这是否等于派生作品已完成声明义务？ | **不等于** | 交付产物中既没有根许可证，也没有上游来源声明。**这正是当前的分发缺口** |

**必须说清的一点**：MIT 要求「在所有副本或实质性部分中保留版权声明和许可声明」。当前交付物里没有任何一份声明，因此**从交付物角度看，Java 后端派生的分发义务尚未履行**；仓库内纳入快照只是保存了证据，不是履行了交付义务。

是否把上游 LICENSE 与来源声明随 JAR、镜像与交付包分发，属分发决定，见[待有权者决定](#decisions)。本轮不代定。

## 离线部署包流程的可执行性

[构建离线部署包说明](../部署/构建离线部署包说明.md) 描述的流程按步骤核对如下。**本轮没有执行其中的构建与安装步骤**，只核对可执行性与产出范围：

| 步骤 | 本轮是否执行 | 说明 |
| --- | --- | --- |
| `mvn -Pquality-gate verify` 与前端构建 | 否 | 属于其他代理的构建范围；本轮复用工作区已有的 JAR 与 dist |
| `docker build` 两个应用镜像 | 否 | 会产生大体积镜像，且与本轮的只读核查目标无关 |
| `docker save` / `docker load` 导出导入 | 否 | 需要构建机与目标服务器两套环境 |
| 逐文件 `sha256sum` 清单 | 否 | 依赖上一步产出的包目录 |
| 断网环境安装与验收 | 否 | 需要一台**断网的 Linux 服务器**；本机是联网开发机，不满足条件 |

**可执行的部分（本轮真实执行了）**：

1. 从交付物本身枚举第三方组件与许可证文本 —— `license_inventory.py`，退出码 0。
2. 前端交付包结构、类型分布、资源清单与 `交付清单.json` 登记信息的核对 —— 同上。
3. 上游快照在交付物中的存在性核对 —— 同上。

**不可执行的部分**：离线安装、断网验收、镜像导出导入、逐文件哈希清单。这些步骤都需要断网目标服务器或另一台构建机，**本轮如实标记为未执行**，不据本轮结论宣称离线部署已验收。

## 待有权者决定

1. **是否把第三方许可证文本与来源声明并入交付物**：涉及 JAR/镜像内容变更、前端打包规则变更（现规则不接受无扩展名文件），需要有权者决定范围与方式。
2. **57 个不可核实的组件如何处理**：联网核验、向上游索取，还是在发布前替换依赖。
3. **弱 copyleft / GPL 组件的实际选用条款**：需法务确认，尤其是 Logback（EPL/LGPL 双许可）、jsqlparser（LGPL/Apache 双许可）、jakarta.annotation-api（EPL/GPL2+CPE 双许可）。
4. **字体与图标资源的可分发性**：2 个字体与 3 个图像在确认可分发前是否排除出交付包。
5. **前端运行期闭包与产物的映射**：是否为构建期增加依赖到产物的可追溯能力。
6. **上游快照是否随交付物分发**：D7 授权的是**证据用途**纳入版本控制；随交付物分发上游正文是另一件事。
7. **仓库自有代码的许可**：见[自有代码许可决策材料](自有代码许可决策材料.md)，**本轮未代定**。
