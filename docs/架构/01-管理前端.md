# 管理前端架构

## 摘要

管理前端使用 Vue 3、TypeScript、Vite、Element Plus 和 Vben 组件体系，应用位于 `前端代码/basic-framework-admin/apps/web-ele`。前端从 Java 获取用户、菜单和权限码，通过统一请求客户端调用 system 与 infra API；共享组件和工程工具位于同一 pnpm 工作区。

## 工程与版本

页面开发主要修改应用源码；公共组件变化会影响其他消费方，应同时检查类型和对应单测。

| 路径，均相对前端工程根 | 用途 |
| --- | --- |
| `apps/web-ele/src/views/system`、`views/infra` | 系统与基础设施页面 |
| `apps/web-ele/src/api` | 接口函数、类型与 `request.ts` |
| `apps/web-ele/src/router`、`store` | 路由注册、动态访问与认证状态 |
| `apps/web-ele/src/adapter` | Element Plus、表单和表格适配 |
| `packages` | 权限、状态、请求、布局、主题及通用 UI |
| `internal`、`scripts` | Vite、Lint、TypeScript、构建与质量工具 |
| `apps/web-ele/docker` | 浏览器运行配置与生产 Nginx 模板 |

环境要求为 Node.js `>=20.19.0`、pnpm `>=10.0.0`，`packageManager` 固定 `pnpm@10.28.2`。根工作区标注 `5.5.9`；它是当前工程标识，不说明所有源码均与上游同版本相同。Vue、Vite、Element Plus、TypeScript 等版本按 [catalog](../../前端代码/basic-framework-admin/pnpm-workspace.yaml) 和[锁文件](../../前端代码/basic-framework-admin/pnpm-lock.yaml)维护，不独立升级应用内重复依赖。

## 配置来源

构建配置与浏览器运行配置有不同生效时机；修改后应检查实际页面取得的值。

| 来源，均相对 `apps/web-ele` | 生效方式 |
| --- | --- |
| `.env` | 通用 Vite 构建参数，包括 HTML 标题 |
| `.env.development` | 开发端口 `5175`、公共路径 `/`、接口地址 `/admin-api` |
| `.env.development.local` | 可选本机覆盖；文件被忽略，不保存服务端凭据 |
| `.env.production` | 生产公共路径 `/admin/`、hash 路由；变更须重新构建 |
| `docker/app.config.js` | 开发 `main.ts` 导入；生产生成为站点根 `_app.config.js`，改变后刷新页面 |
| `vite.config.mts` | 开发 `/admin-api` 代理到 `http://127.0.0.1:48080/admin-api` |

`useAppConfig` 在生产读取 `window._VBEN_ADMIN_PRO_APP_CONF_`；开发优先使用非空 `VITE_GLOB_API_URL`，否则读取同一运行配置。`VITE_UPLOAD_TYPE` 默认 `server`，验证码界面默认启用，默认密码为空。所有运行配置均对浏览器可见；存储秘密、OAuth2 client secret 和 Java 服务秘密不能写入这里。生产静态资源和代理要求见[部署说明](../部署/部署说明.md)。

## 新增页面与权限

菜单由后端返回，业务页面必须同时满足页面映射和角色授权，才会成为用户的可访问路由。

1. 在 `apps/web-ele/src/api` 增加明确的请求、响应类型和接口函数；通过 `requestClient` 调用，接口字符串不重复拼 `/admin-api`。
2. 在 `src/views` 增加页面，复用 `adapter` 与现有 Vben 表单、表格、弹窗或抽屉组合。页面中的编辑、删除等按钮使用与后端一致的权限码。
3. 在系统菜单中登记组件路径。例如 `views/system/user/index.vue` 对应组件地址 `system/user/index`；不能登记为另一项目路径或不存在的组件。
4. 将菜单和按钮权限分配给角色，再把角色分配给用户。目录菜单、页面菜单与按钮权限职责不同；只新增按钮记录不会产生页面路由。
5. 更新权限后重新登录或重新装配权限数据，检查页面、按钮及 Java 接口。前端隐藏按钮不能替代后端拒绝未授权请求。

完整 CRUD 的文件组合与组件约定查[Web 技能](../../.agents/skills/weetion-development-web-standards/SKILL.md)，不要用来源项目的 AI 页面作为默认业务模板。

## 请求与上传

页面通过统一客户端取得业务数据，上传方式决定请求经过 Java 还是直接到对象存储。

- `api/request.ts` 设置 API 基地址、Bearer Token 与语言头，处理 `code=0` 的结果拆包、401 刷新、过期登录和错误提示。不要在普通 API 函数中自行复制刷新或错误处理。
- 账号密码登录在认证 Store 中将密码做 MD5 后提交；这只是当前协议处理，传输仍需要 HTTPS，不能把 MD5 当作传输加密。
- 默认 `server` 上传通过 Java `/infra/file/upload`，返回长期文件地址。文件组件必须使用实际 API 类型和回包，不能把返回 URL 当作数据库 ID。
- `client` 直传先获取 `/infra/file/presigned-url`，PUT 到返回地址，再调用 `/infra/file/create` 登记元数据。预签名地址必须从浏览器可达，MinIO 要允许对应 Origin 与请求头的 CORS；上传到对象存储成功不代表元数据登记成功。
- API 协议加密默认关闭；启用时前后端算法、请求头和密钥参数必须一致。浏览器可见参数不能代替身份与权限检查。

## 启动与权限装配

`main.ts` 加载配置、初始化偏好和应用命名空间，再动态导入 `bootstrap.ts`。后者安装组件适配、国际化、Pinia、权限指令、路由及插件，并挂载应用。

## 验证与排查

在前端工程根执行 [README](../../前端代码/basic-framework-admin/README.md) 中的安装、启动和检查命令；业务变更要验证页面的实际接口。

| 现象 | 优先检查 |
| --- | --- |
| Vite 无法解析 `#/api/...` | 文件是否存在、路径大小写及导出；不要用关闭错误 overlay 掩盖缺失依赖 |
| 工具报原项目绝对路径不存在 | 安装脚本是否被跳过、工具 `dist` 是否从旧目录复制；执行 `pnpm -r --if-present run stub` 后重启 |
| 页面打开、接口 502/连接拒绝 | Java 48080 是否就绪，Vite 目标或生产上游是否可达 |
| 登录成功但页面不存在 | 权限接口返回的组件地址、前端页面映射、菜单状态、角色授权与平台类型 |
| 接口 401 或 403 | Token、刷新结果与后端真实权限；不要仅修改菜单可见性 |
| 文件列表有 URL、浏览器无法读取 | `MINIO_PUBLIC_URL` 的浏览器可达性、桶公开策略、HTTPS 混合内容和网络代理 |

`pnpm check:type`、`pnpm test:unit`、`pnpm build:ele` 分别证明类型、已声明测试与生产构建；`pnpm test:e2e` 通过 Turbo 分发任务，必须核对实际执行的测试数量，零任务不代表业务验收通过。完整工程门禁见[脚本索引](../开发指南/脚本使用索引.md)。
