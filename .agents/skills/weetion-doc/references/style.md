# 页面风格

<a id="summary"></a>

## 摘要

让文档便于扫读且不易误解的页面级风格要求：简短摘要、清晰准确的技术表达、可选的章节分隔线、保留章节标题可见的 `<details>` 折叠区，以及有节制的强调。包 README 示例按[参考选择规则](review.md#reference-example)确定。

## 简短摘要

普通人工页面以简短的“摘要”开头，极短文件、生成片段和特殊格式沿用[页面顺序](structure-hierarchy.md#page-order)中的例外：用一个简短、完整的段落，说明读者可以做什么或观察什么、为何值得关注、运行模型，以及最重要的边界。详细内容由目录和各章节承载；位置与章节顺序见 [structure-hierarchy.md](structure-hierarchy.md)。摘要的具体长度和计数方式遵循项目已有规范；没有规定时，以清晰表达用途和边界为准。

<a id="clear-technical-expression"></a>

## 清晰、准确的技术表达

语言遵循用户和目标项目要求，未指定时默认中文。保留标识符、命令、字段名、技术术语及必要原文；已有多语言维护要求继续适用，不因润色新增语言版本或配对流程。

专项润色、精简或表达评审时使用以下规则；普通局部修改只核对涉及的内容。先核实事实对应的版本、来源和用途，再判断如何改写，不能为了保留原句而保留已证实错误或过时的说明；暂时无法核实的内容标明疑点，不据此删除。

- 保留与当前主题相关且仍有效的主体、动作、条件、时机、顺序、义务强度、例外、失败后果和副作用。不能把“必须”改成“可以”，也不能把假设、提案或历史结论写成当前保证。
- 必要说明不足时补足。框架组成、模块职责、调用关系、源码定位、扩展位置和关键设计理由能帮助读者定位或避免误用时应保留；不能仅因可从源码查到就删除。完整细节由所属文档维护，局部保留读者完成操作和判断所需的信息及入口。
- 精简重复、空泛修饰和不增加信息的解释；保留能够防止误用或错误简化的理由、示例及可搜索的机制名称。字数更少本身不构成改进。
- 注释的必需内容由项目语言规范负责，README 结构由[包文档规则](review.md#package-readme-review)负责，决策记录由[Agent Note 规范](../../weetion-doc-archive-agent-notes/SKILL.md)负责。表达调整不能删去这些规则要求的内容；创作过程残留的专项识别使用[残留清理 Skill](../../weetion-doc-trim-cot-leakage/SKILL.md)。
- 修改后对照原文和事实来源，核对条件、否定、数值、顺序及失败结果未被遗漏或改义。生成内容从来源修改；测试数据、提示词和用户可见文案可能影响行为，按所属场景取得验证，不能仅凭文字检查判定等价。无法验证时报告缺口，保留尚无依据改写的内容。

<a id="expression-examples"></a>

### 改写示例

以下均为假设场景，只说明判断方法，不代表项目已有行为。实际改写须核实对应实现和文档。

| 场景 | 合适的表述 | 需要保留的信息 |
| --- | --- | --- |
| 异步清理 | “先请求任务取消，再等待后台任务结束，最后释放连接。” | 请求取消不等于任务已经结束，不能压成“退出时清理资源”。 |
| 框架定位 | “接口层接收请求，服务层处理业务；新增处理器的位置和注册入口见本模块源码映射表。” | 模块职责和定位入口有维护价值，不能压成“按现有架构实现”。 |
| 失败与例外 | “提交失败时保留待发送记录；认证失败须更新凭据后重试。” | 保留失败后的状态及重试前置条件，不能只写“失败时重试”。 |

<a id="section-separators"></a>

## 章节分隔线

章节分隔线是可选排版，不强制使用 `-----`，也不检查分隔线的空行或锚点前后位置。按页面阅读需要选择是否使用，已有分隔线可以保留。使用时留意 Markdown 渲染结果，例如紧接段落的横线可能被解析为 Setext 标题；项目解析器的专用格式另按实际约定处理。

<a id="foldable-content-sections"></a>

## 可折叠的内容章节

面向开发者的实现细节和已有开发笔记正文必须折叠进 `<details>`／`<summary>` 块，不以内容较短为由取消。章节标题及其锚点保留可见，只折叠标题下的内容。读者完成任务所需的操作、限制和警告保持在普通正文中可见。核对项目查看器支持该语法；不支持时说明格式冲突并按项目明确规则处理，不将无法渲染的标签视为折叠已生效。

在 `<summary>` 后留一个空行；顶层 Markdown 块不整体缩进成代码块，列表和代码示例保留自身需要的缩进。结束前留一个空行，再写 `</details>`。核对展开后的标题、列表、表格和链接可读，锚点有效。

在包 README 中，适用的“模型体验”章节放在“已知限制与暂缓工作”之前；不涉及模型交互时省略模型体验章节及目录项。开发笔记可省略，不限定为 H2 或 H3，也不要求位于限制章节内或页面末尾；设置时按同样的折叠规则处理。
