# 元数据与链接

<a id="summary"></a>

## 摘要

README 元数据是检索和模板选择接口，不是小型报告或广告。`kind` 字段必须对应已定义的类别和模板，分类依据文档用途及包的真实接口；字段遵循下方必填项和项目扩展规则。仓库链接应在项目实际使用的 Markdown 查看器中正确解析，目标文件、图片和锚点必须有效。

## README 元数据

包 README 和包组导览 README 必须以有效的 YAML 前置元数据开头。其他文档按项目规则及对应模板执行；本规则不改变技能自身 `SKILL.md` 的必填字段约定。

```yaml
---
description: "示例能力，面向正在选择、配置或调试该包的用户与维护者。"
kind: "package-reference"
---
```

`description` 和 `kind` 必须存在且为非空字符串。`description` 说明主题及适用场景，符合下方[描述质量](#description-quality)要求；`kind` 必须且只能填写一个已定义类别，不能用列表、多值或临时名称替代。

`name`、`audience`、`tags` 默认不添加；仅当目标项目的规则、元数据规范或实际消费工具明确要求时允许，并按其字段类型和取值约束核验。其他自定义字段须有明确用途和负责维护的规范；不复制易变的代码清单。除非项目规定其他拼写，键名使用小写和连字符；禁止重复键。

<a id="the-kind-system"></a>

## 类别体系

每个类别恰好对应一个明确模板，每个模板也对应一个类别；使用本技能内已有类别，或按下方规则完整定义的项目扩展类别。按文档用途、内容和真实接口分类，不根据固定目录或文件名推断。包组导览、类型变更确认、发布比较和历史格式参考承担不同用途，不能因为路径相似而混用。包 README 按以下事实判断：

1. 介绍包组或模块组、提供直接下属包导览的 README → `package-group`。
2. 包清单、构建或发布配置表明它组合多个组件形成分发包或预设 → `package-bundle`。
3. 公开入口供调用方直接引入和调用，主要职责是提供库 API → `package-library`。
4. 插件、服务或其他功能包 → `package-reference`。结合项目的加载机制确认真实接口；兼具多种接口时，以主要使用方式选择模板，并补充其他受支持入口。

| `kind` | 适用用途 | 模板 | 标准 |
|---|---|---|---|
| `package-group` | 包组或模块组的导览 README | [package-group.md](../templates/package-group.md) | 分组导览：介绍能力家族、列出其直接下属包、解释组合关系，并链接各包负责的细节。 |
| `package-reference` | 插件、服务或其他功能包的 README | [package-reference.md](../templates/package-reference.md) | 功能包约定：遵循[包 README 评审标准](review.md#package-readme-review)，说明接入、配置、行为及限制。 |
| `package-library` | 供调用方引入的库 README | [package-library.md](../templates/package-library.md) | 库约定：依赖获取、公开入口、调用方式及边界。 |
| `package-bundle` | 组合多个组件的分发包或预设 README | [package-bundle.md](../templates/package-bundle.md) | 组合包约定：实际安装和启用方式、组成关系、冲突及移除行为。 |
| `persistence-change` | 持久化格式变更确认记录 | [persistence-change.md](../templates/persistence-change.md) | 变更确认：来源版本、前后约定、兼容性决策及迁移验证；未验证结论明确标注。 |
| `persistence-release` | 明确发布版本间的持久化结构比较 | [persistence-release.md](../templates/persistence-release.md) | 历史观察：比较版本、范围、差异和来源证据；不以结构比较证明兼容性或迁移安全。 |
| `persistence-format` | 选定历史持久化格式的参考记录 | [persistence-format.md](../templates/persistence-format.md) | 格式参考：可定位的历史来源、完整结构及必要依赖定义、核验结果与覆盖缺口。 |

选择包模板前，先读取目标项目的包清单、公开入口、加载机制和构建配置，按真实使用方式核实类别。安装、依赖获取和调用命令取自项目实际工具，不由类别名称推导。

新增类别必须同时完成：说明用途、读者及与已有类别的区别；提供对应模板；登记类别与模板的映射，并定义可据实核验的分类条件及必需内容。已有自动检查覆盖分类时，同步更新规则；没有对应工具时，按相同条件人工核验并报告，不要求创建额外工具。不得使用尚未完成这些定义的类别。

<a id="metadata-verification"></a>

## 元数据核验

按以下项目逐项核验，不以“存在前置元数据”代替检查：

1. YAML 可解析为字段映射，分隔符完整，无重复键。
2. `description`、`kind` 均为非空字符串；描述具体、可检索，不能只是标题、宣传或章节清单。
3. `kind` 已定义且只对应一个可访问的模板；页面用途、包接口及必需内容与该类别一致。
4. `name`、`audience`、`tags` 存在时，能指出目标项目明确要求它们的规范或工具依据；扩展字段符合已有类型和取值约束。
5. 新增类别已具备用途、边界、模板映射和核验规则；已有自动检查同步更新。

项目或可用工具提供对应检查时执行自动检查；工具未覆盖的项目仍须人工核验。没有对应工具时逐项记录人工核验结果，不将人工核验表述为自动检查通过；已有必需检查无法运行时，如实报告未验证范围。

<a id="description-quality"></a>

## 描述质量

智能体会搜索前置元数据中的 `description` 值，在加载全文前筛选候选页面。每个值都应像技能描述一样编写：说明页面涵盖什么，以及读者何时应该打开它。使用一到两个具体句子，包含可搜索的领域术语，并与相邻内容的负责页面区分。不要概括每一节、宣称优越性、重复标题、作含糊宣传、保留变更历史，或写成技术状态报告。

良好示例：`说明会话日志存储的配置、读取方式和持久性边界，供部署人员与维护者选择、配置或排查日志存储时查阅。`

较差示例：`最先进、最强大、拥有大量优化的存储方案。`

<a id="repository-links-and-path-mentions"></a>

## 仓库链接与路径提及

保持链接目标可由机器检查，提及的路径相对于上下文。当前页面的菜单使用纯片段链接。外部资源使用完整 URL。

仓库内文件和图片使用相对于当前文档的有效路径；不要假定以 `/` 开头的链接表示仓库根目录。使用项目实际支持的 Markdown 链接与锚点语法，不依赖自动改写路径。代码中的示例占位路径应明确标注，不作为实际链接交付。

- **文件与图片：** 核对目标存在、大小写及路径编码正确；图片还须检查能否显示，并提供有意义的替代文本。
- **目录与片段：** 本页目录及跨页片段必须对应实际标题或显式锚点。标题生成规则有差异时，使用查看器支持的稳定锚点，并检查目标存在且无重复标识。
- **移动、重命名或删除：** 在同一次变更中修复受影响的入站链接、图片引用、目录和索引，不留下指向旧位置的引用。
- **核验：** 有链接或 Markdown 检查工具时执行对应检查；工具未覆盖的渲染、图片或锚点行为进行人工复核。缺失或无法验证的目标如实报告，不将未核验链接表述为有效。
