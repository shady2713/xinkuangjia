# 模板：persistence-format

本模板用于记录一个明确历史版本的持久化格式及完整结构证据。它描述选定检查点，不代替当前格式约定、版本差异比较或兼容性确认。位置、命名和格式版本标识遵循目标项目。

<a id="frontmatter"></a>

## 前置元数据

必须满足[元数据核验规则](../references/metadata-links.md#metadata-verification)，`kind` 固定为 `persistence-format`。

```yaml
---
description: "说明指定历史版本的存储格式、完整结构和来源证据，供读取历史数据或核查格式演变时查阅。"
kind: persistence-format
---
```

<a id="sections"></a>

## 章节

页面结构遵循[页面顺序](../references/structure-hierarchy.md#page-order)：标题默认中文，项目机器规则要求的标题保留；分隔线和开发笔记均可省略，不强制分隔线样式、空行和锚点前后位置，也不强制开发笔记数量、标题层级或末尾位置。已有开发者实现细节与开发笔记正文仍须折叠，必要操作、限制和警告保持可见。

1. **摘要：** 明确格式、历史检查点、适用数据范围及主要特征。
2. **目录：** 链接后续章节，保持锚点稳定。
3. **来源证据：** 记录可准确定位的版本、源码或发布产物，以及结构提取方法。区分开发中间状态、最终合并结果和正式发布；路径本身不足以确定历史版本时，补充项目支持的精确版本标识。
4. **格式特征：** 说明适用的记录布局、字段类型与约束、编码和版本识别方式。结构定义不能证明的读写行为应链接对应实现或权威资料，并区分已核实事实与未知信息。
5. **格式声明：** 列出格式标识、来源版本、根对象和覆盖范围，以及结构证据的位置。项目有机器声明、附件或摘要规范时严格遵循；没有时用明确字段或表格记录，不强制数字版本、特定字段名或固定附件格式。
6. **完整结构：** 在声明范围内保留完整字段、类型、约束及必要的依赖定义，或链接可稳定定位的完整历史产物。项目使用生成区域时遵循其实际标记和生成方式；无法取得完整内容时明确缺口，不能声称格式证据完整。
7. **验证与限制：** 记录实际执行的提取、完整性检查或人工核验方法、环境、结果及覆盖缺口。结构证据本身不能证明某个读写器会接受全部数据，也不能证明迁移安全。
8. **开发笔记（可选）：** 只保留非权威工作上下文，无内容时省略；位置和标题层级按正文组织。

<a id="maintenance-rules"></a>

## 维护规则

- 使用项目实际的权威格式资料、生成器和验证入口，保留要求的清单、摘要及附件；不为使用本模板引入一套额外生成工具。
- 生成器不能补造历史来源。保留原有可选字段、未知或不透明声明，不按当前实现补写历史结构，也不手改生成产物来满足检查。
- 完整性检查同时核对来源、根对象、依赖定义和附件一致性；没有对应工具时逐项人工核验并报告，不声称自动检查通过。
- 历史检查点的选择和覆盖策略按项目规定执行，不要求为每个整数版本创建文档。当前格式由当前权威资料维护，不通过复制当前定义来填充历史空缺。
- 历史证据按项目的记录或归档政策维护。更正时保留原始来源和更正依据；已冻结的历史快照保持不变。
