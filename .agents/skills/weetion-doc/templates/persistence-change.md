# 模板：persistence-change

本模板用于确认持久化格式变更及其兼容性决策，例如数据库结构、文件格式或序列化数据结构的变化。仅涉及运行时行为而不改变持久化约定的变更不属于本类。记录位置、命名和版本机制遵循目标项目；索引页不能代替具体变更记录。

<a id="frontmatter"></a>

## 前置元数据

必须满足[元数据核验规则](../references/metadata-links.md#metadata-verification)，`kind` 固定为 `persistence-change`。

```yaml
---
description: "说明具体持久化格式变更、受影响数据和兼容性决策，供实施迁移或维护读写兼容时查阅。"
kind: persistence-change
---
```

<a id="skeleton"></a>

## 骨架

页面结构遵循[页面顺序](../references/structure-hierarchy.md#page-order)：标题默认中文，项目机器规则要求的标题保留；分隔线和开发笔记均可省略，不强制分隔线样式、空行和锚点前后位置，也不强制开发笔记数量、标题层级或末尾位置。已有开发者实现细节与开发笔记正文仍须折叠，必要操作、限制和警告保持可见。

用下列章节记录必需事实。项目已有机器声明、结构定义、附件、摘要或校验格式时，严格按其规范生成和维护；没有时使用明确的文档字段及表格，不要求新增生成器或伴随 JSON 文件。

```markdown

<a id="declaration"></a>
## 变更声明

以下字段和对照表明确变更来源、范围及读写影响。

- 记录标识：按项目约定填写，供其他记录引用。
- 变更前与变更后来源：可定位的版本、源码或结构定义；首次引入或删除须明确标注。
- 影响范围：数据实体、文件或记录类型，以及受影响的读写方。
- 前驱记录：链接相关已确认记录；没有时说明本记录的基线来源。
- 版本决策：是否调整格式版本及其依据；项目没有独立格式版本时明确说明。

<a id="compatibility"></a>
## 兼容性与迁移

分别说明新读取方处理旧数据、旧读取方处理新数据的结果及适用条件。核对默认值、缺失或未知字段、约束、编码及语义变化，按实际涉及的情况记录证据。不能仅凭结构差异判定兼容。

需要迁移时，说明适用起止版本、执行顺序、失败恢复及回退条件，并链接实际迁移实现。不可回退或尚未验证时明确说明；不需要迁移时给出依据。

-----

<a id="verification"></a>
## 验证

记录实际执行的命令或人工核验方法、环境和版本、结果及证据位置。覆盖受影响的读写或迁移路径、关键边界和失败情况；未覆盖或无法执行的部分明确列出。
```

<a id="rules"></a>

## 规则

- 变更事实来自实际源码、结构定义、生成结果或可追溯的历史材料，标明来源和范围；不编造版本、字段、兼容性或迁移结果。
- 有项目生成器时，使用其实际命令，保留机器声明及完整产物，核对声明、结构定义与摘要一致；不手改生成结果或删除产物来绕过检查。
- 没有生成器时，逐项核对变更前后约定并记录证据，不将人工判断称为机器检测结果。兼容性或迁移安全缺少验证时，明确保留未验证结论。
- 已确认记录及前驱关系按项目历史记录政策维护；新变更新增后继记录。更正历史错误时保留原始来源和更正依据，不为匹配当前实现而重写历史证据。
