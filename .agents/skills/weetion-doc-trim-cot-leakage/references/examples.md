# 少样本泄露示例

本文件供判断有歧义时按问题读取对应章节，不要求每次局部修正或批量审计通读。教学场景用于说明判断原则，示例中的数字、接口、路径、议题和行为均为假定已核实的前提，不是目标项目事实。真实改写必须核实对应来源；无法核实时标明疑点，不照搬数据或补造保证。标为“泄露”的示例默认位于当前行为说明中，不能推广为对历史记录、复盘或审批记录的禁令。本文件刻意包含待清理措辞，[召回探针](recall-batteries.md)命中示例时仍须判断用途。

<a id="dead-citations"></a>

## 失效引用

<a id="decision-ordinal-with-a-committed-owner"></a>

### 有可交付归属文档的决策序号

**泄露：**“斜杠输入根据可见目录解析（决策 21）。”

**示例归属文档：**下方的[输入解析决策示例](#input-parsing-decision-example)是本文件内可定位的教学材料，用于演示引用方式，不声明目标项目存在这项决策。

**修复后：**“斜杠输入根据可见目录解析，依据见[输入解析决策示例](#input-parsing-decision-example)。”

序号无法帮助读者定位依据；决策名称和实际存在的文档路径或章节锚点可以。实际使用时应链接目标项目已维护的归属文档，而不是引用本教学材料作为产品依据。每个文件至少写明一次所属文档路径——支持链接的位置应使用链接——之后的提及可以只使用可搜索的名称。

<a id="input-parsing-decision-example"></a>

#### 输入解析决策示例

本示例假定输入解析器只根据当前可见目录识别斜杠项，避免将当前不可见的项作为可操作命令。这里的规则和理由共同构成前述引用的依据；真实文档必须以项目实际实现与决策为准。

<a id="decision-ordinal-without-an-owner"></a>

### 没有归属文档的决策序号

**泄露：**“注册表拒绝重复名称（决策 7：名称是扁平的，没有命名空间）。”

**修复后：**“注册表拒绝重复名称；名称是扁平的，没有命名空间。”

本例已确认目标版本及本次交付中没有“决策 7”的归属文档，但名称规则可以从实现核实，因此移除失效引用并保留事实；仅因无权限访问来源时，不能作出同样判断。

<a id="audit-item-codes"></a>

### 审核项目代码

**泄露：**“渲染是纯函数：相同快照得到相同字符串（审核 R3）。”

**修复后：**“渲染是纯函数：相同快照得到相同字符串。”

仓库中没有审核文档；该代码只是纯粹的会话速记，不承载任何命题。

<a id="section-numbers-of-uncommitted-drafts"></a>

### 未纳入交付的私人草稿章节编号

**泄露：**“分层遵循设计（v2 §3.2）：`src/core/` 是纯核心。”

**修复后：**“分层：`src/core/` 是纯核心。”

本例假定草稿仅存在于私人会话且不纳入交付，而核心目录的职责已从实现核实，因此移除失效指引并保留职责。若设计文档在同次变更中交付且章节可定位，可以直接引用。外部标准也必须核实具体章节与主张相符，不能仅因写有 RFC 编号就认定有效。

<a id="plan-phase-labels"></a>

### 计划阶段标签

**泄露：**“`src/client/` 是外壳（T4）；P-I 迁移负责适配器。”

**修复后：**“`src/client/` 是外壳；适配器位于 `src/client/adapters/`。”

本例已核实适配器实际位于该目录，阶段代号只存在于私人计划中，因此用真实位置替换。尚未实现时必须保留提案状态，不能将计划改写成已交付路径。

<a id="stack-and-pr-vantage"></a>

## 堆叠和 PR 视角

<a id="stack-position-in-durable-prose"></a>

### 长期保留的文字中的堆叠位置

**泄露：**“未来的远端后端实现此接口（沙箱后端位于此堆叠中后续的 PR）。”

**修复后：**“远端后端可以实现此接口，无需修改渲染层。”

在长期行为说明中保留已核实的扩展点约定；具体实现仍未交付时，按项目约定将待办放在可定位的 PR、议题或记录中。PR 正文和依赖说明可以保留与任务有关的堆叠关系。

<a id="this-pr-in-a-readme"></a>

### README 中的“本 PR”

**泄露：**“本 PR 为会话列表新增基于游标的分页。”

**修复后：**“会话列表按游标分页。”

README 的寿命超过任何 PR；应将机制陈述为当前事实。

<a id="change-narration-and-version-stamps"></a>

## 变更叙述和版本标记

<a id="war-story-with-a-pr-number"></a>

### 带 PR 编号的故障往事

**泄露：**“颜色过去来自 `--widget-*` token，但没有任何地方定义它们，所以总是渲染回退值；别名 token 修复了这一问题（PR #88）。”

**修复后：**“颜色来自别名 token；未定义的 token 会渲染回退值。”

两项仍有效的事实——当前机制和持续存在的失败行为——都以现在时重新表述并保留。缺陷的来龙去脉属于 PR 及其 Agent Note。

<a id="removal-narration"></a>

### 移除叙述

**泄露：**“随着移除版本发布，`probe` 字段已消失；徽标现在沿用通用投影对。”

**修复后：**“徽标使用通用投影对。”

本例假定该段只说明当前渲染机制，旧字段没有仍需告知的兼容或迁移影响，因此可以精简。若读者需要迁移旧配置，字段移除、版本范围及替代方式仍须在迁移说明中保留。

<a id="fixed-regression--counterfactual-present"></a>

### 已修复回归 → 现在时反事实表述

**泄露：**“这过去会对多字节标签进行二次编码。”

**修复后：**“没有字节长度防护，多字节标签会被二次编码。”

本例已核实具体防护与失败条件；当前行为说明保留该约束，复盘或回归历史可保留故障发生及修复经过。不能仅凭“过去会出错”推导未经核实的防护机制。

<a id="indexical-version-stamps"></a>

### 依赖当时语境的版本标记

**泄露：**“本版的批量渲染是同步的；异步路径属于路线图工作。”

**修复后：**“批量渲染是同步的。”（暂缓事项放在调用点的 `TODO(widget-batch):` 中。）

这里“本版”没有明确指代，且未来工作已有可定位记录，因此当前行为说明可以直接陈述同步机制。版本明确的发布说明、协议标识或运行时时间可以保留这些词；尚无待办记录时，先确认后续工作是否真实存在及是否获准记录，不自动创建任务。

<a id="review-choreography"></a>

## 评审过程描述

<a id="review-verdicts-as-prose"></a>

### 将评审结论写进正文

**泄露：**“在评审中被否决：缓存已解析的规格。我们保留逐调用解析。”

**修复后（放在 Agent Note 的‘已考虑的备选方案’中）：**“**缓存已解析的规格。**否决：规格依赖每次调用的 cwd，因此按请求建立的缓存会提供陈旧的根目录。”

本例假定规格确实依赖当前工作目录。设计取舍以该事实为依据，普通正文不需重复评审过程；项目要求的审批或审计记录仍可保留有来源的人物、时间和结论。

<a id="draft-ordinals"></a>

### 草稿序号

**泄露：**“截至本笔记第 5 版，loader 还会校验 manifest。”

**修复后：**“loader 校验 manifest。”

已实现笔记陈述目标版本实际交付的状态。修订历史按项目现有版本或文档管理方式保存，不要求使用 Git，也不删除必要的审批或审计信息。

<a id="reviewer-addressed-justification"></a>

## 写给评审者看的辩解

<a id="arguing-a-cast"></a>

### 为类型转换辩护

**泄露：**“这个类型转换是安全的——对象由 SDK 构造，它只是没有足够严格地声明可选字段。”

**修复后：**“SDK 构造此对象时会填充每个可选字段；声明类型比运行时保证更宽松。”

本例必须先从对应 SDK 版本核实字段保证，不能仅凭“由 SDK 构造”推断所有字段存在。保留维护者需要的不变式，删除没有额外信息的辩护；理由尚未核实时报告疑点，不把假设写成保证。

<a id="appeal-to-review-authority"></a>

### 诉诸评审权威

**泄露：**“这是正确的，因为评审者已经确认了包装顺序。”

**修复后：**（删除；包装顺序已在函数的 `@returns` 中说明。）

技术正确性需要不变式、实现或测试证据，人的确认不能单独替代这些依据。必要审批与责任记录可在项目要求的位置保留，本例只删除当前接口说明中重复且无技术依据的认可表述。

## 复述与推导

<a id="control-flow-narration"></a>

### 控制流解说

**泄露：**“首先我们规范化标签，然后截断它，最后包装它。”

**修复后：**（删除。）

注释下面的三行代码已经表达了相同内容。

<a id="test-walkthrough"></a>

### 测试逐步讲解

**泄露：**“此测试创建一个会话，发送两条消息，等待第二次回复，然后断言日志中有四个条目。”

**修复后：**“两次往返必须恰好产生四个日志条目——投影会对共享前缀去重。”

只保留不明显的断言理由；逐步讲解是在复述测试主体。

<a id="hedges-and-planning-residue"></a>

## 含糊措辞和规划残留

<a id="unmarked-deferral"></a>

### 未标记的暂缓事项

**泄露：**“目前直接渲染应该没问题。”

**修复后：**（删除；暂缓事项已有对应的 `TODO(widget-batch):` 标记。）

本例假定已有待办真实对应帧内合并需求。没有记录时先确认问题、后续工作与授权；信息不足则报告疑点，不为了去掉含糊措辞而编造需求或自动添加 TODO。

<a id="vague-sizing"></a>

### 模糊的容量说明

**泄露：**“64 KiB 缓冲区对于大多数情况应该够用。”

**修复后：**“64 KiB 可以容纳已观察到的最大帧（48 KiB），并留有余量；更大的帧会在 `decode` 中明确失败。”

只有已核实容量、测量记录和超限行为时，才能如此改写。实际文档需提供适用版本、环境及测量方法的来源；没有这些证据时说明未验证，不从“应该够用”补造 48 KiB 或明确失败的事实。

<a id="authoring-language-slips"></a>

## 创作语言混入

**泄露：**“The renderer runs on the client 端; see the 设计稿 for spacing. ---- 私有 ----”

**修复后：**“The renderer runs on the client side; spacing follows the Figma frame `widget-badges`.”

本例假定目标文档要求英文，且已核实“设计稿”指向 Figma 画框 `widget-badges`；不能在没有证据时补造具体来源。这里未完成的语言片段与会话分隔符需要整理，但不能仅因出现中文就判定为泄露。Figma 画框名称、标识符、技术术语和必要原文应保留。

<a id="authoring-language-slip-inside-a-paired-fence"></a>

### 代码块中的未完成翻译

**待整理：**代码块内的 `// Return 前先释放锁`。本例假定目标项目要求中文注释，且已核实释放锁是返回前必须执行的操作。

**修复后：**`// 返回前先释放锁。`

保留“返回前”和“释放锁”的完整约束。先确认代码块是否来自源码或生成器，再修改其真实来源及受影响的引用；手写示例在授权范围内直接维护。语言选择和多处同步遵循项目实际要求，不要求存在两个语言文件，也不通用强制代码块逐字节一致。项目已有精确复制约定时继续执行。

<a id="behavior-visible-candidates"></a>

## 影响可见行为的候选项

**可疑内容：**一条接口注释写着“暂时可用”，生成器将它复制到模型可见目录中。

**错误做法：**在纯文字清理中只改写源句，或只手工编辑生成目录。

**正确做法：**在授权范围内追踪受影响的下游，更新源头并重新生成相关产物，执行所属场景的行为验证。已有快照及项目要求的界面验证随改动维护，不要求每个项目具备同一种验证设施。缺少对应场景或验证条件时，保持措辞不变并报告暂缓。

<a id="keeps"></a>

## 保留项

<a id="issue-references-are-durable-on-every-surface"></a>

### 议题引用须核实目标与用途

**保留：**“上限适用于包含包装层的完整渲染值（议题 #1470 负责后续工作）。”

本例假定已核实议题属于当前项目，内容确实对应该上限，且后续工作仍成立；实际文档在编号可能歧义时应提供完整链接。有效且与使用有关的议题可以留在 README，不必仅因它是议题就移动；无权访问或不能确认目标时，报告未核实，不能默认有效或直接删除。

<a id="dead-name-drops-are-not-naming-the-owner"></a>

### 失效的点名引用并不等于“指出归属文档”

**待核实：**“基于组件接口的徽标渲染器（参见组件渲染 RFC）。”

先查找目标版本及本次交付中的归属文档。存在且支持主张时补全路径；已证实指引失效时只移除失效引用，并保留可核实的渲染器职责。权限或访问条件不足时标明未核实，不把整句作为失效内容删除。

<a id="suppression-justifications"></a>

### 抑制检查的理由

**保留（修正后）：**`// oxlint-disable-next-line no-non-null-assertion -- the one-element literal guarantees index 0.`

这是使用对应检查器时的语法示例，不要求其他项目采用该工具。抑制仍存在时，必须保留已核实的理由；理由错误时查明真实依据，不能补造解释。抑制或对应机制已经移除且不再需要该说明时，可以同步清理。

<a id="measured-bounds"></a>

### 实测界限

**保留：**“深度上限（实测：512 层嵌套同步耗时约 0.15 秒；4096 层会阻塞循环）。”

这里的数字仅演示如何表述测量；实际使用须链接对应版本、环境、方法和结果。“实测”说明证据性质，不能省略后当作通用保证；环境变化或证据过时需要重新确认适用性。

<a id="runtime-oldnew-is-not-change-history"></a>

### 运行时的新旧状态不是变更历史

**保留：**“旧连接排空之后，新连接才开始接受请求。”

这里的“旧”和“新”指交接过程中两个存活的运行时对象。按语义区分运行时顺序与历史叙述；历史叙述也可在复盘、迁移和版本记录等适当位置保留。

<a id="runtime-natural-time-is-not-a-version-stamp"></a>

### 运行时自然时间不是版本标记

**保留：**“今天是几月几日？”

提示词询问的是运行时时钟；“今天”没有对比仓库状态。由于该文本会传递给模型，任何改写仍需所属的行为验证。

<a id="overcorrection-traps"></a>

## 矫枉过正的陷阱

以下示例展示可能丢失或扭曲事实的编辑方式，按实际疑点查阅。无论是否读取示例，精简段落前都须列举命题并核实依据。

<a id="flipping-an-obligation-into-an-endorsement"></a>

### 将义务改成认可

**原文：**“这些直接注册属于待迁移到 slot 的例外。”

**过度修正：**“这些直接注册是允许的例外。”

**正确：**“这些直接注册属于待迁移到 slot 的例外。”

“待迁移”是一项义务；“允许”是在认可现状。这次精简在缩短句子的同时反转了其模态含义。

<a id="promoting-a-hypothetical-to-a-shipped-feature"></a>

### 将假设提升为已交付功能

**原文：**“未来基于 IPC 的 shell 会继承执行器并重写 `spawn`。”

**过度修正：**“基于 IPC 的 shell 继承执行器并重写 `spawn`。”

**正确：**“假想的基于 IPC 的 shell——目前不存在这种 shell——将继承执行器并重写 `spawn`。”

仅删除未来标记，会将设计示例变成该类已交付的主张。应明确标注假设，而不只是取消未来标记。

<a id="deleting-a-true-fact-with-the-transcript-around-it"></a>

### 将真实事实与周围的过程记录一并删除

**原文：**“门禁通知解说检查顺序；通知文本也是 `verify-doc-typecheck` 编译时所依据的内容。”

**过度修正：**“……”（将整句话作为过程解说删除。）

**正确：**“通知文本是 `verify-doc-typecheck` 编译时所依据的内容。”

半句话是过程解说，另一半则是关键耦合关系。如果多个命题在同一行中，应按分句删除，而不是整句删除。

<a id="dropping-the-measurement-source-while-keeping-the-number"></a>

### 保留数字，却丢掉测量来源

**原文：**“4 MiB 上限来自实测：生成的最大 `py-types` 模块为 3.1 MiB。”

**过度修正：**“上限为 4 MiB；生成的最大 `py-types` 模块为 3.1 MiB。”

**正确：**保留“实测”。

没有“实测”，3.1 MiB 读起来像定义而非观察值，于是没有人会在提高上限之前重新测量。
