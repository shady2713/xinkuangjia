# 召回探针组

这些探针为[分类体系](../SKILL.md#taxonomy)提供候选线索，可能误报或漏报，不是禁用词表或自动删除规则。每个命中都须结合目标版本、文档用途及证据判断；还应阅读范围内相关的关键文字，不能将零命中当作全部内容正确。

<a id="invocation-rules"></a>

## 调用规则

- 先按 [输入与排除规则](../SKILL.md#scope-and-permissions)确定范围，并向命令传入实际目标路径；下方命令的 `...` 代表目标路径和适用排除项，不可省略范围后直接扫描整个仓库。范围涉及 `.agents/` 等隐藏目录时，添加 `--hidden --glob '!.git/**'`。
- 排除项放在最后，以免后续包含规则将它们重新纳入：`--glob '!vendor/**' --glob '!node_modules/**' --glob '!.agents/notes/archived/**' --glob '!.agents/skills/weetion-doc-trim-cot-leakage/**'`（本 skill 自身文件引用了泄露措辞作为校准材料），再加上经确认的依赖、构建产物、缓存及实际生成的测试数据、快照目录。手写 fixture 和快照按真实用途判断，不因名称一律排除。范围内的决策记录也可能引用待清理措辞作为证据；按[可独立定位的引用规则](../SKILL.md#resolvable-citations)判断其用途，不将示例引文直接当作实际残留。
- 自然语言模式行带上 `-i`，以便句首大写也能命中（“This PR adds…”、“Probably fine…”）；匹配代码模式的第一行保持大小写敏感——`-i` 会把 `\bT\d\b` 和 `\bP-I\b` 变成噪声。
- 为完整短语设置匹配边界。`\bthis PR\b` 必须匹配“this PR adds”，同时不能匹配“this project”“this process”或“this provider”。
- 采用新增或调整的探针前，用已知正例确认能够召回，用易混淆反例检查边界和误报。宽泛模式可能有意召回反例，须能按用途与证据识别并保留它们，不以反例全部零命中为通用通过条件；精确短语的匹配边界仍须满足上一条要求。
- 已有校准可复用，但须能核验当时使用的模式、匹配选项、工具及相关版本、样例和实际结果，并确认当前语言与语料类型仍在其适用范围内。探针或匹配条件改变、语料变化使原样例不再有代表性、结果出现无法解释的漏报或噪声，或缺少上述依据时，重新校准受影响的探针；不能仅凭记忆声称已经验证，也不要求每次任务重复仍有效的校准。
- 校准只证明这些样例下的召回与区分能力，不证明目标语料完整。零命中始终不能证明没有残留，仍须独立阅读关键文字；修改后复跑本轮使用且受修改影响的探针，对剩余命中逐项作语义判断。
- 根据用户与项目的语言要求及实际内容选择目标文件，不根据 `.zh.md` 等后缀认定语言，也不要求存在对侧文件。下方中英文探针是可选示例，按内容选择或调整，不要求每个项目运行全部探针。命中另一种语言本身不构成泄露；结合句意判断未完成翻译和会话残留，保留标识符、技术术语、原文引用及有意的多语言内容，避免用通用 ASCII 或中文字符匹配代替语义判断。

<a id="english-battery"></a>

## 英文探针组

```sh
rg -n --hidden '\(decision \d|\(audit [A-Z]\d|design §|plan §|design ledger|\(B ruling|\bP-I\b|\bW\d\b|\bT\d\b' ...
rg -n --hidden -i '\bthis PR\b|\bthis branch\b|\bthis stack\b|\blater PRs?\b|\bprevious commits?\b|\bthis commit\b' ...
rg -n --hidden -i '\bused to\b|\bno longer\b|\bpreviously\b|\bthe old\b|\bwas renamed\b|\bwas moved\b' ...
rg -n --hidden -i '\bv1\b|this cut|\bcut \d|\btoday\b|\bfor now\b|roadmap' ...
rg -n --hidden -i 'rejected in review|review round|reviewer|as of v\d' ...
rg -n --hidden -i 'probably |should be enough|should suffice|it simply|is safe —|is safe --' ...
rg -n --hidden '§\d' ...
```

<a id="chinese-batteries"></a>

## 中文探针组

```sh
# 在已确认包含中文内容的目标文件中寻找变更或评审叙述。
rg -n --hidden '评审|上一?轮|旧版|老的|不再|以前|本版|遗留' ...

# 仅在已确认以英文为主的 Markdown 中筛选可能的创作残留，逐项判断命中。
rg -n --hidden '设计稿|评审|上一?轮|旧版|老的|不再|以前|本版|遗留|私有|(^|[^a-zA-Z])端([^a-zA-Z]|$)' --glob '*.md' ...

# 仅用于已确认要求英文注释的目标文件；语言与注释语法按实际项目调整。
rg -n --hidden '(^[[:space:]]*(//|/\*|\*)|//|/\*)[^\r\n]*(设计稿|评审|上一?轮|旧版|老的|不再|以前|本版|遗留|私有|端)' --glob '*.{ts,tsx,js,jsx,mjs,cjs,css}' ...
rg -n --hidden '#[^\r\n]*(设计稿|评审|上一?轮|旧版|老的|不再|以前|本版|遗留|私有|端)' --glob '*.py' ...
```

<a id="known-false-positive-families"></a>

## 已知误报类别

以下是常见误报场景；须核实具体用途和证据后判断：

- **表示用途的“used to”**——“the key used to sign requests”（用于签署请求的密钥）表示用途，而不是时间。表示过去的形式前面会有一个主体状态（“colors used to come from…”，即“颜色过去来自……”）。
- **运行时旧/新状态**——“旧连接排空之后，新连接才开始接受请求”指的是交接过程中的存活对象，不是仓库状态。
- **流程文档中的“This PR”**——*关于* PR 工作流的文档（“the PR body should…”即“PR 正文应……”、模板、本仓库的流程笔记）合理地使用“PR”；当前行为说明通常应描述机制，而 PR 正文、发布及迁移说明可以按用途描述具体变更。
- **作为协议或路径片段的 `v1`**——`/v1/chat` 端点和协议格式名称是标识符，不是版本标记。
- **有可定位来源的 `§N`**——外部标准或纳入交付的文档可以按章节引用，包括同次变更的新文档；仍需核实该章节确实支持主张。
- **表示对比的“actually”和名词“wait”**——它们是普通英语用法，不是含糊措辞；当前示例探针未检测它们；扩展模式时仍需结合句意判断。
- **运行时的“today”和已记录的时间戳**——询问当前日期的提示词或测试使用的是自然时间，不是仓库版本标记；已记录的 CLI 输出保持其原有语气。任何传递给模型或用户的措辞，在编辑前仍须遵守行为验证规则。
- **有明确指代的版本用语**——发布说明中版本已明确时，“本版”或“本版本”可以使用；未说明所指版本的当前行为文档应补明范围或直接陈述机制，不按词形一律删除。
- **必要的审批与责任记录**——有依据的人物、时间和结论可在项目要求的记录中保留；技术正确性仍需独立证据，不能仅以人的认可证明。
- **‘已考虑的备选方案’章节**——Agent Note 的这类文体位置是“否决”的允许归属位置，不属于评审过程描述。
