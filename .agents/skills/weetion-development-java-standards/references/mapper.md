# Mapper 与查询选择

用于修改查询、更新条件或结果映射。

## 项目入口

普通单表 Mapper 沿用 `BaseMapperX<DO>`，优先复用 `LambdaQueryWrapperX`、`LambdaUpdateWrapper` 等现有能力。字段引用优先使用 Lambda，避免列名漂移；Mapper 返回 DO、标量或明确投影 DTO，不使用无约束 Map 承载稳定结果。

## 按查询语义选择实现

| 场景 | 选择依据 |
| --- | --- |
| 单表 CRUD、可选过滤 | 优先现有 Lambda Wrapper 与项目扩展 |
| 当前页附加展示信息 | 可先分页主结果，再按键批量补充 |
| 关联字段参与过滤、排序、聚合或 count | 用完整数据库查询表达，已有 MPJ 可用于类型化 Join |
| Wrapper 难以清楚表达的查询或数据库能力 | 在 Mapper 使用有明确入参与结果映射的自定义 SQL；沿用目标模块组织方式 |

Join、自定义 SQL、注解或 XML 本身不是架构例外，不要求统一审批；沿用目标模块的组织方式，不另建 Provider 框架。实际偏离项目约束时遵循[根规则](../../../../AGENTS.md)。

## 空输入与分页

- “查询这些 ID”的集合为空时返回空结果；可选筛选为空时按接口约定决定不筛选、无结果或拒绝输入，不能统一短路。
- 排除集合、权限允许集合和普通可选筛选语义不同。权限集合为空不能导致移除权限条件后扩大查询范围。
- 结合实际 Wrapper 行为验证空集合，避免意外省略条件、生成非法 SQL 或执行全范围更新。
- 常规列表复用项目分页类型并在数据库分页；`PAGE_SIZE_NONE` 只用于有明确数量上限的内部场景。关联查询核对一对多放大、去重和 count，不在分页后过滤造成缺项或错误总数。

## 写入与访问边界

新查询及自定义 SQL 核对逻辑删除、数据权限、租户或业务归属条件实际生效。常规查询不得绕过这些边界；具有专门授权的管理、归档能力使用清晰入口与最小范围，不通过全局关闭拦截器实现。

验证入口见[测试指南](testing-validation.md)，执行计划核对用于大表、高频或已知慢查询。
