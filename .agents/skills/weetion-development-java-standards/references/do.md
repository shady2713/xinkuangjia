# DO 与字段映射

用于新增持久化模型、修改列映射或处理读写不一致。

## 模型与生命周期

普通业务表使用明确 DO 和 `@TableName`。跨表投影、展示值和临时计算结果使用 DTO/VO，不以 `@TableField(exist = false)` 混入展示模型。

普通可修改实体、主数据和配置默认沿用 `BaseDO` 的审计与逻辑删除；关系、日志、记录及快照按生命周期选择字段和基类。新模型不继承 `BaseDO` 时说明生命周期即可。已有表沿用既定审计字段和删除方式，改变时作为兼容性变更处理。

## 主键与列映射

新建普通业务表默认使用 `Long id` 与 MySQL `bigint AUTO_INCREMENT`，显式 `IdType.AUTO` 与 DDL 一致时可用。外部协议或分布式生成等需要其他方案时，核对引用列与插入回填；已有表的主键变更按迁移处理。

DO、基线和数据库不一致时，先确认历史结构、灰度字段或生成列等原因，再决定映射和迁移；不通过字段别名隐藏未执行的迁移。

## 空值与复杂字段

字段更新策略遵循[接口的更新语义](api-controller-model.md#更新与兼容)；需要显式清空时，不得将未提供字段一并写成 NULL。结构稳定的 JSON 使用明确对象或泛型集合，动态扩展数据限定在对应适配范围。

历史 JSON 与逗号分隔字段按目标 DO、DDL 和消费者确认，不能仅凭集合类型推断存储协议。新增多值存储按查询与约束需要选择关系表或 JSON，不复制历史逗号字符串做法。字段注释按[注释标准](java-comments.md)说明业务含义和特殊存储口径。
