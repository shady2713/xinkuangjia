# Java 注释标准

生成、修改或评审 Java 注释前完整读取本文件。修改代码时同步核对受影响注释，测试代码同样适用；本文件是 Java 注释要求的唯一专项来源。

## 覆盖对象与内容

默认使用准确中文，保留必要协议名、代码标识和第三方术语。注释解释职责、业务原因和调用约定，不复述可直接看懂的赋值或调用动作。

| 对象 | 必需说明 |
| --- | --- |
| 所有显式类型：类、接口、枚举、注解和 record | 不区分可见性，均有职责 JavaDoc；public 类型及核心组件按作者规则填写准确作者 |
| 所有显式方法和构造方法 | 准确职责 JavaDoc；简单私有方法、getter/setter 和样板方法可用精确单句 JavaDoc |
| 模块与业务入口 | 说明各自用途与职责 |
| 公共 API、框架扩展点与复杂方法 | 在职责说明外，补全下文[调用契约](#方法与类型文档) |
| DO、VO 新增或修改字段 | 字段 JavaDoc，说明业务含义及必要的单位、可空性或数据口径 |
| DTO、record 组件、枚举与其他模型字段 | 业务语义、稳定编码及涉及的状态、协议或兼容要求 |
| 核心逻辑、业务接入点及边界分支 | 按下文[业务逻辑说明](#业务逻辑说明)解释实际规则 |
| 测试类、测试方法与辅助方法 | 所保护的契约及非显然测试设计，不将执行步骤逐句翻译成注释 |

Lombok、框架生成且源码中不存在的方法无需伪造注释；生成源文件不直接编辑。历史缺失不能作为本次新增或修改声明省略说明的理由，但不能借任务扩展到无关旧代码。

## 方法与类型文档

类型、方法和构造方法均使用 `/** ... */` JavaDoc，紧贴声明并位于注解上方；普通行注释或块注释不能代替声明文档。首句说明职责，标签对应实际签名和行为，不填无适用含义的模板项。

公共 API、框架扩展点和复杂方法按实际行为补全调用契约：

- 参数的业务含义、必要范围、单位、格式、空值及互斥条件。
- 返回含义、顺序、单位、部分成功及 null／空集合语义，以及实际可观察的参数错误、业务失败和依赖失败。
- 数据、事务、消息、文件、外部调用、缓存的副作用与资源所有权，以及权限、线程安全、幂等、重试、超时、取消和关闭限制。

接口描述公共约定，实现类仍写职责并补充自身状态、资源、错误与副作用。简单方法可用单句，不补无关维度。

## 作者

新建 public 类型与核心组件的 `@author` 使用当前会话已明确的实际作者；没有可靠姓名时读取 Git 用户配置，仍无法确定再询问。不得把仓库所有者、历史作者或示例姓名当作当前作者，也不填写占位值。

修改已有代码保留真实作者，不因普通修改覆盖或自动追加作者；发现身份信息不确定时核实，不猜测。

## 业务逻辑说明

注释放在对应逻辑块前，说明实际涉及且不能从代码直接看出的规则：

- 条件成立或不成立的语义、状态前置条件、幂等与冲突结果。
- 转换、过滤、订正、补偿的原因、不处理条件与失败后保留的状态，以及精度、单位、时区和来源。
- 权限、脱敏、兼容、回滚和兜底保护的约束及保留原因；算法、正则和优化的假设与取舍；阈值、默认值、随机值和批量边界的业务口径。

只对逻辑实际涉及的规则说明，不编造业务理由。`TODO/FIXME` 写明未完成原因、触发条件和可追踪标识；检查抑制写明精确规则、理由与范围。错误、过期、占位、空泛或被注释掉的无用旧代码应在授权范围内修正或移除。

## 修改后复核

重新读取本轮涉及的声明、字段、私有方法、转换及核心分支，核对注释是否与行为一致。不能只看公共 API，也不能用复制方法名、模板或逐行流水账充数。

修改 Java 文件后，在仓库根目录运行现有工作区门禁：

```powershell
python scripts/code/java/check_worktree_java_comments.py
```

该入口检查工作区版本，使用临时索引复用暂存检查器，不改变真实暂存状态。纯只读任务或仅修改 Skill 文档时无需运行 Java 注释检查。

检查失败按[根规则](../../../../AGENTS.md#required-validation)处理。自动检查不能证明作者真实或说明完整，仍需上述语义复核。
