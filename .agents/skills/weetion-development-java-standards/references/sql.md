# 数据库结构、迁移与种子约定

用于修改 Java 业务表、空库基线、版本化迁移或种子数据。表映射见 [DO](do.md)，查询实现见 [Mapper](mapper.md)。

## 项目表约定

表名和列名采用小写下划线，业务表名使用所属领域前缀 `system_*`、`infra_*`；表和业务字段有准确中文注释。审计、删除、主键及复杂字段按 [DO 规则](do.md)由生命周期决定。

沿用目标表族的字符集、排序规则和时间口径；可演进状态不使用 MySQL ENUM。历史 JSON 与逗号字段的兼容规则见 [DO](do.md#空值与复杂字段)。

## 基线与迁移

[空库基线](../../../../数据库文件/basic_framework.sql)用于 MySQL 8.x 新建数据库，不能重复导入已有业务库。结构演进使用增量迁移；当前没有迁移目录，首次需要时在部署目录中建立 MySQL 迁移入口，文件使用唯一时间版本：

```text
VYYYYMMDDHHMM__<domain>_<action>.sql
```

描述部分使用 ASCII 小写下划线。该命名不代表已接入 Flyway/Liquibase，也不代表应用启动会自动执行；按部署流程确认版本执行与记录方式。

迁移文件头说明目的、适用旧结构、受影响对象、执行顺序、重放能力、前后检查和恢复方式。迁移验证后同步空库基线，使新装与升级到同一版本的结构一致。Quartz 等第三方框架表按其版本和升级方式管理，不从业务 DO 反向生成。

DO、空库基线和迁移记录均不能单独代表生产现状；实库执行遵循[根规则](../../../../AGENTS.md)。

## 种子数据

| 数据 | 基线处理 |
| --- | --- |
| 必需元数据、权限、菜单、字典 | 可以纳入；使用稳定来源与标识，和应用契约一致 |
| 示例与演示数据 | 放隔离开发脚本或测试资源 |
| 管理员账号、密码 Hash、Token、密钥 | 不新增到基线；通过初始化或受控运维流程创建 |
| Quartz 当前运行状态、环境实例数据 | 不作为普通产品种子复制，核对第三方初始化流程 |

存量基线中的历史账号或运行状态不作为新增数据的范例，也不在无关任务中顺带清理。

## 对应验证

结构迁移在隔离环境分别验证适用旧结构升级和空库新装，比较受影响结构、数据及应用必要读写。静态检查、Maven 或 SQL 解析成功不能代替迁移执行结果。
