# Web 注释完整规范

## 适用范围

本文件由 [Web 开发技能](../SKILL.md)维护，是 basic-framework Web 注释的完整必读规范。生成、修改或评审 TypeScript、JavaScript 和 Vue 注释前完整读取本文件；已有完整且仍有效的上下文可复用。适用于管理前端的模块、函数、类型、composable、组件契约及复杂模板逻辑。

[根规则](../../../../AGENTS.md)负责共同底线，本文件负责注释对象、内容、格式、执行及复核。框架、样式、构建、测试和安全开发要求仍按目标工程及 Web 主技能执行。混合变更中的 Java 使用项目 Java 技能及其完整注释规范；Python 辅助工具遵循根规则及相关脚本的实际契约，不把 JavaDoc 或 Python Docstring 标签强加给 Web。

## 核心原则

- 注释质量是代码质量的一部分；复杂逻辑、对外契约和新增或修改的业务接入点不能缺少必要说明。
- 默认使用准确中文；协议字段、标准名、类名、异常名和第三方术语保留原文。
- 注释解释职责、业务原因、约束、边界、风险、副作用和失败结果，不机械复述代码动作。
- 优先保持目标模块已有的注释格式、字段风格、业务术语和合理粒度，但历史缺失不能作为降低当前规则的理由。
- 修改代码时同步更新相关注释；错误、过期、空泛或与行为不一致的注释必须修正或删除。
- 不能只检查公共 API；实现完成后必须反查本轮涉及的私有方法、局部业务接入点、数据转换、常量和边界分支。
- 注释不能代替清晰命名和合理结构；能通过重命名、类型约束或职责拆分表达的内容，优先改进代码本身。

## 必须注释的对象

- 所有显式声明的模块、类型，以及类、接口、枚举、核心组件和脚本入口等对外或核心结构。
- 所有显式声明的函数、方法和构造方法；简单私有方法可以使用精确单句职责说明，但不得完全缺失。
- 公共 API、RPC/SDK 方法、事件回调、消息消费者、定时任务、命令行入口和框架扩展点。
- 复杂私有方法、嵌套函数、异步任务、后台任务和资源生命周期管理入口。
- 新增或修改的业务接入点、数据修正、补偿逻辑、留痕审计、事务顺序和外部系统数据口径。
- 复杂业务逻辑、跨模块流程、状态机、权限判断、金额、库存、订单、配额和计费等关键规则。
- 边界条件、错误码、异常转换、事务边界、并发控制、缓存策略、重试、回滚、补偿和失败兜底。
- 数值单位、精度、格式转换、随机值、阈值范围、默认值、空值、批维度和兜底保留原值等业务口径。
- 正则表达式、算法、性能优化、兼容性处理、安全裁剪和非显而易见的返回约定或副作用。
- 数据模型、枚举常量、TypeScript 接口/类型成员和 Vue props/emits 中仅靠名称无法准确表达的业务含义、单位、可空性和数据来源。

## 文档注释内容要求

- 第一段直接说明对象承担的职责和业务目标，不以名称改写、空泛口号或“用于处理相关逻辑”代替。
- 参数说明包含业务语义和关键约束；不能只重复参数名，也不能遗漏范围、单位、格式、空值或互斥关系等必要信息。
- 返回说明写清结果语义、空值或空集合约定、数据形状、顺序、单位和部分成功行为；无返回值时不虚构返回标签。
- 异常或错误说明只记录真实可观察的失败条件，区分参数错误、领域失败、外部依赖失败和系统错误；不虚构实现不会产生的异常。
- 涉及事务、数据写入、外部调用、消息发布、文件操作、缓存更新、资源所有权或长耗时行为时，说明实际副作用和失败边界。
- 涉及调用前置条件、线程安全、幂等、重试、取消、超时、关闭顺序、权限或敏感数据时，记录调用者必须知道的限制。
- 文档标签必须与真实签名和行为一致；无参数、无返回值、无显式异常或无版本语义时不为了格式完整而编造标签。
- 接口、抽象契约和实现类分别说明各自职责；实现不能只依赖接口文档而省略实现特有的状态、资源、错误和副作用。
- 简单 getter/setter、样板方法和自解释私有方法仍需满足“显式方法有职责注释”的要求，但可以使用准确单句，避免制造长篇噪音。
- 生成代码或框架自动生成且源码中不存在的声明不伪造注释；生成源文件本身不得直接编辑。

## 核心逻辑与行内注释

- 注释放在需要解释的逻辑块之前，优先说明决策原因、业务规则和结果，避免在每一行末尾写流水账。
- 条件分支说明触发条件及不进入分支时的语义；兜底分支说明为何安全、保留什么以及何时需要报警或失败。
- 状态转换说明合法前置状态、目标状态、幂等行为和并发冲突结果。
- 数据修正、过滤、转换和补偿说明“为什么改、何时不改、异常时保留什么”，并明确精度、单位、时区或数据来源。
- 安全、权限、脱敏、白名单和兼容分支说明所防止的风险及不能删除的原因，不能只写“安全处理”或“兼容旧数据”。
- 算法、正则和性能优化说明输入假设、复杂度或关键权衡；代码已经清楚表达的循环和赋值动作无需重复描述。
- TODO/FIXME 写明触发条件、未完成原因和可追踪标识；忽略规则写明精确规则码、必要原因和最小作用范围。

## TSDoc/JSDoc 要求

- 导出的函数、类、composable、常量和工具方法使用 `/** ... */` 块注释说明职责；模块内部自解释的简单函数可以使用准确单句，但不得完全缺失。
- 公共 API 和复杂函数按实际情况说明 `@param`（业务语义、单位、可选性、互斥关系）、`@returns`（结果语义、空值约定）和 `@throws`（真实可观察的失败条件）；无参数、无返回值或无显式异常时不虚构标签。
- 注释标签必须与真实签名一致；类型已经由 TypeScript 签名表达时，不在注释中重复抄写类型，只补充名称无法表达的业务口径。
- 接口、类型别名和枚举的成员字段，仅靠名称无法准确表达业务含义、单位、可空性、取值来源或协议口径时必须注释。
- 遵循目标模块已有的注释风格和粒度（如 vben 体系的 `@description` 用法），不为统一格式批量重写无关旧注释。

## Vue 组件专项

- 业务组件在 `<script setup>` 顶部或组件声明处说明组件职责、使用场景和关键约束；纯展示且自解释的小组件事从简，但不缺失。
- `defineProps` 的业务字段说明含义、单位、默认值口径和可选性；`defineEmits` 的事件说明触发时机、载荷语义和与 `v-model` 的对应关系。
- `defineExpose` 暴露的方法和 `defineSlots` 的插槽说明调用方契约；`v-model` 多值绑定时说明每个值的语义。
- composable（`useXxx`）说明参数、返回的响应式状态与方法、内部副作用（定时器、订阅、请求）及调用方是否需要手动清理。
- `<template>` 中的复杂条件渲染、权限分支、兼容分支使用 `<!-- -->` 说明业务原因；简单结构不逐行注释。
- `<style>` 中覆盖第三方组件或修复兼容性问题的样式说明原因和适用边界。

## Web 结构专项

- 异步请求、轮询、WebSocket、定时器和事件订阅说明创建与清理时机、取消语义和组件卸载后的行为。
- 权限指令、路由守卫、菜单过滤和数据脱敏说明所防止的风险及不能删除的原因，不能只写“权限处理”。
- 与后端接口对齐的数据转换、枚举映射、时间格式和金额精度说明前后端口径差异及取舍。
- 浏览器兼容处理、第三方库缺陷绕行和临时方案说明原因、影响范围和退出条件，并给出可追踪标识。
- `// @ts-ignore`、`// eslint-disable` 等忽略项写明精确规则码、必要原因和最小作用范围。

## 作者

Web 文件不强制作者标签；目标模块已有作者头注惯例且本次确需写入作者时，才确定真实姓名。优先使用当前会话规则中明确的用户姓名，当前用户另有明确说明时以其说明为准；没有可靠姓名时读取 `git config user.name`，仍不能确定再询问。无需写作者时，不为完成注释检查额外查询或询问姓名。

不得用“作者”“待填写”“TODO”“unknown”等占位值，不把仓库所有者、历史文件作者或规则中的固定姓名自动当作当前开发者。修改已有代码保留原有真实作者，不因普通修改覆盖、删除或自动追加作者记录。

## 不应出现的注释

- “设置变量”“调用方法”“返回结果”“进入循环”等直接复述代码的流水账。
- “临时处理”“以后优化”“特殊逻辑”等没有原因、边界或追踪信息的空泛说明。
- 为通过门禁复制方法名、参数名或同一模板，导致所有方法注释内容近似但不反映真实职责。
- 与代码行为、签名、错误、单位、事务或副作用不一致的旧注释。
- 被注释掉且没有明确保留理由、退出条件和追踪事项的大段废弃代码。
- 用注释掩盖差命名、重复逻辑、过长方法、无约束动态类型或错误分层。

## 执行与复核

1. 读取适用根规则、本文件和目标前端规范，核对本次涉及的声明、字段、公共契约、复杂逻辑及相邻代码风格。只读评审不授权修改，局部任务不扩大为无关历史注释整改。
2. 按真实签名和行为编写或修正注释；简单方法可用准确单句，公共 API、核心组件和复杂方法按上文补全适用内容。需要写作者时执行作者规则，不猜测，不写占位内容通过门禁。
3. 重新读取变更片段，按“必须注释的对象”“文档注释内容要求”“核心逻辑与行内注释”以及 TSDoc/JSDoc、Vue 和 Web 专项逐项复核，反查私有方法、局部业务接入点、数据转换、字段、常量及边界分支；不能只看到公共 API 有注释就认为完成。核对旧注释与签名、行为、错误、单位和副作用一致，并排除“不应出现的注释”。
4. 执行下方适用门禁及人工复核。作者真实性、字段业务含义、间接异常、跨文件类型、副作用、复杂模板与样式原因不能仅依赖工具判定。失败时修复本次授权范围内的问题，范围外问题单独报告，不擅自扩大修改或声称整体检查通过。
5. 评审时分别报告缺失、错误、过期、占位、复述和格式问题，给出文件路径、行号、影响和最小整改建议。交付说明实际检查、结果、未验证事项与剩余风险，不能只依赖提交钩子兜底。

## Web 门禁

管理前端在既有 ESLint 中维护中文注释规则。Web 代码修改后，在所属工程运行 `pnpm quality:comments`，或运行已集成同一增量规则的 `pnpm lint`，检查当前工程相对 HEAD 改动涉及的 TS、JS 和 Vue 声明；覆盖职责注释及可机械核验的公开调用契约。`pnpm quality:comments:all` 仅用于明确要求的全量审计。所属工程独立安装依赖并运行检查；环境和调用方式见[质量检查脚本](../../../../docs/开发指南/质量检查脚本.md)。

仓库级兼容入口 `scripts/code/web/check_worktree_web_comments.py` 按文件所属前端调用其解析实现。`scripts/code/check_worktree_comments.py` 只覆盖 Java 与 Python，不能证明 Web 注释通过；`scripts/workflow/run_checks.py` 的 comments 组可运行三个语言检查。

按目标前端配置执行相关 lint、类型检查和必要测试，例如 `pnpm lint`、`pnpm check:type`；注释工具不能替代上文人工语义复核和行为验证。不得降低阈值或扩大忽略范围，缺少工具、依赖、跳过和失败须如实报告。纯只读且未修改代码的任务无需执行修改后的交付门禁。

## 停止条件

未完整读取本规范、未重新检查变更片段、必要职责或业务契约说明缺失、需要写入的作者无法确定，或本次授权范围内的注释问题未解决时，不得直接交付。必须回到真实代码核对原因、边界、失败兜底、副作用及保护职责，不能用占位注释、名称复述、虚构参数／错误或忽略规则掩盖问题。范围外失败和未完成验证如实报告，不据此扩大修改范围，也不宣称整体门禁通过。
