# basic-framework Web 开发规范

## 规则来源与工程范围

- 根目录 `../../../AGENTS.md` 定义共同底线；本技能统一 Web 工作入口，按场景读取开发资料与完整注释规则。
- 目标前端为 `前端代码/basic-framework-admin`，唯一管理应用的源码位于 `apps/web-ele/src`。先结合用户范围、实际文件和上下文确定目标，无法确定时再询问。
- 读取目标目录规则、`package.json`、工作区配置、TypeScript 配置和相邻实现，确认真实版本、脚本、目录及导入路径。资料中的示例不能替代项目当前实现。当前应用使用 Element Plus；菜单由后端权限接口提供，`preferences.app.accessMode` 为 `backend`。业务菜单配置后端 `system_menu` 与角色授权，静态路由只用于明确需要的核心或独立路由，不为每个 CRUD 强制新增。
- Java 使用项目 Java 技能；Python 仅用于质量和交付辅助工具，按根规则、相关脚本及相邻实现核对，不加载不存在的 Python 技能。本技能不授权无关重构、依赖升级、部署或提交。

## 工作模式与必读资料

| 当前任务 | 执行方式 |
| --- | --- |
| 普通页面、组件、接口、状态或路由开发与修改 | 定位目标调用链及相邻实现，读取下表中实际涉及的组件资料，按授权范围修改 |
| 完整 CRUD 模块生成 | 完整读取 [CRUD 流程](references/crud-workflow.md)，按其要求读取默认模板及对应组件资料 |
| 中文注释、TSDoc/JSDoc、公共契约或复杂逻辑说明 | 完整读取 [Web 注释完整规范](references/web-comments.md) |
| Web 代码评审 | 读取实际涉及的组件与注释资料；输出问题前按 [报告前核验](../weetion-code-review/SKILL.md#verify-findings) 逐项核验 |
| 编写或修改涉及共享状态、并发、模拟时钟、子进程或清理的测试 | 按问题读取[测试可靠性](../../../docs/测试与可靠性/测试可靠性.md)的相关章节，不因普通页面使用异步操作而读取 |
| 排查已有偶发测试失败 | 读取[偶发失败诊断](../../../docs/测试与可靠性/偶发失败诊断.md)，依据失败证据选择复现范围 |
| 修改后的验证与交付 | 按目标应用配置执行相关检查；完整 CRUD 同时执行其专项流程中的脚本与人工核对 |

普通修改和只读评审不自动触发完整 CRUD 文件生成；评审与方案讨论不授权写入文件。生成或修改代码时，所有显式声明的职责、公共契约和关键业务逻辑必须满足完整注释要求。

## 组件资料路由

普通页面与组件修改先根据本次要修改的组件与行为，读取参考文档中的相关章节；已有完整且仍有效的上下文可复用。局部修改不默认读取整篇 API 文档或模板。需要新建组件、组织多组件交互，且相邻实现不足以提供范例时，再读取对应模板片段。

使用 `useVbenModal`、`useVbenDrawer`、`useVbenVxeGrid` 等 API 前，在目标工程核实导入、类型及相关实现；模板是组合示例，不能替代当前代码契约。完整注释资料仍按上表要求读取。完整 CRUD 生成遵循其专项流程的资料、模板与检查要求，不适用局部修改的读取减免。

## 执行与验证

1. 明确目标应用、任务模式、改动范围与真实接口契约，核对相关页面、路由、请求封装和组件实现。
2. 读取命中的专项资料；写入前说明目标文件与修改目的，保持既有授权范围。
3. 按目标 TypeScript 配置和项目惯例实现，并同步准确中文注释。只读评审给出文件、行号、触发条件及核验依据。
4. 实施变更后，执行与风险匹配的 lint、类型检查及测试；命令取自目标项目配置，不把构建或脚本成功当作所有行为均已验证。
5. 完整 CRUD 还必须按专项流程运行本技能自带的[检查脚本](scripts/check.sh)，并人工核对组件 API、跨文件类型和请求参数；该脚本不属于所有 Web 任务的通用门禁。
6. Web 修改后在所属前端工程运行 `pnpm quality:comments`；`pnpm lint` 已集成同一增量规则，按完整注释规范人工复核自动检查不能判断的业务语义。环境准备、范围和输出见[质量检查脚本](../../../docs/开发指南/质量检查脚本.md)。Java/Python 注释脚本不能证明 Web 注释通过；工具缺失、跳过或失败必须如实报告，不降低阈值，也不修复无关问题。
7. 按下表选择与改动有关的工程工具；在管理前端工程中执行。环境、文件与命令映射及实际接入状态见[脚本使用索引](../../../docs/开发指南/脚本使用索引.md)，业务测试范围见[测试策略](../../../docs/测试与可靠性/测试策略.md)。
8. 最终报告实际修改、验证命令与结果、未验证事项和剩余风险；完整 CRUD 的交付结构按其专项流程执行。

| 任务场景 | 需要查阅并选择的工具 |
| --- | --- |
| 包清单、依赖、导入方向或配置读取变化 | [工作区约束](../../../docs/开发指南/质量检查脚本.md#前端工作区依赖)、[源码审计](../../../docs/开发指南/前端开发检查与构建工具.md#源码审计)；清单关系变化时核对[模块图](../../../docs/开发指南/前端开发检查与构建工具.md#模块依赖图) |
| 测试受代理影响，或需要覆盖率证据 | [测试代理隔离](../../../docs/开发指南/前端测试与交付工具.md#测试代理隔离)、[覆盖率与未覆盖位置](../../../docs/开发指南/前端测试与交付工具.md#覆盖率与未覆盖位置)；保留实际测试失败状态 |
| 需要可核对来源的构建或体积调查 | [构建记录](../../../docs/开发指南/前端开发检查与构建工具.md#构建记录)、[构建体积分析](../../../docs/开发指南/前端测试与交付工具.md#构建体积分析) |
| 整理本地构建产物 | [清理预览](../../../docs/开发指南/前端开发检查与构建工具.md#清理产物)；实际删除按项目确认规则执行 |
| 制作或验收静态交付包 | 按[静态站点交付](../../../docs/开发指南/前端测试与交付工具.md#静态站点交付)完成构建、打包、核验及冒烟，另行验证浏览器和业务行为 |
| 修改前端工具、规则或解析桥接 | 按[工具测试入口](../../../docs/开发指南/脚本使用索引.md#脚本自身的测试)运行受影响消费方的测试；解析器和分析插件的测试见各专项指南 |

上述工具按场景使用；未接入 quality:verify 的独立命令不能假定已经执行，不能把全部工具变成每次 Web 修改的固定检查集合。

## 停止条件

- 依赖尚未明确的真实接口、权限或业务契约，且现有材料无法确认时，先说明缺口。
- 规则与实际配置发生会影响结果的冲突时，按根规则处理，不猜测或降低质量要求。
- 未读取强制资料、编造组件 API 或契约、缺少必要注释、试图通过忽略规则掩盖问题时，不得宣称完成。
