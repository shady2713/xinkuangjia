<a id="archive-agent-notes"></a>

# Agent Note 编写与生命周期

Agent Note 保存需求变化、决策依据、真实考虑过的替代方案、后果、关联实现和必要验证。是否编写由下方变更门槛决定；未来决策价值用于记录形成后的活动保留、归档及生命周期判断，不能用来免除本应记录的变更。字数、年代和数量只用于发现候选项，不作为保留或归档的判据。

<a id="read-the-contracts"></a>

## 确认项目约定

先定位目标项目已有的 Agent Note 规则、目录、格式、状态标记、归档政策及校验入口。遵循实际存在的项目约定，不假定规则位于固定路径，也不要求特定语言组合、文件数量或包管理器。项目有附属文件、归档清单或完整性校验时，按其既有契约维护。

依据当前代码、配置、文档、活动笔记和入站链接，确认决策仍约束什么行为。项目已有格式时沿用它；没有格式约定时，使用下方中文骨架。记录位置与分类沿用项目布局，没有现成布局时在已授权范围内确定存放位置，不为套用示例创建整套空目录。

<a id="basic-framework-contract"></a>

## basic-framework 的目录与交付约定

框架发布基线不携带提取、适配和修复过程的维护笔记；这类整理交接材料存放在仓库外。使用框架开发业务时，按本技能保存该业务项目实际形成的决定，不导入来源项目笔记作为当前规则。

活动记录路径为 `.agents/notes/<lifecycle>/<class>/YYYY-MM-DD-主题.md`。日期为主题首次提出的有效日期，主题名称非空；按需创建实际用到的目录，不预建空目录，不另设集中式索引。

| 生命周期 | 唯一状态行 | 用途 |
| --- | --- | --- |
| `proposed` | `状态：提议中` | 尚未交付的提案 |
| `implemented` | `状态：已实现` | 已交付且仍约束业务维护的决定 |
| `rejected` | `状态：已拒绝` | 已否决且仍有防范价值的提案 |

| 分类 | 负责范围 |
| --- | --- |
| `feature` | 面向用户的新能力 |
| `bug-fix` | 缺陷或事故暴露的问题 |
| `simplification` | 不增加能力的代码、行为或对外范围精简 |
| `architecture` | 交付源码的结构、模块关系和运行时边界 |
| `process` | 工具、策略和工作流程 |
| `testing` | 测试基础设施与策略 |

分类与命名的检查配置位于 [agent_note_support.py](../../../scripts/docs/agent_note_support.py)。新增分类时说明现有类别为何无法覆盖，并同步本节、检查配置和相关测试；不另设与 `simplification` 重叠的 `refactor` 类别。

新记录的 H1 使用 `# 决策记录：具体主题`，状态行唯一且与目录一致，必需 H2 与内容遵循下方[格式规则](#note-format)。状态改变时同步目录、状态和正文；不以空标题或 HTML 注释占位。旧业务记录可以保留检查器支持的历史英文标记，不批量改写。

只有已实现记录可以进入 `.agents/notes/archived/<class>/YYYY-MM-DD-主题.md`；归档后保持已实现状态并记录归档日期，正文与实际附件按下方冻结规则保留。业务决定需要恢复时新建活动记录，不改写快照。

在仓库根目录，针对本次实际新增或修改的记录执行以下入口；将 `实际笔记路径` 替换为存在的文件或范围：

```powershell
python -X utf8 -B scripts/docs/verify_agent_note_classification.py 实际笔记路径
python -X utf8 -B scripts/docs/verify_agent_note_format.py 实际笔记路径
python -X utf8 -B scripts/docs/verify_md_links.py 实际笔记路径
```

[分类检查](../../../scripts/docs/verify_agent_note_classification.py)与[格式检查](../../../scripts/docs/verify_agent_note_format.py)不能证明决定依据完整或替代关系正确；[链接检查](../../../scripts/docs/verify_md_links.py)不能证明链接内容符合当前行为。空发布基线的零对象结果仅证明没有记录，不能声称已经验证业务笔记。

<a id="when-to-write-a-note"></a>

## 何时编写与更新

非小改动必须在同一次变更中新增或更新至少一份相关 Agent Note；有 PR 时一同提交，不依赖 Git 或 PR 才执行。需求或验收条件、行为、架构、跨文件约定、工具与流程、测试策略、存储或协议格式发生实质变化，或存在维护者可能重新审视的取舍，都属于此范围。只有不改变行为、约定、结构、流程或理由的纯机械性或局部小修改可豁免；改动行数少不等于可豁免。

获授权生成计划或需求卡时，先保存已确认讨论的需求、边界、取舍、否决方案和未决事项，注明需求编号与适用版本，再生成卡片；已有同一决策记录则复用。记录依据来自已确认讨论，不从卡片反推。业务尚未实施时，不能因卡片生成而标为“已实现”；状态沿用下方规则，来源链接与读取要求见[需求卡生成规范](../weetion-task-cards/SKILL.md#需求来源)。

优先更新已经负责同一决策的笔记，避免重复记录。原地修改用于同步该决策的实际实现，包括路径、符号、默认值、结构及机制；保留原有决策、理由、备选方案和仍适用的约束，不追加变更流水账。

决策或其理由改变时，创建新记录，并与旧记录交叉链接，说明完整或部分替代关系。新的独立决策由自己的记录承载；不通过改标题、扩大主题或连续补充，将旧笔记改成不同的决策，即使新旧结论并非相反也不例外。记录按决策及其理由划分，不机械地每条规则新建一篇。

需要拆分已经混入不同决策的活动笔记时，按授权完整转移各自的独有依据、真实备选方案、影响、必要验证及覆盖缺口，建立交叉链接，让原记录继续负责原决策。不得用拆分抹去历史依据；归档冻结和完整合并条件仍按下文执行。

<a id="note-format"></a>

## 格式与内容

标题明确主题，状态可检索且与所在生命周期一致。文件命名、日期、分类及机器识别的字段遵循项目规范；没有约定时可用首次提出日期和主题命名。正文以中文记录，保留项目解析器要求的固定标记。

| 状态 | 必需内容 | 表述要求 |
| --- | --- | --- |
| 提议中 | 问题、提案、考虑过的替代方案、验收标准、风险 | 明确尚未交付的部分 |
| 已实现 | 问题、决策、考虑过的替代方案、影响、必要验证 | 描述当前实际交付情况 |
| 已拒绝 | 保留提案内容，补充拒绝理由与状态 | 不改写当时的提案和取舍 |

没有项目模板时，已实现笔记可使用以下骨架：

```markdown
# 决策记录：<具体主题>

状态：已实现

## 问题

## 决策

## 考虑过的替代方案

## 影响

## 验证
```

在对应章节保留需求或验收条件的前后变化及可定位来源、分析所依据的事实、真实备选方案及取舍、关联模块或文件，以及实际验证和未覆盖范围。来源可以是已有需求文档、议题或已确认要求的准确摘要；缺少来源或尚未确认时如实说明，不编造授权、方案或证据。相关内容可以链接到已有负责记录，不要求复制整段对话或代码差异；读者应能沿记录追溯变化及其理由。

问题描述应能独立于方案成立。替代方案只记录真实考虑过的选择及落选原因，不为凑齐章节编造历史。影响同时说明收益、代价和明确不保证的事项；验证记录实际证据与覆盖缺口，避免实现流水账。提议中笔记使用提案、验收标准和风险章节；交付后改为当前决策、影响及实际验证结果。

<a id="check-supersession-when-adding-a-note"></a>

## 新增笔记时检查替代关系

每篇新笔记都必须触发有明确范围的检查，搜索讨论同一决策、机制或被否决方案的活动记录，不扩展为无关笔记的全量清理。

- 没有替代关系：独立保留，必要时链接相邻决策。
- 部分替代：保留双方及仍有效的事实，说明各自覆盖范围并建立交叉链接。
- 完全替代：确认每项独有依据、替代方案、影响、必要验证和覆盖缺口都有归属，再按项目政策选择归档或合并；有独立决策价值的旧记录继续保留。
- 合并后移除旧记录：新记录必须完整承接上述内容，修复所有入站链接，并在同一次变更中处理项目要求的关联文件；不能只依赖版本历史保存理由。

功能仍有受支持的实现、配置、数据格式或兼容行为时，不得把相关决策当作已完全失效。只有功能彻底移除且独有依据得到承接，才可合并其原始记录；保留原始动机、移除理由、放弃的能力和重新引入条件。

<a id="classify-by-future-value"></a>

## 按未来价值处理

- **已实现且仍有价值：** 理由、备选方案、不保证事项、所有权边界、兼容性、安全规则或重新引入条件仍会影响未来决策时，保留为活动记录并同步事实。
- **已实现且适合归档：** 决策已交付，主要记录一次性过程或已被其他权威资料完整承接的细节，不再承担当前约束时，转为历史快照。
- **提议中：** 有效提案保持活动，不归档；不再推进时记录真实拒绝理由，转为已拒绝。
- **已拒绝且仍有防范价值：** 落选方案仍容易被重新采用且会导致实质问题时，保留其理由。
- **已拒绝且不再有价值：** 在任务授权和项目政策允许时删除，并修复入站链接及关联文件。

例如，已经完成的一次性界面调整可能适合归档；持续约束数据所有权或兼容边界的短笔记应保留。按语义判断，不以篇幅或年代代替判断，也不为达到数量指标而归档。

<a id="archive-an-implemented-note"></a>

## 归档已实现笔记

1. 确认笔记已实现、适合归档，并明确项目的归档位置及需一同处理的关联文件。
2. 在已授权范围内移动完整记录。保留已实现状态，按项目格式记录归档日期；除归档所需元数据外，不修改正文、重排内容或修复出站链接。
3. 搜索活动文档的入站链接。当前行为应链接当前权威来源；有意引用历史证据的链接改为归档位置；不再需要的引用删除。
4. 项目有封存清单或哈希校验时，先验证既有快照，再按其流程追加新记录；不得用重算旧哈希掩盖历史内容变化。没有这些工具时，核对正文、关联文件和元数据差异，不创建无需求的校验体系。
5. 执行项目实际提供的格式、入站链接及归档完整性检查，确认活动记录不再把归档内容当作当前规则。

记录一旦封存，就不得编辑、移动、翻译、重新排版或删除。需要恢复某个历史决定时，新建活动记录，链接原快照并重新核实其适用性，保持归档文件不变。不得验证或修复冻结快照的出站链接。

<a id="validate-and-report"></a>

## 验证与汇报

按目标项目的规则、构建配置和 CI 确认检查命令，不绑定固定脚本。检查状态与目录是否一致、必需内容是否完整、活动记录及入站链接是否有效；归档操作额外检查冻结内容与项目规定的清单或关联文件。只阅读和验证本次任务涉及的范围，排除冻结快照的出站链接。

项目已有的必需检查继续执行；无法运行时说明原因和未验证范围。没有对应工具时进行人工复核，不能将人工复核表述为自动检查通过。Git 工作区运行 `git diff --check`。

汇报新增或更新的记录、替代关系及实际执行的归档或删除操作，说明影响文件、验证命令、结果和剩余风险。对仍存在争议的保留价值说明依据，不声称归档笔记的出站链接有效。
