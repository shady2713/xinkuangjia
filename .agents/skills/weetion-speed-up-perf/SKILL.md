# 性能调查与优化

根据用户目标，在真实负载下调查延迟、吞吐或资源开销；优化收益必须由可比较的测量支持，不能仅凭实现看起来更高效判断。先选择任务，已有有效上下文可复用，只读取涉及的参考章节。

| 本次任务 | 执行与读取范围 |
| --- | --- |
| 性能调查 | 明确指标、完成点和负载，核对[当前依据](../../../docs/性能优化/性能调查与证据.md#authority)并形成[可证伪假设](../../../docs/性能优化/性能调查与证据.md#hypotheses)；优先使用现有测量设施，静态分析不足时在授权环境补测。输出证据和缺口，不默认修改生产代码、新建基准或门禁 |
| 性能优化 | 先保存基线，再实施获准修改，比较目标指标及不可退化指标，完成行为和资源验证；按下方流程及[结论规则](../../../docs/性能优化/性能调查与证据.md#conclusions)留底与交付 |
| 基准或回归门禁建设 | 按需读取[基准规则](../../../docs/性能优化/性能基准与回归门禁.md)，核实入口、测量口径与稳定性；建立或修改自动回归判定时，额外验证预算依据及负对照能否触发预期失败 |

同一任务可包含多个阶段，只有实际涉及的阶段才执行。运行已有门禁时核对版本、负载与环境是否适用，不重复建设设施；条件变化后重新核实受影响的预算和回归识别证据。

<a id="establish-scope-and-current-authority"></a>

## 确定范围和当前依据

先定位目标项目并读取适用的 `AGENTS.md`，按当前问题读取相关架构、测试入口、模块约定及 Agent Notes；不因局部性能任务通读全部资料，也不要求创建缺少的约定文件。需要选择验证层次或处理并发与资源边界时，分别参考[通用测试原则](../../../docs/测试与可靠性/通用测试原则.md)和[通用防御性模式](../../../docs/测试与可靠性/通用防御性模式.md)。设计或修改测试与基准设施，且涉及共享资源、并发、时钟、子进程或异步清理时，按问题读取[测试可靠性](../../../docs/测试与可靠性/测试可靠性.md)；排查已有偶发失败时读取[偶发失败诊断](../../../docs/测试与可靠性/偶发失败诊断.md)。

上述资料及下文性能参考维护在仓库共享 `docs` 中。跨项目携带本技能时，一并携带所引用资料并核对链接，或映射到目标项目明确承接相同规则的文档；缺失时报告具体依赖，不能假定已读取。

依据用户目标明确主要指标（例如延迟、吞吐、CPU、内存或资源容量）、不可退化指标、完成点、负载、资源约束、允许差异及停止条件，不默认以耗时下降作为所有优化的成功标准。关键缺口影响结论或执行边界时再澄清，已明确要求不重复确认。选择实际存在的相关路径；涉及浏览器时单独验证相应交互完成点，不用后端结果推断绘制、滚动或输入响应。

根据测量目的确定外部开销：局部归因可以排除网络、模型或其他外部依赖，但必须说明排除项；宣称完整链路结果时，应包含该路径实际依赖的工作。仅测量部分阶段、使用替身或缺少外部环境时，结论限于已覆盖范围，不能称为完整产品延迟。

调查、测量和修改按任务授权执行。只读调查不自动授权代码修改、付费调用、生产压测、提交、推送、发布或平台反馈；这些操作须处于已有明确授权内，并符合项目要求的再次确认规则。执行测量前核对环境、数据访问、资源占用、成本和副作用是否在约定范围内；缺少必要授权时继续可独立进行的只读工作，说明受阻部分，不擅自扩大范围。已有明确授权继续有效，不为同一操作机械重复询问。

确认本次目标版本、实际工作区差异和比较基线，核对所属源码与测试。有相关历史 PR 或评审时，检查最终差异与已解决的讨论；PR 正文可能描述了已放弃的实现，没有 PR 的项目不要求创建 PR。按[性能调查与证据](../../../docs/性能优化/性能调查与证据.md)区分当前实现、历史已合并方案、未合并或已替代提案、估算与新测量；历史线索不构成重新引入实现的授权。

<a id="survey-user-paths-then-rank-candidates"></a>

## 先调查用户路径，再排列候选项

按项目实际路径选择调查场景，以下是候选方向，不是逐项执行清单：

- 启动与初始化：冷启动、首次使用、预热后重复使用及恢复。
- 请求与批处理：单次请求、并发请求、任务队列、批量任务及排队等待。
- 存储与数据处理：读取、写入、查询、序列化、迁移及缓存命中或失效。
- 流处理与长任务：持续输入、背压、重连、取消及资源释放。
- 界面交互：首次可用、导航、分页、滚动、实时更新及非活动视图首次激活。

仅在当前指令允许委派、工具可用且子任务能独立拆分时采用委派；本技能不单独授予启动子智能体的权限。明确各子任务的场景、读写范围、资源预算、停止条件及证据要求，避免共享资源干扰测量或多个执行者覆盖同一文件。要求报告准确版本、生产调用点、负载、命令、原始结果和未验证项；主执行者核对证据与当前实现，不将委派结论直接当作实测事实。委派不得扩大原任务或操作权限。

分别改变与场景相关的独立成本维度，例如数据字节数、记录数、单项大小、并发度、批量大小、队列深度或可见对象数；这些量不能互相替代。说明负载对应的用户操作及其代表性，不能仅凭大量微小且相同的输入就称为贴近实际。同时覆盖典型负载和尾部负载，避免构造没有决策价值的组合矩阵。

根据观察到的用户延迟、CPU/分配量、保留内存、发生频率和置信度，为候选项排序。对每项明确指出生产消费方、重复工作、预期复杂度、最小可证伪干预，以及必须保持稳定的行为。仅凭可疑循环、未使用的缓存或大文件，不能认定存在瓶颈。

<a id="build-realistic-synthetic-benchmarks-first"></a>

## 按测量目的使用基准规则

先核对现有基准、性能分析工具和测试通道，能够回答本次问题时直接复用；缺少必要证据且任务包含相应建设时，再新增或修改设施。下列规则按实际测量内容读取，局部调查不自动变成门禁建设。

| 涉及内容 | 必需约束与详细规则 |
| --- | --- |
| 生产入口或浏览器响应 | 使用实际交付入口与运行时，不复制产品算法或随意增加生产导出；浏览器结果须有真实输入及对应界面更新证据，见[入口规则](../../../docs/性能优化/性能基准与回归门禁.md#ownership) |
| 负载设计与私有数据 | [测量卡](../../../docs/性能优化/性能基准与回归门禁.md#workload)记录目标、负载和判定条件；合成基准用固定常量或种子，与私有材料及实时服务隔离，真实外部链路单独验证并说明授权、成本和波动；私有材料仅提取必要聚合特征，不泄露原始内容、凭据或可识别片段 |
| 采样、内存或受限资源 | 保持前后输入、校验、完成点及输出存活状态可比；区分冷／热态，保证退出和清理。按目标及受影响风险检查延迟、保留量、峰值或受限资源下的完成能力，不能以加速掩盖无界保留，见[样本与资源](../../../docs/性能优化/性能基准与回归门禁.md#samples) |
| 统计、校准与预算 | 保留全部原始样本、统计口径和可比性依据，不挑选幸运结果；需要跨环境校准或预算判定时按[校准规则](../../../docs/性能优化/性能基准与回归门禁.md#calibration)核实适用条件，不套用时间倍率到资源量，不放宽阈值掩盖回归 |
| 回归判定或门禁建设 | 按[失败判定](../../../docs/性能优化/性能基准与回归门禁.md#verdict)核对真实完成点、预算与受控负对照；未完成验证不能声称门禁有效 |

<a id="prove-the-regression-then-remove-work"></a>

## 先验证瓶颈，再减少工作

修改生产代码之前，先运行未优化的目标负载，保存命令、准确版本、工作区差异、运行时与平台、输入维度、原始测量及判定。缩减问题场景时保持真实瓶颈仍可观察；先提出可证伪假设，再用性能分析、分配样本、工作次数或阶段耗时区分原因。缺少基线或必要环境时，报告验证缺口，不编造优化前数字或声称已经证明收益。

以下模式仅在当前调用路径和行为契约适用时作为候选，不自动套用：

- 消费方只需要汇总或最终内容时，保持紧凑表示，避免无用的展开和逐项对象分配。
- 只有确认数据归属与信任边界后，才移除重复解析、复制、冻结或校验；进程内类型约束不能替代持久化与协议边界的必要验证。
- 大量数据转换可考虑流式处理并限制中间状态；保持验证、持久化、发布和可写就绪等实际义务，不将必要工作移到约定完成点之后。
- 延迟非活动界面或未使用详情的工作时，同时测量首次激活与保留资源。延迟执行仍有后续成本，局部按需处理也不能直接证明完整虚拟化。
- 订阅更新确有重复开销时，考虑稳定对象身份与缩小订阅范围，保持更新顺序、可观察时机和必要的失效传播。
- 根据完整消费路径选择数据结构，减少反复移位、扫描或重建，不以孤立容器操作的收益替代产品收益。
- 采用缓存或合并重复请求时，明确键与失效条件、有界保留、并发一致性、各等待方的取消及资源释放归属；不得只为重复基准更快而缓存不必要的展开表示。

每次验证一个因果因素，在可比条件下复测聚焦场景和受影响的真实路径，报告主要指标、不可退化指标及取舍。宣称端到端延迟改善时必须有相应实测；资源优化须证明真实负载中的资源收益及相关行为约束，不能以孤立微基准代替。建立或修改回归判定时，额外按[有效断言与失败判定](../../../docs/性能优化/性能基准与回归门禁.md#verdict)验证受控负对照；只读调查不因这一要求自动修改实现或门禁。

<a id="preserve-behavior-and-resource-ownership"></a>

## 保持行为和资源归属

性能测量补充功能验证，不能取代它。根据真实调用链和目标项目契约，使用或补充范围适当的功能测试、契约测试或快照，覆盖受影响的输出、顺序、分页或流处理、错误、取消、并发与资源释放。涉及持久化时，核实兼容性、不可变数据、原子发布及就绪条件等实际约定；这些要求按项目是否存在相应契约适用，不强加原项目的会话格式或日志协议。

不得通过截断必要数据、跳过应执行的操作、禁用校验或改变生命周期语义制造加速。任何刻意引入的可见差异都要符合已约定的行为范围，说明影响并独立验证；超出约定时先确认行为变更，不能以性能收益代替授权。

涉及用户界面行为时，按实际受影响路径执行浏览器验证；演示或 GIF 按目标项目及适用技能要求提供。没有界面变化时不自动增加浏览器场景。保持功能预期独立于基准实现；基准断言证明已达到真实完成点，详细语义由所属功能验证维护，见[通用测试原则](../../../docs/测试与可靠性/通用测试原则.md)。

按[目标指标与停止条件](../../../docs/性能优化/性能调查与证据.md#conclusions)判断候选：目标收益无法在代表性负载中复现或仍无法区别于噪声、不可退化指标超出约定、维护成本超过收益，或必要行为及资源语义无法验证时，停止采用该候选并保留依据。目标是 CPU、内存或容量时，延迟未下降本身不是否决理由，但必须满足约定的延迟等约束；目标是端到端延迟时，组件加速不能代替端到端收益。

<a id="deliver-a-bounded-reviewable-result"></a>

## 交付范围明确、可评审的结果

按 [Agent Note 编写与生命周期](../weetion-doc-archive-agent-notes/SKILL.md#when-to-write-a-note)及项目规则执行非小改动留底，不能以预判的长期价值免写。保留需求与指标变化、分析假设、采用及否决的方案、前后数据、校准或预算依据、排除项、验证缺口和剩余风险；原始样本放在所属测量记录并从 Note 引用。纯调查按已有记录授权留存结论，不自动写入；实施授权包含项目要求的相关记录维护。新决定另建记录并核查相关替代关系，不扩展为无关笔记清理。

存在适用 CI 时核对其对应版本与结果；未配置、未运行、无法查询或尚未完成时分别说明，不以本地计时证明 CI 稳定，也不为补齐流程擅自创建 CI。

任务涉及评审时，按[代码评审](../weetion-code-review/SKILL.md)依据当前代码和可执行证据核实意见，不因来自机器人就忽略。回复、提交评审、关闭讨论与发布分别遵循已有授权和项目规则；仅调查时提供建议回复，不向平台发送。代码修复、检查通过、讨论关闭及评审批准分别核实，不能相互替代。

按任务交付：调查说明现象、证据、候选假设及缺口；优化补充基线与候选的目标指标、不可退化指标、行为验证和取舍；门禁建设额外说明预算依据、负对照及实际失败原因。均保留负载、准确版本、环境、完成点、资源语义、原始结果位置、实际检查和排除项，适用时报告前后绝对值与比率。区分本次实测、复用证据、历史报告与估算；未运行、失败、未知及未涉及的阶段如实说明。在约定范围内停止，后续机会单独列出，不自动实施。
