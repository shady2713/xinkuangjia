# 决策记录：SM2 密码传输与等保二级密码策略

状态：已实现

## 问题

管理后台账号密码登录、注册、短信重置、个人改密和管理员重置密码都把密码处理成前端 MD5 摘要后提交，后端再以 BCrypt 存储，因此数据库中的存量哈希实际是 `bcrypt(md5(明文))`。MD5 不是传输加密，摘要一旦被截获仍可直接重放；同时后端没有校验时间戳或 nonce，不能阻止重放。密码复杂度仍是 6-16 位字母数字组合，登录没有失败锁定，管理员创建或重置密码后的初始密码也没有强制修改机制，与等保二级身份鉴别要求存在差距。

## 决策

- 传输统一改为 SM2：前端从 `GET /system/auth/sm2-public-key` 取得带 `04` 前缀的公钥，用 sm-crypto 按 C1C3C2 加密 `{"p":密码,"t":毫秒时间戳,"n":nonce}`；后端用 BouncyCastle 解密，兼容 sm-crypto 不带 `04` 的原始输出。所有提交用户密码的 HTTP 字段均改为密文，前端 MD5 方案及 `md5` 工具一并移除。
- 私钥只通过 `SM2_PRIVATE_KEY` 注入，配置项为 `basic-framework.security.sm2.private-key`；缺失或格式错误时 Bean Validation 阻止应用启动。公钥由私钥在启动时推导，不单独落盘。
- 防重放采用时间窗加 Redis nonce 一次性：默认允许前后 5 分钟偏差，nonce 通过 `SETNX + TTL` 占用；Redis 不可用时失败关闭。只有显式关闭 `SM2_REPLAY_CHECK_ENABLED` 才退化为仅时间戳校验，并在启动时告警。密文、时间戳和重放失败统一返回通用错误，日志不记录明文、密文或载荷。
- 密码存储保留 BCrypt：现状已经是 BCrypt（强度默认 10，内置随机盐），等保二级不强制存储使用国密算法，改 SM3 会引入新的迁移和实现风险。新增 `isPasswordMatchLegacy`，登录先校验 `BCrypt(明文)`，失败再校验 `BCrypt(md5(明文))`，历史格式通过后立即用 `BCrypt(明文)` 重写 hash；兼容代码在存量账号完成登录迁移后按截止日期删除。
- 密码策略改为 8-32 位可见 ASCII，且大写字母、小写字母、数字、特殊字符四类中至少三类；后端在解密后由 Service 校验，前端表单规则和提示同步。登录不强制校验历史密码复杂度，避免存量账号无法登录。
- 登录失败按账号计数，默认连续 5 次锁定 30 分钟，成功登录清零；计数键保存账号 SHA-256 摘要，锁定提示只返回剩余分钟数，不区分账号是否存在。
- 新增 `system_users.password_change_required`：管理员创建、管理员重置、导入初始密码置为 1；用户自行修改、短信重置、注册置为 0。登录响应和权限信息返回标志；前端守卫跳转 `/change-password`，后端 `PasswordChangeRequiredFilter` 对非必要接口返回 403。
- 初始化 SQL 移除明文初始口令线索，管理员 hash 留空并由受控 provisioning 写入；新增迁移脚本处理存量库并标记空密码账号。

## 考虑过的替代方案

- 改 SM3 加盐存储。未采用：BCrypt 已满足等保二级存储要求，强度可配置且自带盐；改造会同时影响登录、管理员重置、导入和兼容迁移，收益不足。
- 只在前端继续 MD5、后端加时间戳/nonce。未采用：MD5 摘要本身是可重放的凭据，不能替代传输加密。
- 用 HTTPS 代替应用层密码加密。未采用：HTTPS 仍是必要边界，但不能覆盖网关、日志或客户端环境中的明文暴露；等保要求通信传输保密性，应用层国密加密提供额外保护。
- 将兼容逻辑永久保留。未采用：历史 MD5 派生哈希不应无限期保留；兼容代码有明显删除条件，并在文档写明截止后未登录账号需管理员重置。
- 在权限框架层统一拦截首次改密。采用模块内 Servlet Filter：认证过滤器不依赖 system 模块，反向依赖会破坏模块方向；当前过滤器在安全链之后按用户标志拦截，已覆盖管理端接口。

## 影响

- 所有仍提交 MD5 摘要的旧前端版本无法登录；前后端必须同版本发布。
- 缺失 SM2 私钥时后端启动失败；无 Redis 且未显式关闭防重放时登录失败，部署方必须提供 Redis 或明确接受降级。
- 存量 `bcrypt(md5(明文))` 账号可继续登录一次并自动升级；删除兼容代码后，从未登录的旧账号需要管理员重置密码。
- 管理员创建、重置或导入的用户首次登录必须先改密；改密期间其他管理端接口返回 403，前端路由守卫同时跳转 `/change-password`。
- `system.user.init-password` 不再提供默认值，用户导入前必须由管理员设置符合策略的初始密码。

## 验证

- 后端 `mvn -B -pl basic-framework-module-system -am test`：SM2 往返与 sm-crypto 样例解密、错误密文、过期/超前时间戳、nonce 重放、密码策略、失败锁定、历史哈希迁移和首次改密标志测试。
- 前端 `pnpm test:unit`：SM2 加密工具（04 前缀、载荷字段、公钥缓存、失败重试）和密码规则边界测试。
- 全仓检索：确认前端密码提交点不再使用 `md5`，明文初始口令线索不再出现。
- 未验证：真实 Redis/MySQL 联调、数据库迁移执行、浏览器端强制改密跳转和密钥轮换后的缓存刷新，需在目标环境补验。
