# 决策记录：等保二级第二轮认证与会话安全加固

状态：已实现

## 问题

第一轮已落地 SM2 密码传输、密码策略和首次改密，但登录会话仍存在以下缺口：

- 改密、管理员重置密码和删除用户后，旧 access/refresh token 继续有效；按用户撤销令牌的能力没有被业务入口调用。
- 登录、锁定、改密、短信登录失败和 SM2 传输失败没有统一的安全审计，登录日志字典也缺少锁定和传输失败编码。
- 短信登录没有按手机号和 IP 限制验证码尝试，攻击者可批量猜测验证码；锁定提示没有覆盖这两个维度。
- 登录失败锁定在 Redis 不可用时直接放行，属于 fail-open；短信限流和防重放也没有统一的降级说明。
- 空库基线中的 `default` OAuth2 客户端处于启用状态、密钥为空并带 `password`、`client_credentials` 授权类型；管理后台登录又直接依赖该记录。
- 访问令牌 30 分钟、刷新令牌 30 天，前端在 401 时自动刷新，空闲用户在刷新令牌有效期内可以无限续期，缺少后端强制的空闲超时。

## 决策

- 新增 `UserTokenInvalidatedEvent`，改密、短信重置、管理员重置、删除用户后由 `AdminUserServiceImpl` 发布，`UserTokenInvalidatedConsumer` 同步调用 `OAuth2TokenService.removeAccessToken(userId, userType)`。撤销范围包含访问令牌、按用户删除全部刷新令牌（含孤立记录）、Redis 令牌缓存和活动标记。用户禁用沿用状态事件，并把监听器改为同步执行。
- 会话空闲超时由后端强制：签发令牌时写入 `oauth2_access_token_active:{token}`，每次认证续期；刷新令牌前要求关联访问令牌仍有活动标记，空闲用户不能靠刷新续期。默认 30 分钟，`SESSION_IDLE_TIMEOUT=0` 可关闭。Redis 不可用时失败关闭。
- 新增 `system-admin` 内部会话客户端，由 `OAuth2ClientService.getSystemClient()` 在内存构造，不落库、无授权类型，有效期读取 `basic-framework.security.session`。管理后台登录与刷新改用该客户端；空库基线和迁移停用 `default` 客户端、清空其授权配置并删除其已签发令牌。
- 新增 `SecurityAuditService`，统一写入 `system_login_log`：登录成功/失败、锁定、自助改密、密码重置、短信登录失败、SM2 解密失败/重放/防重放不可用。新增日志类型 `300/301/302` 和结果编码 `40/50/60/70-74`，通过基线 SQL 和幂等迁移补字典。审计字段只包含用户、账号、IP、User-Agent、类型、结果和原因。
- 新增 `SmsLoginFailureLockService`，按手机号（默认 5 次）和 IP（默认 20 次）双维度计数，锁定时长与窗口可配，成功登录清零；锁定提示统一为通用剩余时间，不泄露账号是否存在。
- 新增 `LoginAttemptStore` 统一封装 Redis 计数与降级：默认 `local-fallback`，Redis 不可用时使用单实例有界内存计数；可配置 `fail-closed` 在 Redis 故障期间直接拒绝登录。SM2 nonce 和会话空闲校验保持失败关闭，不跟随该策略。

## 考虑过的替代方案

- 异步撤销令牌：现成的状态变更监听器使用 `@Async`。未采用：业务方法返回后到监听器执行之间存在旧令牌可用窗口，不满足“改密后旧令牌立即失效”。
- 在访问令牌表增加 `last_active_time` 并按请求节流更新：未采用。每个活跃用户都会产生周期性数据库写入，且多实例下仍需额外协调；Redis 活动标记与现有令牌缓存路径一致。
- 默认 `fail-closed`：未采用作为默认值。Redis 故障会直接阻断全部登录，把补充防线放大成业务中断；默认内存兜底仍能约束单实例暴力尝试，需要严格失败关闭的部署可显式切换。
- 删除 `default` 客户端记录：未采用。停用并清空授权配置已消除风险，同时保留记录便于审计追溯；删除会丢失该客户端的历史配置。
- 保留 `default` 客户端并轮换密钥：未采用。它仍是面向开放接口的持久化客户端，与后台内部会话职责混在一起，后续容易被误启用。

## 影响

- 升级后默认客户端令牌被清理，且旧访问令牌没有活动标记，所有管理后台用户需要重新登录一次。
- 自助改密和管理员重置后，该用户在所有终端的会话立即失效；个人中心改密成功后前端主动退出并提示使用新密码登录。
- `local-fallback` 在多实例部署、Redis 故障期间只能约束当前实例的失败计数；需要跨实例强一致限制的部署应选择 `fail-closed`。
- 短信发送侧仍沿用同手机号发送间隔和每日上限，本轮新增的是短信登录验证码尝试的手机号和 IP 双维度锁定。
