# 决策记录：移除分享码自动登录并收紧认证与上传边界

状态：已实现

## 问题

固定分享码自动登录把长期有效的分享凭据放在数据库，并通过 `@PermitAll` 接口直接换取令牌。只要拿到链接即可登录，绕过了账号密码、禁用状态和平台隔离；同时短信登录只校验验证码和手机号，没有复用账号密码登录的禁用与平台类型检查。文件上传在 Spring 与 Nginx 层都没有上限，Controller 又把整个文件读入堆内存，容器 `-Xmx512m` 下存在内存耗尽风险。

## 决策

- 删除整条分享码自动登录链路：Controller 入口、Service 方法、响应 VO、DO、Mapper、错误码、登录类型枚举和字典值一并移除，不保留停用开关或兼容分支。空库基线不再创建该表，旧库通过 [V202611041805__system_drop_auto_login_ticket.sql](../../../../数据库文件/V202611041805__system_drop_auto_login_ticket.sql) 幂等删除表和相关字典项。
- `smsLogin` 在验证码通过后复用账号密码登录的规则：禁用账号返回 `AUTH_LOGIN_USER_DISABLED`，非业务管理平台账号返回 `AUTH_LOGIN_PLATFORM_MISMATCH`，并分别记录手机登录类型的失败日志。
- 上传统一为单文件 50MB、请求体 55MB：Spring Multipart 与前端 Nginx、部署网关保持一致；`FileController` 先按 `MultipartFile.getSize()` 早拒绝，再用有界流读取兜底，超限返回明确业务错误。
- 覆盖基线分两层落地：父级从 0.00 提高到 0.01，已有测试执行数据的模块必须达到 1%；system 模块因新增认证回归测试实测约 5.3%，单独设置为 `quality.coverage.minimum=0.03`；server 启动模块现有测试只绑定配置、未覆盖启动类，单独保持 0.00 并记录待补测试。
- 文档检查依赖集中到 [tools/quality/requirements.txt](../../../../tools/quality/requirements.txt)，固定 `markdown-it-py`、`PyYAML` 和 `pytest` 版本，安装说明与缺依赖错误提示统一指向该文件。

## 考虑过的替代方案

- 保留分享码并增加有效期、轮换和审计。未采用：固定分享码本身就是可长期复用的 bearer 凭据，轮换只能缩短暴露窗口，不能满足删除入口的要求。
- 只依赖 Spring `max-file-size` 或只依赖 Nginx 限制。未采用：不同部署入口可绕过其中一层，且 Controller 仍需避免把整文件无界读入堆内存。
- 把父级覆盖率最低值直接提高到 0.05。未采用：common 模块实测约 2.65%、infra 约 3.93%，直接 0.05 会让已有测试模块失败；先提高到 0.01，再用 system 的 0.03 固化本次新增覆盖。
- 继续在 `docs/开发指南` 中直接写 `pip install PyYAML pytest`。未采用：Markdown 检查还需要 `markdown-it-py`，分散命令无法保证版本一致。

## 影响

- `/system/auth/share-login` 及分享码链接永久失效；旧库升级必须先执行 drop 脚本并承担分享码数据不可恢复的后果。
- 短信登录不再接受新管理平台（`super_admin`）账号；若未来需要新平台短信登录，应新增带平台边界的独立入口，而不是放宽本接口。
- 超过 50MB 的单文件请求在 Nginx、Spring 或 Controller 任一层被拒绝；错误提示不再进入无界堆读取。
- 本次未调整密码策略与传输加密：前端仍先做 MD5 摘要再提交，后端使用 BCrypt 存储；登录请求显式 `isEncrypt: false`，API 加密默认关闭。这两项已在 [SM2 密码传输与等保二级密码策略](../feature/2026-11-04-SM2密码传输与等保二级密码策略.md) 中另行决策。
- 上传接口仍沿用管理端登录边界，没有新增 `@PreAuthorize`；权限细化不在本次范围。
